# 江湖 · 「AI 时代人机交互三环理论」整体评价报告

> **评价基准**：三环理论——①人类工作系统（人与人打交道 + 由人授权）②AI 工作系统（繁重工作隐于界面之下，如 iPhone 玻璃面板）③人机交互系统（三价值：(a) Context 双向共识 (b) 辅助产生新知识 (c) 注意力二八分配）。
> **材料**：全部设计文档链（交互模式升级 v0.2 → 架构自算主线 v1 → 焦点面板主线闭环 → 推演坞横向推导链）+ 三路代码实证（用户旅程 / AI 链路 / 信息架构），代码基线 main=734b8dc。
> **日期**：2026-07-01。

## 0. 总评

**一句话：江湖在「环二」（AI 系统的隐藏与人审闸门）上是教科书级遵从，「环三·人→机」方向做得很深；最大的欠账在「环三·机→人」（机器不会主动提问）、「环三(c)」（没有注意力优先级系统）和「环一」（未接入销售的真实工作流）。**

先指出一个事实：三环理论与项目自己的设计语言高度同构——「人动脑 / 机器干活 / 排期外放」（交互升级 §1）≈ 环一/环二/环一出口；「引擎不可见，可见的是心跳与产物」（§3.4）就是玻璃面板比喻；「极简·一屏完成」（架构 v1 §6）指向环三(c)。**问题不在理念缺失，而在三环完成度严重不均衡**：授权闸门建成了，反向提问与注意力管理还没动工。

| 环 | 遵从度 | 一句话诊断 |
|---|---|---|
| 环一 · 人类工作系统 | ★★★☆☆ | 「授权」被制度化（收件箱四表），但系统触达不了人的真实工作流（企微/日历/提醒推送全未通） |
| 环二 · AI 工作系统 | ★★★★☆ | 架构正确（确定性引擎+异步 job+候选层+每日巡检），但玻璃面板有三道裂缝：配置暴露、心跳缺失、两处直写破口 |
| 环三(a) · Context 共识 | ★★★★☆ | 人→机（focus 焦点/双轨/全图上下文）近乎满分；**机→人主动提问几乎为零** |
| 环三(b) · 新知识产生 | ★★★☆☆ | 方法论脚手架（G64111/L1-L4/FORM）是最深护城河；但推导链呈现弱、AI 分析阅后即焚不沉淀 |
| 环三(c) · 注意力优化 | ★★☆☆☆ | **系统性欠账**：单屏约 360 个并列元素、无「今天最重要的事」、审核队列不按价值排序 |

## 1. 用户旅程全景（代码实证还原）

### 1.1 五幕旅程

**第一幕 · 进入**（环一→环三）
注册（手机/邮箱+密码，首人自动成 owner，`Auth.tsx`）→ Hub 空态三引导（🎙️口述建客户 CTA / 新建客户 / 载入示例，`CustomerHub.tsx:81-89`）。口述建客户是亮点：一段话 → `/api/voice/extract` 从零建出 客户+商机+人+关系（`IntelCapture.tsx:59-90`）。

**第二幕 · 建图**（环三(a) 人→机 密集区）
新建商机三模式（决策链骨架/空白/克隆，`NewOpportunityDialog.tsx`）→ 建人三入口（画布就地 / 表单 / 口述抽取）→ 连关系（锚点拖拽，L1-L4 四层）→ 填档案（角色 ADURC / 支持度六档 / FORM 七问 / BI / UCV）→ 左栏趋赢力 11 项实时算分（`Sidebar.tsx`，G64111 确定性引擎，零等待）。

**第三幕 · 日常作战循环**（主闭环，对应「情报→推导→出牌→执行→回流」）
进 Hub（无排序的客户卡）→ 进商机 → 看左栏缺口 → 补分卡刷卡（`GapCards.tsx`，按性价比排序）→ 单击人=右栏参谋 tab（带全图上下文多轮深想，`AdvisorPanel.tsx`）→ 🎯 出候选（行动牌/策略卡/风险三类，采纳才落库）→ 推演坞（现状锚→策略卡→里程碑→行动，`DeliberationDock.tsx`）→ 行动牌挂画布人旁 → 点牌反馈（完成+态度↑—↓ → 自动生成证据 → 局势重算）。

**第四幕 · 机器的暗线**（环二）
后台 job 队列（enrich 挖关键人 + suggest 推关系，`jobs.ts:181`）+ 每日巡检（停滞/决策链缺/支持度复查三条规则，`jobs.ts:246-258`，24h 一轮真实在跑）+ MCP 外脑通道（8 工具，外部 agent propose 候选）→ 全部汇入收件箱四表（人物/关系/字段提案/提醒）→ 人审采纳 → `act()` 落库 → 趋赢力重算 → 可能产生新提案（飞轮）。

**第五幕 · 出口**（环一回流，**最薄弱**）
执行排期：企微日历双向同步（P2）**未通**，行动牌只活在江湖内；结果回填靠销售自觉回来点牌；MD 作战档案单向导出已有。

## 2. 环一 · 人类的工作系统：授权已制度化，触达未打通

### 2.1 遵从的设计 ✅

- **「授权」被做成了产品的第一等公民**。铁律②（AI 产出一律候选、人审才落库）本质上是把三环理论「由人授权」做成了制度：候选四表（PersonSuggestion / RelSuggestion / ChangeProposal / Reminder）→ 收件箱统一人审 → 采纳走与手动编辑同一条 `act()` 通道。这是全项目最符合理论的设计。
- **影响预览让授权不盲目**：字段提案卡显示改前→改后 diff + 趋赢力百分点变化预估（`impact.ts` + `InboxPanel.tsx`）——人批准之前就知道后果，授权是知情授权。
- **双轨录入精确划分人机边界**（`voice.ts` isExplicit）：销售明说的=人的话，直落正式库；AI 补充的=机器的话，进候选。「人的工作」与「机器的工作」在数据层就分了轨。
- **行动牌六要素 =「给人的作战令」**：目的/时间/责任人(打谁)/资源/注意/道具，明确指向环一的人对人工作；点牌反馈（态度↑—↓→证据→重算）把人的实地成果回流给机器。

### 2.2 未遵从的设计 ❌

- **江湖是一个「来了才有用」的系统（pull-only）**。销售的真实工作系统是企微、日历、电话、车里的十分钟——而行动牌躺在江湖画布上不会来找你，巡检提醒躺在收件箱等你登录（唯一触达是登录后顶栏角标 `App.tsx:466`）。环一与环三之间的物理通道没接上。**企微日历双向同步（交互升级 §4，P2）正是这条通道，目前只有配置界面（`WeComSettings.tsx`），同步未通。**
- **结果回流依赖自觉**：设计文档 §4.5 的「录音→证据后台管线」是主路径，但现状要人记得回来口述/点牌。缺一个「刚结束与张总的拜访？说两句」的时机钩子（日历联动是最自然的钩子，又指向企微）。
- **人的授权动作本身有退化成低价值劳动的风险**——详见环三(c)。

### 2.3 差距本质

授权闸门是环一的「里子」，触达通道是环一的「面子」——目前有里无面。**只要销售一天不打开江湖，三环就整体停摆**。这也是为什么企微日历（P2）在三环视角下的优先级应高于其当前排序。

## 3. 环二 · AI 的工作系统：架构教科书级，玻璃面板有三道裂缝

### 3.1 遵从的设计 ✅（这是全项目最强的一环）

- **确定性引擎 = 玻璃面板下的元器件**：G64111 打分、缺口、方案包、局势判断、支持度背离全是纯函数本地即算——零转圈、零成本、零等待（架构 v1 的「速度结论」在代码里成立）。用户看到的只是一个趋赢力百分比和几张卡，完全符合「复杂性隐藏」。
- **后台是真后台**：job 队列（`jobs.ts:181` setInterval 消费）+ 每日巡检（`jobs.ts:246-258`，启动 30s 后首跑、24h 一轮）真实在跑；自算（enrich+suggest）异步入队。
- **降级链完备**：LLM 无 Key 走 mock、企查查无凭证走 AI/Web/mock、录音走演示——玻璃面板在任何配置下都不会黑屏。
- **外脑可插拔且守闸门**：MCP 8 工具中 propose_person/propose_relationship 严守候选制 + 200 条容量护栏——「任何 agent 都能喂它，但都得过人审」正是环二与环一的正确接口。

### 3.2 未遵从的设计 ❌（三道裂缝）

1. **配置复杂度穿透了玻璃面板**。BYO 大模型 Key（`AiSettings.tsx`）、企查查凭证、MCP 令牌复制（`McpAccess.tsx`）、录音源授权——用户手册第四章要教销售「复制 MCP 配置粘进 Claude Desktop」。iPhone 不会让用户配基带参数。**架构 v1 已拍板「平台统一配置代付」，是正确解药，但未落地**；MCP 外脑接入对非极客销售仍是断崖。
2. **心跳缺失：机器在干活，但人不知道**。巡检每日在跑，前端却搜不到任何「监测中 / 上次巡检」呈现——设计文档 §3.4 亲自规定的感知四层，第①层（环境心跳）没做。后果不是美观问题：**用户感知不到「AI 在替我工作」，就不会建立信任与依赖，后台价值等于零**。玻璃面板≠完全无感，iPhone 也有灵动岛。
3. **两处直写破口**：MCP `upsert_account/upsert_opportunity` 直写正式表（`mcpServer.ts`），与架构 v1 §1「江湖自算的机器产物也走提案层，不走直接写库——内外一致才叫真解耦」相悖；`append_visit_note` 直写也与口述双轨不对称。另外自算的 2–50s 前台轮询+按钮禁用，是「后台工作前台化」的残留——应点完即走，完成后角标+1。

### 3.3 小缺口

- aiContext 缺 UCV 维度和历史动作/证据链（AI 深想时看不到 C6 与交往史）；ChangeProposal 只支持 sentiment 一种字段，提案层广度不足；参谋会话历史内存态，刷新即丢。

## 4. 环三 · 人机交互系统：三价值逐项评价

### 4.1 价值(a) Context 共识——人→机近满分，机→人缺一半

**遵从 ✅（人→机方向）**
- `buildAiContext` 打包全图（人/角色/态度/关系/趋赢力 11 项/BI）+ **focus 焦点参数（「用户此刻盯着谁」）**——把人的注意力状态显式传给机器，这是意图传达的高级形态。
- 单击人 → 参谋 tab 的交互决策：选中一个人，系统第一反应不是给表单（数据视角）而是给参谋（作战视角），等价于「我看到你在想这个人，要聊聊吗」。
- 双轨录入+溯源（origin/evidence/confidence）让机器的每句话都能对回「你是从哪知道的」——共识是可核查的。

**未遵从 ❌（机→人方向：主动提问几乎为零）**
理论要求「机器主动向人询问以挖掘隐藏知识」。江湖的数据模型其实**精确地知道自己缺什么**——gaps.ts 能算出缺哪些信息、FORM 几分之几、谁的支持度 unknown——但这些知识缺口被呈现为「**分数缺口**」（补分卡：导向坐在电脑前填表），而不是「**问题**」（下次见面该问什么：导向人的真实拜访）。同一份数据，两种 framing：前者把人当数据录入员（人服务系统），后者把系统当参谋（系统服务人）。目前全是前者。
- 最接近的雏形只有巡检的 sentiment_recheck（「A/D 已表态但 >14 天无新证据 → 复查」），仅此一条。
- **拜访前简报（call prep）场景完全缺失**——「明早要见张总」是销售最需要 AI 的时刻（该带什么、他最近什么状态、还有什么没问过他），旅程里没有这一幕。

### 4.2 价值(b) 辅助产生新知识——脚手架最强，呈现与沉淀两头漏

**遵从 ✅**
- **方法论本身就是思考脚手架**：G64111 十一项把「赢面」这种直觉拆成可检视的结构；L1-L4 四层强迫从组织/权力/情感/利益四个横切面看同一群人；FORM/BI/UCV 强迫把「我了解他吗」变成可回答的问题。这是把顶级销售的隐性知识显性化——环三(b) 的最深实现，也是产品护城河。
- 推演坞顺推（现状→策略）/倒推（终局→里程碑）双泳道 = 正反两个思考方向的脚手架；AI 推演「如果把张总争取过来会怎样」= 反事实思考；影响预览 = 决策前的 what-if。

**未遵从 ❌**
- **推导链呈现不出因果**：坞是三条竖堆泳道，「局势→策略→倒排→行动」的推导关系靠两个「↓」示意——你自己在推演坞施工方案里的诊断（转横向左→右流水线）就是对这一条的正确修复，**该方案是环三(b) 的关键补强，建议如期施工**。
- **新知识产生了但没被接住**：参谋/推演的分析是纯 markdown 文本，阅后即焚——没有「存为笔记 / 挂到人 / 转为候选」的沉淀通道（除了手动出候选三类）；会话历史刷新即丢。人和 AI 一起想出来的东西，只有变成卡的那一小部分留了下来。
- 深度思考只有「对着一个人」（参谋）和「对着全局」（顺推/倒推）两档，缺「对着一条关系 / 一个阵营」的中间尺度（设计文档 §11 已列为待决）。

### 4.3 价值(c) 注意力优化——最大欠账，二八原理无系统支撑

**遵从 ✅**
- 方向自觉是有的：顶栏 12→5 收敛（B2）、入口收编（AddIntel 三合一、参谋收编 AI 推演）、推演坞三档渐进披露、补分卡按性价比排序、收件箱提醒置顶+批量操作。

**未遵从 ❌（四项系统性缺失）**
1. **无「今天最重要的事」**。Hub 客户卡无排序无优先级信号（插入序）；无每日简报、无跨商机待办聚合、无临期行动提醒。**二八分配完全靠用户自己在脑内完成**——这恰是理论 (c) 说应由交互系统承担的。
2. **审核队列不按价值排序**——这是「机器写·人审」范式的经典陷阱：人审本身会退化为低价值精力消耗。收件箱按类型排序（提醒>提案>人物>关系，`InboxPanel.tsx:56-60`），一条「D 倒向对手」的提案和一条低置信度关系候选等权排队。**讽刺的是：影响预览已经算出了每条提案的趋赢力变化，这个现成的价值信号却没有用来排序**。容量护栏（200 条）防刷爆，但不防审核疲劳。
3. **单屏并列元素约 360 个**（25 人商机：画布~200 + 左栏~30 + 坞~100 + 顶栏~8……），四套颜色编码并存（支持度 6 色/角色 5 色/band 4 色/连线 8 色）；同一个问题（某 A/D 支持度不明）会在四处同时闪烁（画布红边、EngineBar、补分卡、档案下拉）。信息强度没有分级预算。
4. **推送极弱、拉取极深**：主动找人的信息只有角标+toast+背离提案三种；其余躺在 2-4 层深处。对「聚焦单商机深挖」是对的，对「多商机的一天从哪开始」是空白。

## 6. 优化路线（按 ROI 排序，尽量挂靠已有方案）

### 第一梯队 · 高杠杆低成本（多为纯前端/零 schema）

1. **收件箱按价值排序**：用现成的 `previewProposalImpact` 结果排序（|趋赢力变化| 降序），提醒按 severity。半天工作量，直接治「审核疲劳」。
2. **缺口翻译成「拜访问题清单」**：gaps + FORM 空项 + sentiment=unknown → 生成「下次见 XX 该问的 3 件事」，挂在焦点面板参谋 tab 顶部或行动牌道具里。零 schema（纯 framing 重构），是机→人主动提问的第一步，也把「补分」从填表动作变回销售动作。
3. **心跳落地**：顶栏或坞头一行「引擎 · 昨夜巡检 N 商机 · M 条新提醒」（数据已在 inbox API 里）。让玻璃面板有生命迹象。
4. **「今日三件事」**：Hub 顶部聚合三源（最大缺口性价比项 + 巡检提醒 + 临期/逾期行动牌），纯前端可算。Hub 客户卡加「需要你」角标（pending 提案数+逾期行动数）并按此排序。
5. **执行推演坞施工方案第 1 刀**（对话收口坞底、左栏纯化）——已立案，顺带清环三(c) 的入口冗余。

### 第二梯队 · 结构补强

6. **第 2 刀横向推导链**（局势|策略|倒排|行动 四列因果流水线）——环三(b) 的关键补强，如期施工。
7. **推演产出沉淀通道**：参谋/推演分析加「存为笔记（Note/VisitNote）/挂到人」一键；会话历史落库（设计文档 §11 待决项，建议决「落」）。
8. **巡检规则扩容**：+行动牌逾期、+FORM 长期空缺的关键人、+拜访前一天自动生成 call prep 简报（结合企微日历后更自然）。
9. **自算彻底异步化**：点完即走，完成后角标+1（去掉 25 次轮询与按钮禁用）。
10. **封堵 MCP 直写破口**：upsert_account/opp 改走提案层或至少加「外部来源待核」标记，对齐架构 v1「内外一致」。

### 第三梯队 · 打通环一（战略级）

11. **企微日历 P2 提级**：三环视角下它不是「又一个集成」，而是环一与环三之间唯一的物理通道——行动牌进真实日程、提醒推送到企微、拜访结束触发「说两句」钩子。建议排在道具×WB 之前。
12. **平台代付 LLM 落地**（架构 v1 已拍板）+ MCP 接入引导傻瓜化——拆掉配置断崖。

## 7. 结语

江湖最难得的是：**它没有做成「AI 套壳」，而是先建了闸门（人审）、再建了引擎（确定性+异步）、方法论内核（G64111）从第一天就是显性脚手架**——这三件事恰好是三环理论里最难补课的部分，多数产品是反过来先堆 AI 功能。

下一阶段的主题应该从「把机器管住」转向「把人服务好」：让机器学会**提问**（环三(a) 反向）、让系统学会**排优先级**（环三(c)）、让触达**走出应用**（环一）。这三件事里有两件半是纯前端/零 schema 的 framing 重构——杠杆极高，且与已立案的推演坞施工方案完全兼容。
