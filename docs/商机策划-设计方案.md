# 商机策划 · 行动排期日历（设计方案）

> **定位**：在「侦探墙 / 干系人管理」之外，给客户工作台再装一个**孪生镜头**——把针对 G64111 低分项的销售动作、商机关键节点、历史触点，全部排到 **Apple Calendar 式的年/月/周日历**上：到期执行、周复盘、提分。
> **一句话**：侦探墙解决「**看清**」（关系网谁支持谁、哪项低分），商机策划解决「**做对**」（什么时间见谁、做什么、补哪一分）。二者共享同一份商机数据。
> **作用域**：**客户级**——进入某客户后，顶部 `ViewTabs` 切换「🕸 侦探墙 ｜ 📅 商机策划」，日历汇总该客户名下**所有商机**的行动/里程碑/触点。
> **版本**：v0.2 · 2026-06-05 · **已与 HTML 原型（六轮迭代）对齐**。仍处「先规划、后动工」阶段，未写功能代码。
> **分支**：建议 `feat/deal-planner`（从 main 切）。

---

## 0. 本质：补上 G64111 闭环缺的执行半环

`docs/产品设计方案.md` 定义的完整闭环：

```
G64111 诊断打分 → 趋赢力% → 741 选竞争策略 → 行动宝典取话术 → ★行动计划排期 → ★周复盘更新分数 →（循环）
                  └────────── 侦探墙已实现（看清） ──────────┘   └──── 商机策划要补（做对） ────┘
```

侦探墙只做了闭环的**前半段**。后半段「**行动计划排期 + 周复盘**」从未落地，而它正是销售方法论真正产出业绩的一环。商机策划日历 = 这后半段的可视化载体。

**它不是一个孤立的日程表**，而是 G64111 的执行面：日历上每一个「行动」都挂着一个**要补的低分项（gap）**和**一个要攻的人**，完成后回写复盘、推动趋赢力曲线上扬。

## 1. 决策快照（截至 2026-06-05，含原型迭代结论）

| 项 | 定的 |
|---|---|
| 模块名 | **商机策划** |
| 形态 | **日历**（年 / 月 / 周三视图，参照 **Apple Calendar**） |
| 作用域 | **客户级**：进客户后与侦探墙顶部切换；聚合该客户全部商机 |
| 与侦探墙关系 | **孪生镜头**：看（关系）↔ 做（时间），同一数据两个视角 |
| 日历事件 | **三类**：① 行动计划 ② 商机里程碑 ③ 历史触点。统一为「时间条」——有**起止**（`startDate`~`endDate`，可跨天）+ **时段**（上午/下午/晚上） |
| 商机色系 | 一个客户同时推进 **≤4 个商机** → **4 个色系**；事件颜色 = **所属商机色系**，三类靠**形态**区分（行动实心条 / 里程碑旗标 / 触点虚线） |
| 泳道 | 年/月/周三视图统一**按「商机泳道图例」顺序上下叠放**，避免混淆 |
| 阶段模型 | **模型 B**：商机阶段 = **阶段段列表**（`OppStage`），允许**同名重复 / 降级回退**（如 招投标→方案认可→招投标），不再是固定单调 6 段 |
| 行动完成态 | 行动有「是否完成」复选框（默认未勾，绿色）；条上：完成=绿 ✓、逾期(`endDate<今天`未完成)=红 ✕、未到期=无标记 |
| 趋赢力数值 | 卡片趋赢力一律取 `g64111.ts` 实时计算（`scoreFromDomain`），**不用**手填的 `winProbability` |
| AI 行动建议 | 741 行动宝典生成的动作先入「**待排期建议**」，人审拖入日历才正式排期（呼应铁律②） |

## 2. 与侦探墙的关系：两个镜头，一份数据

```
┌─ 客户：西部电力建设集团 ───────────────────────────────┐
│  顶部 ViewTabs：  [ 🕸 侦探墙 ]   [ 📅 商机策划 ]          │  ← 新增切换（客户级）
│ ────────────────────────────────────────────────────── │
│   🕸 侦探墙（现有）              📅 商机策划（新增）         │
│   ─ 单商机 L1–L4 关系网          ─ 跨商机 年/月/周 日历      │
│   ─ 看清：谁卡谁、哪项低分        ─ 做对：何时见谁、补哪分    │
│   ─ 产出 gap（C/P/1K 缺口）  ───► ─ 把 gap 变成带日期的行动  │
│                          ◄─── 完成回写、周复盘推动趋赢力曲线 │
└──────────────────────────────────────────────────────────┘
```

- **不替换、不挪动侦探墙**：侦探墙仍是进入商机后的默认视图。商机策划是同级的第二个 Tab。
- **数据闭环联动**：侦探墙趋赢力面板每个缺口项可「**＋排个行动**」一键建 `PlanAction`（带 `gapItem`）；反向，日历里行动完成 → 触发该商机一张趋赢力快照（周复盘曲线）。

## 3. 三类日历事件 × 数据源

UI 层统一为 **CalendarEvent** 视图模型：`{ id, kind, oppId, startDate, endDate, half, title, … }`；底层来自三个数据源：

| 事件类型 | 含义 | 底层数据源 | 现状 |
|---|---|---|---|
| 🎯 **行动计划** | 我方销售动作（拜访/对齐/送方案/攻关），关联 gap + 人，**带完成态** | **新表 `PlanAction`** | ❌ 需新建（§4.1） |
| 🚩 **商机里程碑** | 关键节点：开标、立项评审、预计签约…可多个、可增删 | **新表 `OppMilestone`**（轻量） | ❌ 需新建（§4.2） |
| 📌 **历史触点** | 已发生的拜访/互动纪要（回看用） | `VisitNote`（现成） | ✅ 表 + `ADD_VISIT` + `VisitTimeline` 全现成 |

> 与 v0.1 的修订：原计划里程碑复用 `Opportunity.expectedSignDate` 单个签约日；但原型确认里程碑要支持**多个、自由增删**（开标/评审/签约…），故里程碑独立为轻量 `OppMilestone` 表。`expectedSignDate` 仍可作为「预计签约」里程碑的初始来源。

## 4. 数据模型与契约

> 通则：所有新表带 `tenantId`，字段全 `String/Float/DateTime`，**无 enum/json**（铁律③跨库可移植）。改 schema 流程：`schema.prisma` → `npm run generate` → `npm run db:push` → **完全重启 node 进程**。

### 4.1 `PlanAction`（行动计划）

```prisma
model PlanAction {
  id            String   @id // act_xxx
  tenantId      String
  accountId     String   // 冗余存，客户级日历直接按 accountId 聚合，免 join
  opportunityId String   // 必属某商机
  gapItem       String   @default("") // 关联 G64111 低分项：C1..C6 | P1..P4 | 1K（空=非补分动作）
  personId      String?  // 目标干系人
  title         String
  scene         String   @default("")
  scripts       String   @default("") // 话术（741 行动宝典可预填）
  target        String   @default("") // 期望达成
  ownerId       String   @default("")
  startDate     String   @default("") // YYYY-MM-DD ← 日历主锚（起）
  endDate       String   @default("") // YYYY-MM-DD（止；单日则 == startDate）
  half          String   @default("am") // 时段：am 上午 | pm 下午 | eve 晚上（周视图定位）
  done          Boolean  @default(false) // 是否完成（仅行动有完成态）
  doneAt        String?               // 完成日期
  review        String   @default("") // 复盘（喂周复盘）
  origin        String   @default("manual") // manual | ai(741) | workbuddy
  createdBy     String   @default("")
  createdAt     DateTime @default(now())

  @@index([accountId])
  @@index([opportunityId])
}
```

> 与 v0.1 差异：单 `dueDate` → `startDate`+`endDate`（支持跨天连续条）；新增 `half`（上午/下午/晚上）、`done`/`doneAt`（完成态）。逾期 = `!done && endDate < 今天`（前端实时判断，不落库）。

### 4.2 `OppMilestone`（商机里程碑）

```prisma
model OppMilestone {
  id            String   @id // ms_xxx
  tenantId      String
  accountId     String
  opportunityId String
  title         String              // 开标 / 立项评审 / 预计签约…
  startDate     String   @default("")
  endDate       String   @default("") // 多为单日：== startDate
  half          String   @default("am")
  createdAt     DateTime @default(now())

  @@index([accountId])
  @@index([opportunityId])
}
```

### 4.3 `OppStage`（商机阶段段 · 模型 B，支持降级回退）

商机的「漏斗阶段」不再是 `Opportunity.pipelineStage` 上的单值，而是**时间轴上的一串阶段段**。年视图按段渲染色块与阶段文字；允许同 `stageKey` 多次出现（降级回退）。

```prisma
model OppStage {
  id            String   @id // st_xxx
  tenantId      String
  opportunityId String
  stageKey      String   // 需求引导|方案认可|客户立项|招投标|合同谈判|合同双签（可重复=降级回退）
  startDate     String   // YYYY-MM-DD
  endDate       String
  createdAt     DateTime @default(now())

  @@index([opportunityId])
}
```

- 「商机当前阶段」= 覆盖**今天**的那一段的 `stageKey`（若多段重叠取最后定义者）。`Opportunity.pipelineStage` 可保留为冗余/兜底，由当前段同步。
- 与 `docs/产品设计方案.md §2.7` 的「线索 + 商机六阶段」一致；本方案取**六阶段**（线索后）作为甘特 6 段色阶。

### 4.4 前端契约（store.ts = 权威）新增 Action

```ts
// 行动
| { type: 'ADD_PLAN_ACTION';    accId: string; oppId: string; action: PlanAction }
| { type: 'UPDATE_PLAN_ACTION'; accId: string; actionId: string; patch: Partial<PlanAction> } // 拖拽改期/改时段=patch startDate/endDate/half
| { type: 'DELETE_PLAN_ACTION'; accId: string; actionId: string }
| { type: 'TOGGLE_PLAN_ACTION'; accId: string; actionId: string; done: boolean }              // 完成打勾→写 doneAt
// 里程碑
| { type: 'ADD_MILESTONE';    accId: string; oppId: string; milestone: OppMilestone }
| { type: 'UPDATE_MILESTONE'; accId: string; milestoneId: string; patch: Partial<OppMilestone> }
| { type: 'DELETE_MILESTONE'; accId: string; milestoneId: string }
// 阶段段（模型 B）
| { type: 'ADD_OPP_STAGE';    accId: string; oppId: string; stage: OppStage }
| { type: 'UPDATE_OPP_STAGE'; accId: string; stageId: string; patch: Partial<OppStage> }       // 拖阶段交界=patch startDate/endDate
| { type: 'DELETE_OPP_STAGE'; accId: string; stageId: string }
```

后端 `mutate.ts` 对齐；`state.ts` 把 `account.planActions[] / milestones[] / oppStages[]` 按 accountId 挂到客户下（与 `visitNotes[]` 同款）。触点 `VisitNote` + `ADD/UPDATE/DELETE_VISIT` 已现成，零改动。

## 5. 三视图规格（与原型一致）

统一框架：顶部 `CalendarHeader`（◀ 今天 ▶ ｜ 当前期标题 ｜ `年 月 周` 分段）。**无「＋新行动」按钮**——一律**双击空白新增**。视图偏好 `usePersistentState('jianghu.plannerView', 'month')`。右侧栏：事件三类 + 商机泳道，**每项带 👁 显示/隐藏**（睁眼=显示、闭眼=隐藏，三视图统一过滤）。

### 5.1 月视图（默认）

- 周一起始的 6×7 网格；今天用 `--accent` 圆底日号。
- **商机泳道**：每格内事件按商机顺序固定 lane 叠放，跨日事件渲染为**横跨多格的连续条**；**格子高度固定**（按最多商机数算），隐藏/显示泳道时**格高不变**。
- **拖拽改期**：单击选中→两端出**锚点**；拖锚点改起/止、拖条身整体平移；**拖拽中实时重渲染**，越过本周边界继续拖 → 事件实时延伸/顺延到相邻周（按周换行分段）。
- 再次点击已选中事件 → **右侧详情抽屉**（编辑全字段 + 删除）。双击空白 → 新增。

### 5.2 周视图

- 7 天列 × **三时段带：上午 / 下午 / 晚上**（左侧时段轴）；每带高度 ≈ 月视图日格（约 184px）。
- 带内事件按**商机泳道**叠放；多天事件为**连续整块**（非每天独立块）。
- **双向拖拽**：水平拖改日期、**垂直拖在上午/下午/晚上之间改时段**（`half`）；锚点改起止。再点开抽屉。

### 5.3 年视图（「中间态」：月内周列 × 商机行 矩阵）

- 12 个月，每月一个 card；card 内是**矩阵**：**列 = 周**（W1…W5）、**行 = 商机**（按泳道顺序）。
- 每格 = 该商机该周所处**阶段**：背景 = 阶段色（同商机色系、6 阶段 6 档深浅），格内**标阶段名**；**同一行连续相同阶段只在第一格写文字**（色块连续、文字不重复）。
- 事件三类的**图标钉在对应格**（🎯🚩📌，商机色）；点图标开事件抽屉。
- **双击格子** → **新建阶段段**（选阶段名 + 起止，允许同名 → 降级回退）；点已有阶段格 → 编辑/删除该段。

## 6. 视觉编码

复用产品语义 CSS 变量（`--panel/--ink/--line/--hover/--accent…`），亮/暗主题自动适配。

| 通道 | 编码 |
|---|---|
| **事件颜色** | = **所属商机色系**（4 商机 = 4 hue，HSL 半透明底自适应明暗）。**不再按 gap 着色** |
| **事件类型** | 靠**形态**区分：🎯行动=实心条（左色条）/ 🚩里程碑=旗标实描边 / 📌触点=虚线框 |
| **阶段段** | 同商机色系的 6 档明度，深浅=阶段推进；年视图矩阵格背景 |
| **行动完成态** | 完成=条尾绿 ✓（整条略置灰）/ 逾期未完成=条尾红 ✕ / 未到期=无 |
| **泳道** | 三视图按商机泳道图例顺序上下对齐；左侧 5px 色条 = 商机身份色 |
| 趋赢力 | 当日/当周聚合处可显该商机 `scoreFromDomain` 趋赢力% + 741 band（绿/蓝/橙/红） |

| 操作 | 行为 |
|---|---|
| **新增** | 任意视图**双击空白** → 抽屉/弹窗选**类型**(行动/里程碑/触点) + **商机** + 标题 + 起止(+时段) → `ADD_*` |

## 10. 不碰的红线（对齐 CLAUDE.md 铁律）

1. **多租户隔离**：`PlanAction / OppMilestone / OppStage` 全程 `where { tenantId }`；`state.ts` 按 tenant+account 作用域查。
2. **AI 不自动写库**：741/AI 生成的行动**不直接进日历**，先入「待排期建议」，人审拖入=采纳（铁律②）。
3. **跨库可移植**：三张新表字段全 `String/Float/DateTime/Boolean`，**无 enum/json**（SQLite↔Postgres 一致）；时段、阶段名等用 String。
4. **winProbability 不碰**：日历趋赢力只读 `scoreFromDomain`；手填 `winProbability`、WorkBuddy 字段一律不写不覆盖。
5. **数据契约同步**：新表与 Action 的改动，前端 `store.ts`/`types.ts` 与后端 `mutate.ts`/`types.ts`/`state.ts` 同步落（铁律⑤）。
6. **BYO / 敏感**：本模块不引新密钥；行动话术若引用干系人敏感情报，沿用 `VisitNote`/FORM 既有可见性边界。
