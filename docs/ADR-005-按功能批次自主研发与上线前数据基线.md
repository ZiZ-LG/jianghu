# ADR-005：按功能批次自主研发与上线前数据基线

- **状态：** 已接受；协议落盘不代表 CI 配置或数据库已改变。
- **日期 / Owner：** 2026-09-05（America/Los_Angeles）/ 项目所有者。
- **依据：** 项目所有者认可“用户确认产品目标并验收成果，Agent 负责实现、技术审查、测试和修复”的模式，并要求固化；同时确认尚未进入正式生产，现有 CRM 数据均为假的测试数据，无需迁入新库。
- **治理任务：** CORE-207；CI 实施另由 CORE-215 承接。
- **执行权威：** [研发协作协议 v1](研发协作协议v1.md)；[商业清单](商业版开发待办清单v1.md)。
- **替代范围：** ADR-004 及旧计划中的逐子任务完整 CI/合入后才继续、逐任务重新申请相同共享文件授权、业务和状态记录必须分开推送，以及保全/搬运旧测试数据的强制前置。其它产品与安全边界继续有效。

## 决策

1. 用户按可体验的功能批次确认范围和验收结果；Agent 在已授权范围内自行实现、审查、测试和修复。技术检查自动执行，不能以用户不懂代码为由免除。
2. 子任务仍小步、可回退、有任务 ID，并保持同一时刻最多一个 CRM 子任务 IN_PROGRESS；通过本任务适用的本地检查后，可在同一已授权批次中继续依赖任务，不要求每一步推送或合入 main。
3. 文档、普通功能、高风险关联变化和实际发布分别选择检查；精确 SHA 绑定保留。CI 必需检查、失败汇总与真实发布版本检查不得绕过。CORE-215 完成前，远程工作流仍照现有配置运行，不能口头宣称已分层。
4. 本地 commit、远程推送、任务状态、产品验收、合入和发布分别记录。不为记录通过结论反复触发新一轮完整 CI；没有 main/发布授权时停在可审阅候选。
5. 现有 CRM 旧数据库无业务数据迁移义务。新环境从空库建立结构并生成明确标识的测试数据；不为迁移旧假数据建设回填、身份合并、旧版本升级兼容或全历史恢复验收。
6. 保留 schema 的版本管理、从空库初始化、tenant scope、人审、事务、幂等、审计、加密、持久化、备份恢复和回滚能力。引入真实用户数据前，须验证拟上线基线的升级及恢复路径，并明确恢复目标；真实试用数据也不能继续按可弃用数据处理。

## 数据和授权边界

“不需要旧数据”用于缩减研发范围，不要求本轮清库。Agent 可在已授权任务中重建自己创建且已核实身份的隔离测试库；不根据模糊路径、默认连接或名称猜测去删除其他数据库、卷和用户文件。既有 G64111/PDE/协作实现、历史 migration 文件及工程证据继续保留，不顺手删除。

PostgreSQL 单一引擎目标不变；当前 SQLite 测试仍需在 CORE-211～214 中切换并证明覆盖等价。删掉旧测试数据迁移要求，不等于现有依赖已迁移，也不等于可以让所需测试静默跳过。

保留 PR #46 暂停、自我修养开发线隔离、禁止部署 lake2ocean.top/阿里云/Mac mini 等现有边界。本次不新增 main 合并、发布、外发或数据库清理授权。

## 取舍与验证

继续沿用旧规则能保留所有历史演练，但会让纯说明文档和已被替代的中间代码反复等待约 80 分钟 CI，也让用户承担无法有效完成的技术审批。完全取消检查会丢失租户隔离、数据一致性和恢复的证据，因此不采用。

采用批次自主推进与按影响选择检查。CORE-215 应证明纯说明文档走轻量检查、关键依赖变化扩大检查、失败不能被跳过任务伪装为通过、同一候选避免重复运行、实际发布 SHA 与检查/产物一致，并核对共享发布工作流不受误触发。具体文件与测试映射由该任务盘点，不在此 ADR 中假定已经实现。

## 回滚

本次仅文档；撤销本次提交即可恢复此前规则。CI 或数据库实现以后各自提供独立回滚点。历史 DONE、旧 G5–G7 表和既往状态记录保留，新规则从本次记录起适用。
