## 1. 核心价值与服务对象

整个平台的核心价值：帮助大客户销售把新认知用到真实客户中，以更少的信息整理成本，看清客户的决策关系，采取有依据的下一步行动，并把实战经历积累成自己的判断能力。

江湖 CRM 的产品类别为**个人大客户销售的客户经营工作台**。对用户的承诺是：**看清客户为什么买、谁能推动，以及下一步该找谁、谈什么。** 商机的阶段、关键缺口和下一步继续作为总览信息；单个商机通过干系人地图、证据、行动与复盘展开。

首批设计继续使用熟悉的 B 端项目管理软件、数字化与 AI 解决方案销售语境。个人决定是否使用及付费，工作区默认私密；当前不以销售经理的监督、预测或带教需要组织产品。

用户当下应获得三种结果：少做重复整理；发现原先忽略的人物、价值和决策缺口；形成具体且有依据的下一步。长期的能力提升通过“原先怎样判断、行动后发生什么、下次怎样调整”的积累验证，不用内容阅读量、图的节点数或资料完整度代替。

## 3. 产品信息架构

全局保留“商机、今日、客户”三个入口和一个快速记录按钮。待判断线索留在商机视图，允许信息不完整，转入推进时延续同一上下文与来源。

单个商机的主要工作界面为**干系人地图**，同时保留列表式阅读与操作路径。桌面端在图旁显示选中人物/关系的依据和当前行动；小屏使用人物列表与详情抽屉，保持同一份数据。首次记录不要求画完整地图、配置方法论或填写全部六问。

| 区域 | 默认显示 | 用户可以完成的操作 |
|---|---|---|
| 商机顶部 | 客户业务目标、阶段、当前关键缺口、下一步 | 明确或修改目标；手动更新阶段；查看未知项 |
| 中央地图 | 当前商机涉及的人物、已记录关系、候选与待验证提示 | 选择人物/关系；看影响路径；查看来源；确定当前关注的人 |
| 侧边详情 | 本次决策角色、目标/顾虑、依据、更新时间、相关行动 | 补充或修正判断；创建一个验证行动 |
| 活动与复盘 | 沟通记录、承诺、原预期和实际结果 | 回看过程；记录行动结果；调整下一步 |
| 按需展开 | 六问、研究简报、情报/假设详情、已有高级能力 | 解释当前问题；查看更多资料；访问历史 |

地图中的布局、聚焦和筛选不改变正式角色或关系。历史 G64111/PDE 面板保持受控访问，其评分不占据新版默认首屏。

## 4. 地图怎样帮助销售判断

### 4.1 客户价值、人和决策相连

图围绕当前商机表达客户想改善的业务结果，以及相关人的决策角色、关心的问题、顾虑、影响关系和已发生的推动行为。职务与决策角色分别表达；同一人在不同商机中可能承担不同角色。关系亲近、技术认可或沟通频繁，都不足以自动确认预算权或内部推动者身份。

缺少预算负责人、业务目标或采购步骤时，显示待核实问题；不为了填满图而创建虚构 Person、关系或金额。用户可以从少量已知联系人开始，默认聚焦与当前问题有关的局部关系。

### 4.2 证据与不确定性可见

每个判断应能回到授权可见的来源、发生时间和当前版本。内容性质（观察/转述/个人判断/假设）与审核状态分别保留；用户采纳一条转述，不等于证明转述内容客观成立。AI 置信度不等于事实确定性、销售能力评分或成交概率。

候选、当前假设与已采纳记录在图中可区分。冲突证据并列展示；来源过期或权限撤销时，提示重新核实或隐藏受限正文，不继续将过时引用作为确定依据。

### 4.3 从图进入行动

选中人物、关系或缺口后，用户能直接建立一项验证行动，写清“找谁、为了确认什么、何时行动、希望观察到什么”。候选动作必须经用户确认，才进入正式 Commitment；不会同时创建另一套待办。

例如：王主任答应介绍李总时，先保留原话和介绍承诺；下一步可以是确认参会人与业务目标。是否将王主任视为当前推动者，由后续实际行动和用户确认决定。

## 5. 低成本记录与情境方法论

会后路径为：口述文字/已授权转写 → 来源与候选整理 → 一页变更预览 → 用户确认 → 地图、记录与行动同步。

一页预览突出新增项、改前/改后、依据及不确定处。客户或商机归属不明、同名人物、冲突、过期来源和低置信度项不得默认采纳；可保留草稿、修改、部分采纳或驳回。返回清晰的已采纳、未采纳和失败结果；重试遵守现有幂等与版本冲突规则。

六问继续可选：业务问题与时机、可验证价值、预算/采购权、选择标准、决策采购步骤、内部推动行为。默认给出与当前缺口有关的一条提示及理由，完整问题清单可展开。用户无需先学方法论名称；不按填答完整度自动推进阶段，不产生默认总分或赢率。

个人复盘保持简短：原预期、实际发生、下一步调整。允许先完成行动、之后补结果；记录不足只提示，不强制填写整套复盘表。更新判断时保留原版本，AI 的解释和建议仍作为候选。

## 6. 外部 Agent 的首版边界

首版包含**一个真实可用的外部 Agent 入口**，默认优先验证用户提到的 WorkBuddy；ChatGPT、Claude 列为后续适配目标，不声称三者已兼容。真实客户端若存在能力限制，记录具体版本、鉴权方式、失败点及现有文本回退路径，不用 HTTP mock 代替联调结论；如需调整首个入口，在对应任务中据此决策。

优先复用现有服务端业务接口与 MCP 基础，让客户端共享同一份江湖上下文。首版提供读取授权上下文、提交带来源的候选、查询处理结果和打开人审页面的能力；不建设多 Agent 编排平台或 Agent 管理中心。

**外部 Agent 凭据不具有候选采纳或直接改写正式状态、关系、方法论结论及行动的权限。** 用户在江湖的变更预览中确认，服务端重验身份、租户、资源范围、敏感 ACL、来源与版本；不能以模型输出“用户已确认”作为授权凭证。

已有 WorkBuddy 测试使用 `/api/mcp` 和 `sync_intel_bundle`，包含历史 `sync_business` 权限及 G64111/PDE 路径。新入口须逐项核对、收窄授权并适配当前候选权威，不能把旧同步 token 原样当成新版安全证明，也不能为新产品破坏旧客户端授权与存量数据。

直接粘贴文字、上传已支持的转写资料和手动记录始终可用。首版不自建 ASR、不接管录音硬件、不开发微信抓取、不承诺对所有文件格式自动转写；已有资料入口在其当前授权边界内复用。无 AI Key 时清晰提供手动路径，不用演示候选冒充真实解析。

## 10. 验收与未验证事项

### 工程验收：SAAS-215

- C1–C7 可演示、可回归；无 G64111、无 Key、无外部 Agent 时手动闭环成立。
- 商机列表与地图使用相同上下文；同名人物、同客户多商机、跨客户和跨日切换不串写。
- 在地图内完成查来源、确认关注对象、建立验证行动、记录结果与回看原判断；不需要完整绘制客户组织。
- 人审前正式状态、关系、方法论结论及行动零变化；Agent 不能自行采纳；撤销授权、来源冲突、失败重试、幂等与版本检查有效。
- 真实首个 Agent 客户端记录版本、环境、认证方式和实际收据；HTTP 模拟测试不作为客户端联调证据。
- tenant scope、存量 RBAC、敏感 ACL、导出、审计、算法回归、版本化 migration、备份恢复、精确 SHA CI 和回滚门通过；当前双库纪律不变。

### 产品价值观察：SAAS-219

复用模拟场景即可推进方案和工程设计，不要求用户现在再提供新人物。受控试用时，再观察真实工作的整理加复核耗时、发现的关键缺口、因此采取的行动及其结果、主动回访产品和付费反馈。至少覆盖跨两个工作日的接续，避免只记录一次演示印象。

模拟操作可以说明流程能否完成，不能证明真实省时、留存、能力提升或成交率。付费意愿与实际支付分开记录；未发生观察时列明未验证，不把结论填成通过。邀约、联系其他人、收款或生产试用需有对应授权，本方案不代替这些操作的权限。

SAAS-215 的工程通过与 SAAS-219 的价值结论分别报告。真实使用观察不作为重新启动本轮产品讨论的前置条件，也不取消后续实际发布的安全、环境和回滚要求。

## 11. 持续有效的保护边界

一个注册账户原则上对应私有租户；个人化不削弱 tenantId、存量角色和敏感数据权限。PostgreSQL 单一引擎继续按 CORE-211～214 分阶段推进，退出 Gate 前保留 SQLite 验证与存量保全。已有加密逻辑备份不表述为 PITR。

不删除 G64111/PDE、协作模型或历史；不触碰自我修养开发线，不部署 lake2ocean.top、阿里云或 Mac mini。PR #46 保持 OPEN 且暂停，复用旧设计和测试思路不解除其暂停。本轮仅调整 CORE-207 的文档候选，不自动合并 main 或启动后续业务代码。
