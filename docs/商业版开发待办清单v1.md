## 1. 使用规则

1. 本文件已在 ADR-002 获批准后成为持续产品建设的唯一日常状态清单；内部版维护项仍在内部清单单独留档。
2. 同一时间最多一个任务处于 `IN_PROGRESS`。需要并行时必须由项目所有者明确批准，并保证任务不修改同一契约、schema 或共享文件。2026-08-23 项目所有者批准一次双 worktree 例外：CRM 线与“自我修养”线各自最多一个 `IN_PROGRESS`；当时配对为 `CORE-115` / `SAAS-601`，CORE-115 阶段门后 CRM 可按原依赖顺序恢复 `SAAS-102`。两线不得修改同一契约、schema 或共享运行文件；共享清单仍由 CRM 线单一编辑。
3. 状态固定为 `PENDING / READY / IN_PROGRESS / BLOCKED / DONE`。
4. 每个子任务控制在 1–3 个工程日；超出时必须拆分，不能以“完成一整个 Phase”作为单任务。
5. 开始任务前记录 Owner、分支/worktree、开始时间、依赖和回滚点；任务 ID 必须出现在 commit 与验证记录中。
6. 任务只有在验收标准、测试、migration/恢复要求和文档更新全部完成后才能标记 DONE。
7. 修改 `packages/*` 后，按仓库规则在 `app/`、`server/` 重新执行 `npm ci --install-links`，再做跨包验证。
8. 任何 tenant scope、人审、敏感 ACL、G64111/PDE 权威、加密 Key、数据迁移或恢复边界降低都属于重大偏差，须先停工并提交 ADR。
9. 旧字段删除、旧表删除、长期双写、fallback 双读、内部数据复制到商业环境均不得作为“顺手优化”执行。
10. Git 提交小步进行；未获明确授权不得 merge/push `main` 或部署。

## 3. Epic 完成定义

EPIC-CRM-001 只有同时满足以下条件才可关闭：

- 未安装 WorkBuddy、未启用 G64111 的用户可用“客户 + 一句话下一步 + 时间”在两分钟内建立 Commitment，并完成临近确认、改期、完成和下一步闭环；
- 曹经理可完成 ResearchBrief → 飞书妙记/文件导入 → ReviewBatch 速审 → 人物/关系/情报更新 → StakeholderFocus → 假设验证 → 可解释关系干预 → 4–5 商机组合；
- 拜访前简报、会后抽取和关系雷达分别通过 read_only、candidate、read_only/draft Job Card 运行；权限撤销／Job 停用立即生效，自动外发、阶段／Forecast 自动修改和正式业务越权写入均为 0；
- 曹经理作为 team-scoped member 只能看到本人、两名下属和显式授权 Matter，敏感正文不因经理身份自动可见；
- 团队目标、ForecastEntry、SalesOutcomeRecord 和 ForecastSnapshot 可重放，混币或缺关键输入失败关闭；关系／证据缺口只形成带来源软警告，用户 override 保存理由，系统不自动改 Forecast；
- 企业可发布第二套非 G64111 方法论并绑定、评估、迁移、回滚，无需改代码或 schema；新版本可对历史已审核 Interaction/Evidence 生成并排 Evaluation，但不覆盖历史事实或 active binding；
- G64111 关闭配置下通用核心全量通过；G64111 公式、fixtures、server parity 与 PDE golden 全量保持通过；
- SQLite/PostgreSQL migration、备份、恢复和回滚演练通过；内部与商业环境保持物理隔离。
