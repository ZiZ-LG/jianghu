## 1. 探明结论（WorkBuddy 实体 + 对齐）

### 1.1 WorkBuddy 真身
- 腾讯 **CodeBuddy 套壳**的 AI agent 桌面端（Electron，内置 MCP host + skill 编辑器 + 自动化模块，v5.1.6）+「数字能源销售自助包 v2.0.6」。源码：`/Volumes/PowerData/数字员工销售自助包-v2.0.6/`。跑在**每个销售本地电脑**。
- 已有 **2 skill / 10 flow**：客户档案（01 新建工作空间 / 02 刷新档案 / 03 合并已确认 / 04 追问工具集 / 05 企查查情报增强 / 06 查询呈现 / 07 报表）+ 拜访记录（01 定时 4h 拉录音 / 02 提炼生成 / 03 未命中清单）。
- **数据载体 = 企业微信微盘（WeDrive）同步目录里的 .md 文件**，销售用 Obsidian 编辑。`wedrive.*` 是本机文件薄封装；`master_query` 在 `_master/客户主数据.md` 上做主数据 CRUD（customer_id 形如 `CNPC-BJ-001`）。
- **录音源**：得到大脑（MCP）/ 飞书妙记（lark-cli）/ 钉钉听记（dws CLI），三选一。
- **自带 G64111**：`_shared/score.py` 是江湖方法论引擎的随包副本（计分逐位同源）。
- **它已有自己的「待确认更新」区**（`[x]/[-]/[ ]` 三态勾选）= 与江湖收件箱同范式的人审机制。

### 1.2 方法论零翻译（已核实 origin/main）
江湖 v1.1 早已升级：`Role = 'A'|'D'|'U'|'R'|'C'`（ADURC，C=教练）、`CustomerType = 1|2|3|4`（央企发电集团/地方能源国企/分布式头部民企/EPC总承包商），与 WorkBuddy **逐字对齐**。`score.py` 是江湖引擎随包副本。→ **不需要任何角色/分型翻译层**。

### 1.3 江湖侧 M1 全就绪（已核实 origin/main）
- schema：`Account` 有 externalRef/region/group/primaryOwner/profile；`Opportunity` 有 externalRef/status/competitor/competitiveSituation/winProbability/expectedSignDate/expectedAmountW/meta；`VisitNote` 表在。
- MCP 工具（`server/src/mcpServer.ts`）：upsert_account / upsert_opportunity / append_visit_note（直写）+ propose_person / propose_relationship（候选）+ set_opportunity_roles / set_burning_issue / set_ucv（评分状态）全在。
- → **本轮江湖侧 0 schema、0 新工具**。

### 1.4 三现实约束
1. **WorkBuddy 无文件监听，只有 cron 定时任务，且只能 GUI 手建**（部署手册"文件监听"是错的，`LG-部署友好化改造方案.md` 已纠正）。
2. **WorkBuddy 商机是内嵌客户档案 frontmatter 的单一主商机（1 客户 : 1 商机）**，无独立 opportunity_id。江湖支持多商机，更丰富。
3. **数据载体是微盘 .md**，跨系统只传 MCP 结构化字段。

## 2. 集成架构

### 2.1 通道：给 WorkBuddy 加一个 `jianghu` MCP server
往 `~/.workbuddy/mcp.json` 的 `mcpServers` 加一条（WorkBuddy 4.24+ 原生支持 `type:http`+headers，**不必 `npx mcp-remote`**；照销售包企查查"写法二"）：

```jsonc
{
  "mcpServers": {
    "jianghu": {
      "type": "http",
      "url": "https://<江湖域名>/api/mcp",
      "headers": { "Authorization": "Bearer ${JIANGHU_TOKEN}" },
      "timeout": 60000
    }
  }
}
```
令牌 = 江湖产品内「🔌 接入 AI」生成的 `jh_` 令牌（每个销售用各自令牌写进同一租户）。真实值走 `~/.digital-sales/_secrets/env.local`，chmod 600，**绝不入库**。

### 2.2 人审边界（三类，照 M1 设计）

| 边界 | 数据 | 工具 | 落点 |
|---|---|---|---|
| 🟢 直写 | 客户档案字段 / 商机 / 拜访记录 | upsert_account / upsert_opportunity / append_visit_note | 正式表 + `origin=workbuddy` 溯源 |
| 🔴 候选人审（PIPL） | 干系人本体 / 关系连线 | propose_person / propose_relationship | 候选层 → 收件箱 → 采纳才上图 |
| ✏️ 字段提案（human-wins） | 评分输入变更（已有干系人的支持度/角色/BI） | set_*（收编后）→ ChangeProposal | 收件箱 → 采纳 → G64111 重算 |

### 2.3 触发：双入口 + cron
两个入口靠 `externalRef`/`unifiedCreditCode` 幂等合流，**不会重复建**：

- **WorkBuddy 入口（零改动）**：销售在 WorkBuddy 说「新建客户 XX」→ 客户档案 Flow 01 建微盘档案 → `upsert_account` 推江湖。
- **江湖入口（你方案第 1 步，需小改）**：销售在江湖建客户（externalRef 空）→ WorkBuddy 定时任务 / 销售手动「认领」调 `list_accounts` 发现 **externalRef 为空 = 江湖原生建、WorkBuddy 没碰过** → 认领、分配 customer_id、企查查+网搜建档 → `upsert_account` 回写 + `propose_person` 候选。
  - **依赖**：`list_accounts`/`get_account_detail` 需返回 `externalRef`（当前只返回 unifiedCreditCode，见 §5）。
- **cron 兜底**：WorkBuddy 自动化页手建定时任务（如每 4h），周期性扫描 → 同步增量。

### 2.4 数据流（最小链）

```
WorkBuddy（生产端·本地）         MCP            江湖（SoR+前台+人审·云端）
─────────────────────         ────           ──────────────────────
[A] 企查查+网搜 → 客户档案.md   ──🟢──→  Account+profile → 作战档案视图
[B] 商机字段（销售勾选确认后）  ──🟢──→  Opportunity
    推断干系人/关系             ──🔴──→  候选 → 收件箱 → 人审 → 上画布
[C] 4h 拉录音 → 拜访记录.md     ──🟢──→  VisitNote → 拜访时间线
    评分输入（支持度/角色/BI）  ──✏️──→  字段提案 → 收件箱 → 人审 → 趋赢力重算
                              ↑（WorkBuddy 写微盘成功后再调江湖，失败不阻塞）
```
