# 集成 M1 · 实现清单（开工包）

> **配套**：`docs/集成-WorkBuddy销售包对接设计.md`（设计权威：为什么 + schema + 字段映射）。本文 = 怎么动手：精确到文件/函数/字段 + 验收 + 顺序。
> **分支**：`feat/workbuddy-integration`（从 main 切出）。**单线开发，不留 hotfix**。
> **背景**：把销售包（WorkBuddy）经 MCP 接成江湖的数据生产端；江湖做唯一 SoR + 统一前台；销售包退后台 worker。

## 决策快照（2026-06-05 已全部锁定）

| 项 | 定的 |
|---|---|
| 形态 | 江湖统一前台 + WorkBuddy 隐形后台 worker（路线 3） |
| 集成通道 | 江湖 MCP（`POST /api/mcp`）；WorkBuddy 用各自 `jh_` 令牌写进同一租户 |
| SoR | **江湖为唯一权威源**；微盘降为 WorkBuddy 本机缓存 |
| 人审边界 | 仅 **Person / Edge** 走候选人审（PIPL）；客户档案/商机/阶段/拜访/评分状态**直接 upsert** |
| 幂等锚 | `externalRef`(=销售包 customer_id) 主锚 + `unifiedCreditCode`(USCC) 副锚 |
| G64111 | **同步状态、不同步分数**（WB 推必清状态/角色/BI/UCV，江湖引擎算分） |
| win_probability | 销售在江湖里填，**WB 不推**（守"销售自填不覆盖"） |
| AI 成本 | 平台统一承担 = 给 WB 配公司统一企业模型额度（不搬 AI 进江湖后端） |
| 内测 | Mac mini v1 **冻结**；bug 走 **A**（只收反馈不修）；**数据不保留** |

**"数据不保留"带来的简化**：开发期 schema 随意 `db:push` 演进；上线直接 `docker compose down -v` 重建库 + `db:push`，**免加列迁移/演练**（设计稿里"保数据无损"相关段已作废）。

## 枚举对齐（实施时照此规整）

- 角色 `A/D/U/R/C`（A=批准人、D=拍板人、U=使用者、R=影响者·技术把关、C=教练）、支持度 `star/plus/neutral/unknown/minus/x`、变化模式 `G/T/EK/OC` —— **两边完全一致**，直传；P4 只允许非 A/D 角色，且同一商机只能单选一个。
- **商机阶段需映射**：江湖 `PipelineStage` = `线索/需求引导/方案认可/客户立项/招投标/合同谈判/合同双签`（7 段）；销售包 `funnel_stage` 6 段 → `合同签约`映射为`合同双签`，销售包无`线索`。
- `c3Items`/`c5Items` 的 key 用 `app/src/types.ts` 的 `C3_ITEMS`(7 项立项材料)/`C5_ITEMS`(5 项招采)中文项名；值为 boolean。C5 五个权威写入键固定为：`竞标方名单/家数`、`招标参数`、`评标规则`、`甲方项目代表`、`招标代理机构`。
- 客户类型 `customerType` 1/2/3 与销售包 `customer_category` 同序。

## 后端改动（`server/`）

### 1. `prisma/schema.prisma` — 加字段 + 新表
照搬设计稿 §2：Account 加 `externalRef? / region / group / primaryOwner / profile`；Opportunity 加 `externalRef? / status / productSolution / competitor / competitiveSituation / winProbability / expectedSignDate / expectedAmountW / meta`；新增 `VisitNote` 模型。
→ 改完：`cd server && npm run generate && npm run db:push` → **完全重启 node 进程**（tsx watch 不重载生成的 @prisma/client）。

### 2. `src/mutate.ts` — 扩 `applyAction`
- `ADD_ACCOUNT` / `UPDATE_ACCOUNT`：`pick` 列表加 `externalRef/region/group/primaryOwner`；`profile` 走 `S()` JSON 序列化（仿 `c3Items`）。
- `ADD_OPP` / `UPDATE_OPP`：加 `status/productSolution/competitor/competitiveSituation/winProbability/expectedSignDate/expectedAmountW`；`meta` 走 `S()`。
- **新增** `ADD_VISIT` / `UPDATE_VISIT` / `DELETE_VISIT`（VisitNote CRUD，`participants` 走 `S()`）。

### 3. `src/mcpServer.ts` — 加写工具（核心）
- `TOOL_DEFS` 加：`upsert_account`、`upsert_opportunity`、`append_visit_note`（inputSchema 仿现有 `propose_person`）。
- `callTool` switch 加对应分支。
- 实现函数（仿 `proposePerson`：`str()/num()` 校验 + **全程 `where { tenantId }`**）：
  - **幂等查找**：`先 (tenantId, externalRef) → 命中 UPDATE；再 (tenantId, unifiedCreditCode) → 命中 UPDATE 并补 externalRef；都无 → CREATE`。
  - **复用 `applyAction`**：工具内部生成 id（`acc_`/`opp_`/`visit_` 前缀）→ 构造对应 Action → `await applyAction(tenantId, action)`。不要另写 prisma 写逻辑。
  - 返回 `{ id, created|updated, note }`，带 `origin: 'workbuddy'` 溯源。
- **阶段 1.5**（依赖 Person 已采纳为正式节点）：`set_opportunity_roles`(→ SET_ROLE)、`set_burning_issue`(→ ADD_BI)、`set_ucv`(→ ADD_UCV)；`propose_person` 扩可选 `suggestedRole/suggestedSentiment`。

### 4. `src/state.ts` — 出库新字段
`assembleState` 里：account map 加 `externalRef/region/group/primaryOwner/profile(J 解析)`；opportunity map 加新字段；**新增 `visitNotes`**（按 account/opp 查 `VisitNote`，挂到对应层级）。形状要与前端 `types.ts` 同步。

## 验收（M1 完成 = 端到端跑通）

1. 本地 dev（SQLite）起后端+前端；产品内「🔌 接入 AI」生成 `jh_` 令牌。
2. curl 经 `/api/mcp` 调 `upsert_account` → `upsert_opportunity` → `append_visit_note` 写入（重复调验证幂等不重复建）。
3. `GET /api/state` 能看到新数据；前端 `CustomerHub`→客户档案→商机→拜访时间线能展示。
4. 收尾必跑：`cd app && npx tsc --noEmit && npm run test`（17 个 G64111 单测）；`cd server && npx tsc --noEmit`。
