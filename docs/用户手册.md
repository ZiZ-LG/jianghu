# 江湖内部版 · 用户手册

> 江湖用来维护大客户、大项目的干系人作战图。数据会保存到服务端；页面的保存状态会明确告诉你已保存、正在保存还是需要重试。

## 一、先建客户和商机

- 在工作区新建客户，再为客户新建商机。
- 把当前商机真正涉及的干系人加入地图，标注 A 批准人、D 拍板人、U 使用者、R 影响者·技术把关、C 教练和支持度。
- 补充 L1 组织、L2 决策、L3 情感、L4 战略关系，再结合 G64111 趋赢力找缺口。
- FORM、BI、交往日志包含真人信息，只记录与获授权销售作战有关的内容。

## 二、Workbuddy 同步和收件箱

1. 在 MCP Token 管理中按用途创建令牌，选择只读、调研提议或同步权限；不再使用时及时撤销。
2. 把系统给出的 MCP 配置放进 Workbuddy、OpenClaw 或其他兼容客户端。令牌只显示一次，不要转发或写进文档。
3. Workbuddy 可把客户、商机、拜访纪要、候选人物/关系和后续任务以同一次同步提交。
4. 每次同步都有回执：已新建、已更新、已提议、已跳过、失败会分开统计。客户端超时不等于服务端失败；先在同步回执/运行记录核对，再用原幂等键重试。
5. 机器生成的候选人物、关系、Evidence 和字段修改进入收件箱或提案，不会直接成为正式事实。

## 三、人审候选与证据

- 打开收件箱，逐项查看类型、来源、依据和归属客户/商机。
- 确认无误后采纳；信息不足就保留待核；明显错误则拒绝。批量处理会显示每项进度和失败项。
- 只有已审核的 Evidence 会进入 PDE 决策快照；等待审核或已拒绝的内容不改变评估。
- AI 分析前会显示服务端核对后的数据范围。默认不发原始日志和 FORM；如确有必要可手动包含。私密 BI、self 日志和非当前商机数据始终排除。

## 四、纠错、合并和恢复

- **纠错**：在纠错入口修改客户/商机的关键字段，或把拜访、笔记重新绑定到正确客户和商机。
- **合并重复人物**：在人物合并流程中选定保留人物和重复人物，审阅角色冲突后再确认。
- **归档与恢复**：客户/商机误归档后，由 owner 或 admin 在归档清单中恢复；日常界面不提供硬删除整棵客户树。
- 关键纠错、合并、归档和恢复会保留最小审计信息，不把 FORM、BI、日志正文复制到审计记录。

## 五、如何判断保存或同步失败

- 看页面保存状态：只有显示已保存才代表服务端已确认。
- 显示失败时保留当前草稿，不要反复快速点击；根据页面提示重试或重新登录。
- 冲突后系统会重新拉取服务端版本再排队保存。仍有冲突时，先核对同事刚修改的内容。
- Workbuddy 同步以 SyncReceipt/SyncRun 结果为准；只有其中的 `failed` 项需要处理。

## 六、日常安全提醒

- 每人只使用自己的账号和 MCP Token；按最小权限创建，泄露后立即撤销并重发。
- 不把客户隐私、密钥、令牌或未经授权的个人信息放进外部 AI 对话。
- 页面不承诺毫无延迟的“实时同步”。以保存状态、收件箱和同步回执为准。
