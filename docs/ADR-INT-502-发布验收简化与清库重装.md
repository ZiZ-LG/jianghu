# ADR-INT-502：发布验收简化与公司服务器清库重装

- 状态：已批准
- 日期：2026-07-21
- 批准人：项目所有者
- 关联任务：INT-502（发布门）；新登记 INT-503（无风险清理）、INT-504（清库重装投产路径）
- 关联计划：`docs/superpowers/plans/2026-07-11-internal-edition-development.md`
- 关联记录：`docs/内部版-发布验收记录.md`

## 背景

INT-502 原验收口径要求：无损接管公司服务器 pre-INT501 旧库（41→45 表 bridge）、三套脱敏商机人工验收、备份恢复+回滚真机演练、连续 336 小时受控运行、项目所有者签署，未完成禁止改 GO。

RC1→RC9 期间，公司 CentOS 7 服务器共五次 bootstrap 尝试全部 fail-closed 失败（依次为 `.env` 缺 `OUTBOUND_ALLOWED_HOSTS`、OpenSSL 不支持 pbkdf2、旧库无迁移历史被误判、readiness 档位错绑开发阶段、旧快照校准晚一个阶段）。五次失败均发生在改动生产库、写 marker、替换运行容器之前，`pgdata` 与运行服务从未受损——防线有效，但发布被"无损接管旧库"的复杂度死死卡住。

2026-07-21 主线梳理时项目所有者确认：**公司服务器旧库中无需要保留的真实数据**（该环境此前即记录为"无真实用户、可随意测"）。"无损接管"保护的对象不存在，其全部复杂度失去必要性。

## 决策（项目所有者 2026-07-21 四项拍板）

### 1. 公司服务器改走"备份留档 + 清库重装"

- 对旧库做最终认证加密备份并**双份留档**（服务器本地 + 异地副本；`.env` 连同 `BACKUP_MASTER_SECRET` 一并留档，丢失即历史备份永不可解）；
- 之后 `docker compose down`（不带 `-v`）→ `docker volume rm` 清空数据卷 → 按空库全新安装：容器 entrypoint 按序 `migrate deploy` 全部版本化迁移（桥接迁移在空库上为幂等 no-op，已经 CI 与本机集成测试验证）；
- `deploy-company-update.sh` 的空库分支在 readiness 通过后自动创建首个认证备份并写 bootstrap marker，使后续日常更新的 marker 验证链保持完整；
- `deploy-company-bootstrap-int501.sh` 及旧库桥接路径退出关键路径，仅为存档与集成测试兼容保留，计划 2026-10 随 legacy 清退包一并删除。

### 2. 发布验收口径简化

| 项目 | 原口径 | 新口径 |
|---|---|---|
| 三套脱敏商机人工验收 | 三旅程分别人工验收+签名 | 压缩为**一套核心旅程冒烟清单**（人工逐项勾选，覆盖登录/建档/情报→候选→人审采纳/评分与 PDE/行动回填/同 key 重试/归档恢复/viewer 只读/跨租户不可见） |
| 受控运行 | 连续 336 小时（两周） | **48–72 小时**，每日点检 |
| 指标样本门槛 | ≥100 条终态逻辑命令 | **≥20 条**；不足 20 条且零失败时由项目所有者人工判定 |
| 成功率/卡住项/重复率阈值 | ≥99% / =0 / <1% | **保留不变** |
| 备份恢复+回滚真机演练 | 必做 | **保留不变**（数据安全底线，不简化） |
| 签署 | 全角色签署栏 | 项目所有者口头拍板即 GO，签署表仍留档 |

### 3. 机制冗余只拆无风险项

死代码/孤儿样式/废弃分支与 worktree/文档纠偏本轮清理（INT-503）；双评分引擎、五套候选模型、三张 run 表、两套写纪律**保持现状**，收敛路线另立 `docs/架构-收敛路线图v1.md`，不在投产前动刀；legacy MCP 同步工具按既定 `2026-10-01` 日程清退。

### 4. 功能取舍

- 飞书妙记、得到大脑接入**已经真机验证可行，保留**（此前文档中"待真机校准"的说法过时）；
- 文件上传/手动粘贴入口保留（钉钉无开放转写 API，钉钉用户走此通道）；
- 企微全系暂时保留；
- **MomentFlow 手机竖屏时刻流退役**（INT-503 完成：竖屏直接进桌面版 Hub，进作战室后 OrientationGate 横屏提示保留）。

## 影响与边界

- `server/src/releaseMetrics.ts` 常量随本 ADR 调整：`RELEASE_OBSERVATION_HOURS 336→48`、`RELEASE_MIN_LOGICAL_COMMANDS 100→20`；阈值键名 `observed336Hours` 更名 `observedRequiredHours`。
- `docs/内部版-发布验收记录.md` 的规则行、旅程表、观察窗口表按新口径改写；Release ID 顺延 **rc10**（含 INT-503/504 变更）。
- 本 ADR 不改变：多租户隔离、AI 候选人审、BYO、幂等/审计/恢复等一切安全与真相边界；不授权双引擎/候选模型等机制统一（见收敛路线图）。
- 清库为一次性破坏性动作，仅限公司服务器本次投产执行，前置条件为**双份留档确认**；Mac mini 团队栈与本机 dev 环境不适用本 ADR 的清库条款。
