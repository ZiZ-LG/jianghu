## 1. 永久不变量

1. `https://lake2ocean.top/` 的根路径 `/` 必须始终展示公开网站首页，不能直接打开、重定向或渲染老版 CRM。
2. 公开首页导航顺序保持“首页｜自我修养｜江湖 CRM｜卧虎藏龙”；“江湖 CRM”明确进入 `https://crm.lake2ocean.top/`。
3. 老版重 CRM 只是 `crm.lake2ocean.top` 下待逐步替换的遗留实现：冻结新增功能、暂不破坏性删除、保留数据与回滚能力。
4. 恢复公开首页和删除老 CRM 是两件事。主页修复不得删除 CRM 代码、容器、数据库、卷、migration、业务记录或回滚镜像。
5. `app/dist` 是身份不明确的通用输出目录。任何文件名为 `index.html`、`assets/` 或目录名为 `dist` 的产物，都不能仅凭名称进入公开根路径。
6. 自我修养由独立开发线管理。CRM 发布任务只能核验其页面和资源未变化，不能构建、覆盖或修复其源码和阿里云目录。
7. 生产只接受不可变版本目录和经机器校验的产物身份；禁止先删除 `current` 或当前容器再上传候选。
8. 任一关键检查失败必须回滚，并重新核验公开首页和自我修养，不能只检查 CRM API。

## 3. 2026-08-24 错误部署事实

错误链路已经由构建内容和 SHA-256 对齐确认，不是根据目录名推测：

1. `cd app && npm run build`（即默认 `vite build`）生成老版/重 CRM 的 `app/dist`。
2. 本地错误候选 `app/dist/index.html` 与阿里云错误 staging `edge-81da993d76ce422eac89227aa6e8183314812d04/main/index.html` 的 SHA-256 都是 `be7df16a2862837b383d41824cc0ae07028ca5fd89cf30a2b0609f2422113385`。

错误镜像和纠正镜像使用同一个 main SHA 标签片段，进一步证明“source SHA + 文件名”仍不足以证明站点身份；必须同时绑定构建命令、内容标识和产物 checksum。

## 5. 机器校验与当前 fail-closed 状态

`scripts/verify-public-site-artifact.mjs` 对真实目录执行以下检查：

- source worktree HEAD 必须等于完整 40 位 SHA，且 tracked/untracked 状态为空；
- `index.html`、页面标题、导航、CRM 明确入口、ICP、公网安备号和图标引用必须存在；
- 老 CRM 标识、meta refresh 和 JavaScript 自动跳转不得出现在公开首页产物；
- 所有本地 `src`/`href` 资源必须存在；软链、设备、socket 和越界路径失败关闭；
- 按排序后的相对路径、文件大小和单文件 SHA-256 计算稳定目录 checksum；
- 输出 source SHA、build command、artifact path/checksum、destination host/path、canonical URL 和 title；不输出文件正文、环境变量或密钥。为防止命令日志泄密，CLI 直接拒绝任何 inline 环境变量赋值；未来安全且非敏感的构建参数必须由受审 registry 单独声明。

检查示例（当前只能做只读 plan）：

```bash
bash deploy/aliyun-edge-release.sh \
  --site public-home \
  --artifact /absolute/path/to/versioned/public-home-artifact \
  --source-dir /absolute/path/to/clean/source-worktree \
  --source-sha <完整40位SHA> \
  --build-command '<实际执行的完整构建命令>'
```

当前 `deploy/public-site-targets.json` 明确设置：

- `public-home.source.authority = unresolved`；
- `public-home.deployment.atomicRuntimeAuthority = false`。

所以即使操作者增加 `--execute` 并显式设置 `HOMEPAGE_DEPLOY_APPROVED=YES`，脚本也会在任何 SSH、上传、Docker、Nginx 或软链操作之前返回 `PUBLIC_SITE_RELEASE_BLOCKED`。禁止添加环境变量后门、替换 registry 参数或临时删掉检查。

## 6. 启用生产发布前必须另行通过的阶段门

真正启用公开首页发布，需要项目所有者另行批准会触及共享区的任务，并同时完成：

1. 把公开首页源码归并到 `origin/main` 的专属目录，固定唯一构建命令和专属产物目录，彻底消除 `app/dist` 身份碰撞；正式 release executor 必须在已验证的 clean source SHA 上自行执行该命令并接管输出，不能把外部传入目录与一个无关 SHA 拼成“来源证明”；
2. 修改并审核共享 Nginx/边缘运行方式，使在线根目录真实读取版本根目录内的 `current` 指针，而不是嵌在镜像中；
3. 候选先上传到全新不可变版本目录；验证完整后，以同一文件系统的临时软链加原子 rename 切换 `current`；
4. 切换前保留上一指针、上一镜像/容器和所有自我修养文件；禁止先删当前版本；
5. 候选通过 Nginx 配置检查、内容身份检查和三站预检后才可切换；
6. 把 registry 的两项 gate 改为可执行时，必须同步新增真实原子切换、故障注入和回滚测试，不能只改两个布尔值。

在上述阶段门完成前，现行安全动作是“拒绝公开首页生产发布”，不是复用历史 ad-hoc Dockerfile。

## 7. 部署后强制冒烟矩阵

每次公开边缘、CRM 或共享路由发布后，至少验证：

1. `https://lake2ocean.top/` 返回 200，标题和公开首页标识正确；无 meta refresh、脚本或服务端 3xx 自动进入老 CRM；
2. 公开首页导航顺序为“首页｜自我修养｜江湖 CRM｜卧虎藏龙”，CRM 链接明确到 `https://crm.lake2ocean.top/`；
3. `https://crm.lake2ocean.top/` 可打开登录/注册页，`/api/health/ready` 返回健康；登录 API 路由仍可达，但冒烟不得在聊天或日志暴露凭据；
4. `https://stephen.lake2ocean.top/` 标题、JS/CSS、favicon/备案图标和页面资源 checksum 与发布前一致；
5. 三站都显示“京ICP备2026046195号-2”和“京公网安备11010802049879号”，公安备案图标可加载；
6. `/healthz-lake2ocean` 与 `/healthz-stephen` 返回 `ok`；公开根站 `/api/` 仍隔离，不得代理 CRM API；
7. Nginx 配置检查通过，CRM server/web/db 保持健康，未出现跨站资源 404、控制台错误或证书异常。

任一项失败即判定发布失败，不允许用“CRM API 正常”覆盖公开首页或自我修养失败。

## 8. 回滚方法

### 8.1 当前嵌入镜像拓扑

1. 切换前记录活动 `zizai-site` 容器的完整 image ID、image tag、端口、证书挂载、restart policy 和健康检查；保留旧容器/镜像，不删除。
2. 候选镜像必须先以不占用 80/443 的方式检查 Nginx、三站静态内容和自我修养 checksum。
3. 切换失败时停止候选，恢复原容器名、原 image ID、80/443、证书挂载和 restart policy。
4. 恢复后完整重跑第 7 节，特别是公开首页和自我修养；不得只测 CRM API。

当前已验证的公开首页回滚镜像为 `zizai-site:public-security-filing-corrected-81da993`（image ID `sha256:8b3a525a702dd22275c33e9603fcde59c2bd65cff091ebcaa412c4f5551576ce`）。这是当前恢复锚，不授权从本文直接执行生产变更。

### 8.2 未来原子指针拓扑

1. 切换前记录 `readlink current` 为 `previous_release`，并验证它位于批准的版本根目录；
2. 只在新版本目录完整上传并通过检查后，建立临时软链并用同文件系统原子 rename 替换 `current`；
3. 冒烟失败时用同样方式把 `current` 指回 `previous_release`，执行 Nginx 检查/安全 reload；
4. 回滚后重跑公开首页、自我修养、CRM、备案、API、登录和健康矩阵；
5. 候选与上一版本均保留到验收窗口结束，禁止自动 prune 回滚锚。

数据库不属于公开首页回滚对象。不得运行 `db push`、删除 CRM 数据或删除老 CRM 来修复静态主页。

## 9. 角色与停止条件

- CRM 线程可维护本文、机器 registry、产物校验器和 CRM 专属部署检查。
- 自我修养线程独占其源码、构建和阿里云版本目录；CRM 线程只能只读验收。
- 主站源码归并、跨站导航、通用 Nginx、公共 CI 或边缘 runtime authority 都是共享区；必须列出精确文件并再次取得项目所有者批准。
- 未得到“批准部署”不得执行生产；未得到“批准合并”不得合并 main。
- 发现线上映射与 registry 不一致时停止，不得通过放宽 title/marker/destination 检查换取通过。
