# 策略引擎（内部代号 PDE）· 融入策略沙盘的设计方案

> **一句话定位**：策略沙盘的量化推演内核——用**立场分布**替代单点标签、用**证据**持续修正局势、用 **EV 纪律**决定资源投放姿态，并在此之上**自动推演 2-3 个成形的候选方案包（策略+行动）**，人审采纳后一键展开到沙盘与行动计划。
> **效果验收（用户原话）**：系统获取背景信息后，由策略引擎自动推演出实现相关目的的几个候选方案（包括策略和行动）→ 用户决策选择或手动补充/修改 → 系统将其纳入行动计划。
> **来源**：`jianghu-pde-module-design-v0.1.md`（销售德扑决策引擎草案）× 江湖既有体系（G64111 / 牌桌贡献分 / 沙盘 v2 / 行动计划）的融合；对草案的六处修订见 §1。
> **对外命名**：「策略引擎」（沙盘内入口「⚡ 推演」）；不出现德扑/赌博语汇（草案 §10 合规对策继承）。
> **状态**：设计稿（方案包对比视觉稿已过目）。

## 1. 对 PDE 草案的吸收与修订

**全盘吸收**：三引擎内核（范围/贝叶斯/EV）；伪计数三态分布 + 等效样本量 n + 归一化熵 H；「行为信号 > 言语信号」的信号库；四动作纪律（FOLD/CHECK/CALL/RAISE，CHECK=便宜看牌是最差异化输出）；沉没成本不入式；`inputsJson` 决策留痕（复盘决策而非结果）；全部 NG 与合规对策（不做对客话术操纵、pWin 防伪精确、干系人是盟友不是对手）。

**六处修订**：

| # | 草案原设计 | 修订 | 理由 |
|---|---|---|---|
| 1 | Deal/Stakeholder/Diagnose/Execute 自成对象体系 | 映射：Deal→Opportunity、Stakeholder→Person+OppRole、Diagnose→关系地图+G64111、Execute→行动计划 | 不造平行体系（草案 §8 自己的修订建议反向落地） |
| 2 | P0 = 销售手动滑杆评估，目标 ≤10 分钟/商机 | 立场分布从现有 `sentiment × confidence` **自动推导**（映射表 §3.1），0 分钟起步；滑杆校准降为可选 | 江湖已有六档支持度+四级置信度，正是「带置信的立场」；这是融合的最大红利 |
| 3 | pWin 为核心展示 | **EV（万元）为主语言**，pWin 小字+强制置信标记；趋赢力保持全产品唯一大百分数 | 两个百分数并存必混淆；G64111=唯一权威「局面分」，引擎=「投放纪律参考」 |
| 4 | 证据更新分布后独立演化 | 分布与人审支持度显著背离时生成**「支持度变更提案」**走人审，绝不静默改 | 守铁律②（AI 不直写评分输入）+ 根治双事实源；接 P0 变更提案层主线 |
| 5 | 输出止于四动作建议 | 四动作之上加 **L2 方案包生成层**（§4）——成形的候选方案（策略卡组+行动序列+预期+成本） | 用户要的效果是「候选方案」而非方向建议 |
| 6 | 影响力权重 wᵢ 人工录入（来自 Diagnose） | 用牌桌**贡献分 potential 归一化**作默认权重（D=34/A=21/KI=11…），可手调 | 又省一道录入，且与 G64111 同源无双权威 |

## 3. L1 局势量化层

### 3.1 立场分布：零录入推导（修订 2 的落点）

三态 Dirichlet 伪计数 `(αS, αN, αO)`，从现有 `(sentiment, confidence)` 推导初值：

**方向（sentiment → 概率质量分配比例）**：

| sentiment | ☆ 排他支持 | + 支持 | = 中立 | ? 未知 | − 抗拒 | x 倒向对手 |
|---|---|---|---|---|---|---|
| (S : N : O) | 0.80:0.15:0.05 | 0.65:0.25:0.10 | 0.15:0.70:0.15 | 1/3:1/3:1/3 | 0.10:0.25:0.65 | 0.05:0.15:0.80 |

**把握深度（confidence → 等效样本量 n₀）**：共识 8 ｜ 明确 6 ｜ 推理 3 ｜ 不清 1.5。

`α 初值 = 比例 × n₀`。例：钱大钧（+ 支持 · 明确）→ (3.9, 1.5, 0.6)，n=6，熵中低；王教授（= 中立 · 推理）→ (0.45, 2.1, 0.45)，n=3，熵偏高 → 天然成为 CHECK 的降熵目标。

- **派生关系**：`(sentiment, confidence)` 是人审权威快照（G64111 输入，不变）；分布是其派生视图 + 证据累积。人审改支持度 → 分布按新值重置锚定；证据漂移 → 见 §6 提案机制。
- 可选校准滑杆（E2）：调整后映射回伪计数，`priorSource=manual`。

### 3.2 影响力权重：复用贡献分

`wᵢ = potentialᵢ / Σ potential`（来自 `personContributions`，D=34/A=21/KI=11/招采 5/普通 1，身兼叠加）。与 G64111 同源，无第二套权重录入；E2 允许手调（存 `StanceProfile.influence`）。

### 3.3 S / pWin / EV / 四动作（继承草案 §4.3，初值照单）

```
S    = Σ wᵢ·(pSᵢ − λ·pOᵢ) / Σ wᵢ          λ=1.3（反对杀伤系数，一票否决语境）
pWin = σ(k·(S − S₀)) × C                   k=4, S₀=0.15, C=竞争修正(人工,默认1)
EV(continue) = pWin × potValue − plannedCost     // 沉没成本不入式
potValue = expectedAmountW × 毛利率(租户配置,默认 0.3)
plannedCost = owner 整体估值（存 Opportunity.meta.plannedCostW，E0 不动 schema）
```

四动作触发条件照草案表（FOLD：EV<0 连续两期且无正 ΔEV 翻盘动作；CHECK：关键人 w>0.25 且熵>0.85 或 n<6；CALL：EV>0 平推；RAISE：存在 ΔEV/cost ≥ 1.5 的动作且处阶段窗口）。

### 3.4 防伪精确与双分数纪律（修订 3 的落点，UI 红线）

- 引擎面板主数字 = **EV（万元）** + 姿态徽章；pWin 以小字呈现且**永不裸出**——必须伴随置信标记（`低置信·样本偏少` / `高熵警示`）与「内部参考值」字样；
- 趋赢力（G64111 百分数）仍是沙盘现状锚与全产品唯一的大百分数；引擎面板不出现第二个大百分数；
- 方案包的「预期效果」用 **Δ趋赢力**（G64111 分值语言）表达而非 ΔpWin——销售已熟悉这套语言，且可被引擎事后验证。

## 4. L2 方案推演层：候选方案包 ★用户核心诉求

### 4.1 方案包（Playbook）结构

```ts
interface Playbook {
  key: string;            // frontal | flank | check | hold | fold
  title: string;          // 「正面攻坚 · 拿下拍板人」
  tone: 'raise'|'check'|'call'|'fold';
  rationale: string;      // 一句话依据（杠杆/缺口/窗口）
  targetPersonIds: string[];        // 攻坚目标（杠杆排序 top）
  cards: { gapItem, title, basis, personId? }[];      // 2-4 张策略卡
  actions: { title, kind: 'gain'|'probe', gapItem, personId?, offsetDays, scene? }[];  // 3-6 个行动；probe=信息型(CHECK 的产品化)
  expectedDelta: { winTendency?: number; confidence?: '↑' };  // 预期 Δ趋赢力 或 置信提升
  costTier: 'low'|'mid'|'high';
}
```

### 4.2 生成算法（规则骨架 + LLM 润色，两段式）

1. **杠杆排序**（确定性）：对每个干系人计算 `∂趋赢力/∂支持度`——直接复用贡献分 `upside`（把此人经营到位能解锁多少分）× 路径可达性（是否有 ☆/+ 的引荐通路相连，查关系地图边）。输出杠杆榜。
2. **基调与路线**（确定性）：按 L1 姿态生成差异化包——RAISE → ①正面包（杠杆 #1 直攻）+ ②迂回包（经高支持度 R/教练触达高杠杆目标，路径来自关系地图）；CHECK → ③探牌包（全 probe 行动，目标=高熵关键人降熵）；CALL → 稳进包（里程碑节奏+关键人保温）；FOLD → 止损包（建议降投入/转养单，**只建议绝不自动执行**）。任何姿态都至少附带一个探牌包（信息永远有价值）。
3. **行动模板**（确定性）：gapItem → 行动宝典动作话术库的模板映射（C1-FORM→FORM 补全拜访 / P3→单独深谈·密谋级 / 1K→高层引荐 / C2→BI 验证访谈 / C5→招采关键人接触…），`kind` 按「直接提分 vs 采集信息」标注。
4. **LLM 润色**（可选增强）：把骨架交给 BYO 模型润色 title/basis/scene（话术要点），无 Key 走 mock 规则文案——**复用现有 `strategySuggest` 架构升级**（`server/src/strategy.ts` 扩一个 `mode: 'playbook'`），不另起服务。

### 4.3 候选不落库

方案包前端本地暂存（对齐沙盘 AI 候选惯例，比草案更严格守铁律②）；「重新推演」即重算。采纳展开才落正式表。

## 5. L3 人审与落地

1. **入口**：沙盘顶条「⚡ 推演」按钮（替代/收编现有「AI 顺推/倒推」两个按钮——单卡候选升级为方案包，旧泳道虚位卡机制保留用于展开后的呈现）。
2. **对比 UI**（已出视觉稿）：顶部局势条（姿态徽章+EV+pWin 小字+置信+依据）；2-3 个方案包卡并排（基调/依据/勾选式行动清单/预期 Δ趋赢力/成本档）；底部「采纳所选 → 展开到沙盘与行动计划」。
3. **混选与修改**：勾选粒度=单条行动/策略卡，可跨包混选；展开前可改目标人/日期；展开后全部是普通卡，随意编辑（机器写初稿 · 人改是常态）。
4. **展开落库**（复用现有 Action，零新写库通道）：策略卡 → `ADD_STRATEGY_CARD`（origin=ai）上泳道；行动 → `ADD_PLAN_ACTION`（origin=ai，gapItem/personId/scene 继承，startDate=今天+offsetDays）入行动计划日历；复用 `dispatchToPlanner` 防重复模式。probe 行动带「🎯信息」标记，完成回填时引导记录验证结论（接行动结果回填设计）。

## 6. 证据闭环（E2）

- **信号库**：预置江湖版模板（草案表本地化，方向挂 G64111 语义）：`intro_referral` 主动引荐高层(+强,联动 1K/P3) / `spec_alignment` 条款向我方收敛(+强,联动 C5) / `attendance_upgrade` 出席升级(+中) / `verbal_positive` 口头表态(+弱,刻意低权) / `reply_latency_up` 回复变慢(−弱) / `meeting_cancel` 会议被取消(−中) / `competitor_quote_request`、`internal_blocker_hint`(±人工定向)。租户可扩展。
- **证据来源**：①行动完成回填（done+结论 → 半自动建议信号）②手动录入 ③WorkBuddy 拜访抽取（录音→信号候选，走审核收件箱——机器写初稿范式的又一作者）。
- **更新流水线**：`EvidenceEvent(pending_review)` → 人审 approve（可改方向/强度）→ 伪计数更新 → 重算 EV → 落 `EVSnapshot(trigger=evidence_approved)`。手动录入默认直接生效（录入者即审核者，租户可配）。
- **分布→支持度提案（修订 4 的落点）**：当分布主导方向与人审 sentiment 背离且置信足够（如 pO>0.6 而 sentiment 仍为 +，n≥6）→ 生成「支持度变更提案」进审核收件箱，附证据清单；人审采纳才改 OppRole.sentiment → G64111 重算。**引擎永远不直接动评分输入**。
- **阶段门重估**：pipelineStage 推进（招投标/合同谈判等）→ 强制落快照并提示复核姿态（相当于发新一条街牌）。

## 7. 数据模型（Prisma，江湖惯例化：String 存 JSON、无原生 enum、accountId 冗余、tenantId 硬隔离）

**E0/E1 零 schema**：分布/S/pWin/EV 全部前端纯函数派生（`app/src/lib/pde.ts`，模式同 g64111.ts，可单测）；plannedCost 存 `Opportunity.meta`。

**E2 四表**：

```prisma
model StanceProfile {   // sp_xxx：仅当用户校准过/有证据累积才落行（否则纯派生不落库）
  id String @id

  @@index([tenantId, opportunityId, status]);  @@index([tenantId, status])
}
model EVSnapshot {      // evs_xxx：复盘决策而非结果（G3）

```

## 9. 分期（比草案 P0-P2 更快：复用红利）

| 期 | 范围 | schema | 周期 | 验收 |
|---|---|---|---|---|
| **E0 局势面板** | `lib/pde.ts` 推导+S/pWin/EV/姿态纯函数（含单测）+ 沙盘 EnginePanel（EV 主数字/pWin 小字置信/姿态+理由） | 零 | ~3-5 天 | 3 个真实商机的姿态判定被 owner 认可；pWin 永不裸出 |

| **E2 证据闭环** | 四表 + 信号库 seed + 行动回填→证据→分布→支持度变更提案 + 阶段门快照 + 审核流（与 P0 提案层合流） | 4 表 | ~2 周 | 证据 approve→EV 重算全链路；至少 1 例分布背离生成提案并被人审处理 |

## 10. 合规与风险（继承草案 §9-10 + 两处澄清）

- 继承全部：不做信息操纵、pWin 内部参考禁止外引、干系人是盟友语汇、视图权限限内部、参数租户可配、拒绝建议无需审批且留痕。
- **澄清 1（话术边界）**：行动的 scene「沟通要点」来自行动宝典（教练性质的拜访准备），允许；禁止生成虚假信息、诈唬性话术——与草案 NG1 不冲突。
- **澄清 2（FOLD 边界）**：止损包只输出建议与理由（含释放资源去向提示），不自动暂停商机、不自动取消已排行动——战略性放弃的执行权完全在人。
