## 使用规则

1. 本文件是内部版唯一日常状态清单；详细做法和验收以计划文档为准。
2. 默认同一时间最多一个任务处于 `IN_PROGRESS`；只有项目所有者明确批准、任务无依赖且不改共享文件时，才可并行两项并记录原因。
3. 任务开始前填入分支/worktree、Owner 和开始日期。
4. 任务只有满足计划中的完成定义并附验证证据后才能勾选。
5. 阶段门未通过，不得开始下一阶段的功能任务。
6. 普通调整更新本清单；重大偏差先按架构基线暂停、评审和批准。
7. 不以“代码已经写了”作为完成标准；没有测试、验收和恢复说明即未完成。

状态值固定为：`PENDING / READY / IN_PROGRESS / BLOCKED / DONE`。

## 预计节奏与容量边界

按一名全职开发、严格小步验证估算：

| 阶段 | 预计 | 容量重点 |
|---|---:|---|
| M0 | 2–3 天 | 测试地基 |
| M1 | 3–4 周 | 共享核心、安全、PDE/G64111 |
| M2 | 2–3 周 | 写入、事务、Workbuddy 同步 |
| M3 | 1.5–2 周 | 最低纠错和契约回归 |
| M4 | 1–1.5 周 | 主旅程和体验收口 |
| M5 | 1 周开发 + 2 周受控观察 | 迁移、恢复、发布认证 |

估算用于容量安排，不作为降低验收标准的理由。两名开发可并行无共享文件的任务，但 M1/M2 的阶段依赖仍不可跳过。

纯内部专属需求最多占同期研发容量的 15%–20%；共享核心、安全和可靠性保持 50%–60%；其余容量用于已经批准的商业版独立计划，不在本清单中登记。
