## 1. P0 现状评估（保什么、改什么）

P0（`StrategySandbox.tsx`）已具备：三栏（现状/方向/终局）、策略卡 CRUD + gapItem 挂靠 + 缺口覆盖 ✓、AI 顺推/倒推（`api.strategySuggest`，候选本地暂存、采纳落库）、派发行动（`dispatchToPlanner` → PlanAction）、风险/假设/弹药、里程碑（共享 DealPlanner 的 OppMilestone）。**这些逻辑全部保留复用。**

要改的是呈现层四个问题：

1. **链路不可见**：缺口 → 策略卡 → 里程碑 → 行动是沙盘的灵魂，但三个纵列表之间没有视觉关联；
2. **候选不在位**：AI 顺推候选堆在方向栏顶部一坨列表，与它针对的缺口/将落的位置脱节；
3. **里程碑无时间感**：列表呈现，没有「从今天倒排到签约日」的时间轴叙事，也没有最晚时间红章；
4. **缺口只有一种**：只有「G64111 缺口被策略卡覆盖」，没有里程碑级的「前置条件缺口」与「时间冲突」信号。

## 2. 新信息架构：三锚双泳道

```
顶条  商机切换 | 741 band 药丸 | 三态切换[正推|倒推|合并] | ✨AI 顺推/倒推
─────────────────────────────────────────────────────────
策略泳道（正推：现状 → 方向）                    ←横向滚动→
 [现状锚]  [策略卡]  [策略卡]  [候选虚位卡]  [＋新建]
    ↓ 驱动 · 策略落到里程碑，缺的前置条件即缺口
里程碑泳道（倒推：终局 → 最晚时间，按日期升序）
 [里程碑卡] [里程碑卡] [里程碑卡] [候选虚位] [终局锚]
─────────────────────────────────────────────────────────
信号汇总条  ▢前置缺口 n | 风险 n·高 n | 策略覆盖 a/b | 前置就绪 c/d | 展开汇总
右侧  点击任意卡 → 详情抽屉（360px 热切换，Esc/空白关闭，不跳路由）
```

- **现状锚**（只读）：741 band + 趋赢力 % + 缺口 Top3（点缺口行 = 在策略泳道挂新卡，继承 P0 的 ＋ 行为）+ 展开看关键干系人/弹药清单。
- **终局锚**（可编辑）：目标名 + 截止日（= `Opportunity.expectedSignDate`，倒排基准）。
- **双泳道横向滚动**，桌面 wheel 横滚、移动端 touch 横滑；卡序：策略卡按 `orderIndex`，里程碑按 `startDate` 升序（最晚时间语义）。
- 风险/假设与弹药从常驻栏降级为：挂靠里程碑的进卡片脚注，未挂靠的进底部「展开汇总」（原型 backcast-map 的 summary 区）。

## 3. 三态 overlay（同一画布，只切强调）

| 模式 | 强调 | 淡化（opacity .35–.45） | 一句话文案（顶条右侧） |
|---|---|---|---|
| 正推 | 现状锚 + 策略泳道 + ✓已具备 chips | 终局锚、缺口 chips、风险脚注 | 从现状与弹药出发，看能推进到哪 |
| 倒推 | 终局锚 + 里程碑泳道 + 最晚时间章 + ▢缺口 chips | 现状锚、策略泳道 | 从签约日反推最晚时间，逼出缺口 |
| 合并（默认） | 全部 + 缺口/冲突/失血高亮 | — | 两个方向会师，未交汇处即缺口 |

实现 = 容器 CSS 类 `sb2-fwd / sb2-back / sb2-merge` 控制子元素透明度与强调框（原型 `m-fwd/m-back/m-merge` 手法），零路由、零数据变化。切态持久化 `usePersistentState('jianghu.sandboxMode', 'merge')`。

## 4. 卡片规格（与牌桌视图同设计语言）

### 4.1 策略卡（正式）

```
┌─┬───────────────────────────┐
│色│ [1K 与A]gapItem chip   ✓已派发│  ← chip 点击=高亮现状锚对应缺口行（依据溯源）
│脊│ 借李晓敏引荐触达周志远        │  ← 标题 13px 加粗
│  │ 依据：教练L4可搭线 · 弹药：…  │  ← 依据/弹药 11px 次级
└─┴───────────────────────────┘
```
- 色脊：`--ok`（绿）= 已派发行动；中性 = 未派发；右上角未派发时显「→ 派发」按钮（复用 `dispatchToPlanner`）。
- 目标干系人显示姓名 chip，点击 = 跳关系地图选中该人（P2，先显示不跳）。

### 4.2 里程碑卡

```
┌───────────────────────────┐
│ 需求定义植入      [最晚 10/15]│  ← 红章 mono 字体（倒排 deadline 语义）
│ ✓ CP3D 信创实测              │  ← 前置条件 chips：✓已具备（绿底）
│ ▢ 客户预算确认 → 建行动       │  ← ▢缺口（红虚线边），点「建行动」生成 PlanAction
│ ───────────────────────── │
│ 假设：Q4 招标如期启动         │  ← 挂靠的风险/假设脚注（StrategyRisk.milestoneId）
└───────────────────────────┘
```
- 冲突态：2px 红边 + 脚注红字（触发规则见 §6）。
- 前置缺口「→ 建行动」：生成 `PlanAction`（title=补齐该前置，gapItem 继承里程碑关联，origin='ai'），与策略卡派发同模式——**行动 done 后结果回填（见行动闭环设计），chip 翻 ✓、就绪度上涨**，沙盘因此「活」起来。

### 4.3 候选虚位卡（AI 顺推/倒推 + 未来 MCP 作者）

灰/琥珀虚线边 + 斜盖「待采纳」章 + 采纳/忽略钮——与牌桌「待核实卡」同语言。**呈现位置 = 它将要成为的位置**：顺推候选插在策略泳道尾部（带 gapItem chip），倒推候选按 offsetDays 换算日期插在里程碑泳道对应时间位。逻辑复用 P0 的 `fwdCands/bwdCands` 本地暂存与 `acceptFwd/acceptBwd`，只改渲染位置。未来 MCP `propose_strategy_card`（WorkBuddy 作者）走 `StrategyCard.status='pending'` 落库后同样以虚位卡呈现——一个泳道，多个机器作者。

### 4.4 锚卡

现状锚 = band 色边 + 趋赢力大数 + 缺口 Top3 行（分数红色）；终局锚 = 危险色底（印章红语义）+ 目标名 + `≤ MM/DD` 章。终局未设截止日时：倒推按钮禁用 + 锚卡显「先设截止日」（PRD §10 边界）。

## 5. 详情抽屉（点击即详情，P2 原则）

单击任意卡 → 右侧 360px 抽屉滑入（复用现有 `.drawer` 体系与移动端全屏惯例）：策略卡 = 全字段编辑 + 备选打法 + 派发历史；里程碑卡 = 标题/日期 + 前置条件增删改（label/satisfied/引用弹药）+ 挂靠风险管理；候选卡 = 完整依据 + 采纳/忽略。点另一张卡热切换，Esc/点空白关闭。P0 的 inline input（onBlur 保存）模式在卡面保留「双击标题改名」，复杂编辑进抽屉——对齐画布 EdgeDrawer/DetailDrawer 惯例。

## 6. 信号引擎 `diagnoseSandbox`（纯函数，前端实时）

输入 `(cards, milestones, risks, gaps, expectedSignDate)`，输出四类信号，任一数据变更即重算（渐进明晰）：

| 信号 | 规则（v1） | 呈现 |
|---|---|---|
| 策略缺口 | G64111 缺口项无 active 策略卡覆盖（P0 已有 coverage） | 现状锚缺口行无 ✓ + 汇总条「策略覆盖 a/b」 |
| 前置缺口 | 里程碑 precondition.satisfied=false | ▢ 红虚 chip + 汇总条计数 + 展开列表 |
| 时间冲突 | ①里程碑 startDate > expectedSignDate；②未满足前置的里程碑距今 < 7 天 | 卡 2px 红边 + 脚注红字 + 汇总条 |
| 风险 | StrategyRisk open 且 severity=high | 汇总条「风险 n·高 n」 |

**命名澄清（防双分数混淆）**：汇总条只显示「策略覆盖 a/b · 前置就绪 c/d」两个**完备度计数**，不合成 0-100 的「就绪度分」——避免与趋赢力并列出现两个百分比让销售不知道信哪个。趋赢力（赢单概率）只在顶条 band 药丸，权威唯一 = `g64111.ts`。

## 7. 数据模型最小变更（唯二）

```prisma
model OppMilestone {
  preconditions String @default("[]") // 新增。JSON: [{id,label,satisfied,resourceId?}]（跨库可移植惯例：String 存 JSON）
}
model StrategyRisk {
  milestoneId String? // 新增。可选挂靠里程碑 → 卡片脚注；空 = 留在汇总区
}
```

- 皆可空/带默认；本地 SQLite `db:push` 后**完全重启 node**（@prisma/client 热重载坑），生产须对应版本化 migration。
- Action 契约同步（CLAUDE.md 硬规则⑤）：`UPDATE_MILESTONE` patch 白名单加 `preconditions`、`UPDATE_STRATEGY_RISK` 加 `milestoneId`——前端 `store.ts`/`types.ts` + 后端 `mutate.ts`/`state.ts` 四处同步。
- 不新增表、不动 StrategyCard/StrategyResource。

## 8. 范式与闭环衔接

1. **机器写初稿**：顺推/倒推候选（本地）+ 未来 WorkBuddy `propose_strategy_card`（落库 pending）统一以虚位卡呈现在泳道位置上——审核动作发生在「内容将要生效的地方」，这是收件箱理念在沙盘的就地化身；
2. **行动闭环**：策略卡「→派发」与前置缺口「→建行动」都生成带 gapItem 锚的 PlanAction → 行动完成走结果回填（路径 A 结果确认卡）→ 评分状态/前置 satisfied 更新 → 沙盘 chips 翻绿、趋赢力重算——**沙盘是闭环的指挥台，不是静态白板**；
3. **溯源**：所有 origin（manual/ai/未来 workbuddy）在抽屉显示来源与依据，AI 卡带「依据」必填约束（无依据不出候选）。

## 9. 移动端

- 双泳道纵向堆叠（策略在上、里程碑在下），泳道内保持横滑；锚卡吸附泳道首尾。
- 三态切换收进顶条下拉（复用 OverflowMenu）；汇总条固定底部（avoid safe-area）；抽屉全屏（既有惯例）。
- 虚位卡的采纳/忽略钮加大到 32px 触达高度。
