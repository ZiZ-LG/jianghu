# 推演坞 · 横向推导链 施工方案（不动代码 · 分刀图纸）

> 把「局势 → 策略 → 倒排 → 行动」从当前的**竖堆泳道**转成**左→右推导流水线**，并让「和地图对话」收进坞作贯穿操作层、行动牌「拖上桌」挂到人旁。

> 状态：**四刀全部施工完成（2026-07-02）**：第1+2刀 `6048b54` · 第3刀 `5a27795` · 第4刀（减配版=上桌按钮，见下）。第5/6刀（坞收敛/旁支退役 `9d3740e`/`d7378bf`）在本图纸后另行拍板插队施工，坞现为真三层——本文「信号汇总留坞底」「EngineBar 保留坞头」等描述已被第5/6刀取代，以刀后现状为准。

## 现状（当前坞结构，`DeliberationDock.tsx`）

坞是**纵向堆叠的三条横向泳道** + 汇总：
```
坞头（趋赢力药丸 + 聚焦 chip + 三档高度 collapsed/half/full）
├─ EngineBar（局势判断→打法→排期→健康度，横条）
├─ 策略泳道 sb2-lane（横滚）：现状锚 sb2-anchor → 策略卡 → AI 顺推候选虚位卡
│    ↓ 驱动
├─ 里程碑泳道 sb2-lane（横滚）：里程碑 ← AI 倒推候选 → 终局锚 sb2-goal
│    ↓ 执行
├─ 行动清单 sb2-lane（横滚）：行动牌 sb2-action（点牌开抽屉）
├─ 信号汇总条 sb2-signal（未覆盖缺口 / 风险 / 弹药）
└─ 展开汇总 sb2-summary（缺口·干系人 | 风险·假设 | 弹药）
```
- 左栏 `Sidebar.tsx` = 诊断台 diag-score + 分隔条 diag-resizer + `ChatPanel`（对话，chatH 可拖高）。
- `AddIntel.tsx` = 口述 / 录音 / **和地图对话** 三 tab（对话与左栏 ChatPanel 是同一个组件 → 上一轮发现的冗余）。
- 画布 `Canvas.tsx` 已实现：节点旁挂 planActions 牌（`data-action`）+ 点牌就地反馈（`data-action-fb`）。
- `PlanAction`（types/store）六要素已备：`title` / `target`(目的) / `personId`(目标) / `ownerId`(责任人) / `resources` / `cautions` / `props`(道具) / `done`。

## 目标态（三大决策）

1. **横向四列**：局势 | 策略 | 倒排 | 行动，左→右推导，列间箭头显因果。
2. **对话收进坞**：`ChatPanel` 从左栏移进坞底作「贯穿操作层」，左栏纯化成诊断台；`AddIntel` 去掉对话 tab（只剩口述/录音喂料）。→ 顺带收口上一轮「对话去重」悬案。
3. **拖上桌 = 状态跃迁**：坞内行动 = 草稿；拖到画布挂人 = 作战令。派发即 AI 预填六要素；区分「打谁(personId)」与「谁执行(ownerId)」。

## 第 1 刀 · 对话收进坞 + 左栏纯化（低风险，先做，解去重悬案）

**做什么**：把「和地图对话」从"两处冗余"收敛为"坞里一处"。
- `Sidebar.tsx`：删 `ChatPanel` 渲染 + `diag-resizer` + `chatH`/`onResizeDown` + `onChatDone` 透传；诊断台 diag-score `flex:1` 占满左栏。
- `DeliberationDock.tsx`：坞底（EngineBar 下 或 坞尾）加一条常驻「和地图对话」操作条（复用 `ChatPanel`，props account/opp/onDone）；collapsed 档也给个入口（半展开可见）。
- `AddIntel.tsx`：移除 `chat` tab（`Way` 只剩 dictate/record），nav 与 body 同步；对话不再算"喂料"。
- `App.tsx`：`onChatDone` 从 Sidebar 迁到坞；`Sidebar` 去掉 chat 相关 props。
- `styles.css`：`.diag-*` 去分隔条相关；坞对话条样式。

**schema**：无。**风险**：低（组件搬移、逻辑不变）；左栏布局变（诊断台占满，需确认滚动）。
**验收**：坞底对话可改图直落（voiceExtract 双轨不变）；左栏纯诊断台；AddIntel 两 tab；tsc + 80 单测；preview 无回归。**同时关掉上一轮的对话去重 TODO（见 `jianghu-design-code-gaps`）。**

## 第 2 刀 · 坞横向四列转置（中风险，纯布局，近零 schema）

**做什么**：把三条竖堆泳道重排成四个横向列。
- `DeliberationDock.tsx`：渲染结构从「lane 竖堆」改「column grid（`grid-template-columns` 四列）」：
  - 列① **局势**：抽出现状锚 sb2-anchor（趋赢力% + 缺口 gaps）独立成列；EngineBar 可并入列①或保留坞头。
  - 列② **策略**：策略卡纵向堆 + AI 顺推候选虚位卡（`fwdCands`）。
  - 列③ **倒排**：里程碑纵向堆（带时间）+ AI 倒推候选（`bwdCands`）+ 终局锚 sb2-goal。
  - 列④ **行动**：行动牌 sb2-action 纵向堆。
  - 列间箭头（→）替代现在的「↓ 驱动 / ↓ 执行」。
- `styles.css`：`.sb2-lane`(横滚) → 列容器（纵向滚）；新 `.sb2-col` 网格。
- 信号汇总 sb2-summary（风险/弹药/假设）保留坞底或折叠，**不进主链**（旁支）。
- 移动端：四列退化成「tab 切列」或竖排（复用现有 collapsed/half/full 或加列切换）。

**schema**：无（数据不变，只重排渲染）。**风险**：中（坞渲染大改；竖向空间有限，四列在 half 档挤 → 靠 full 档或列内滚；移动端要另设计）。
**验收**：四列左→右 + 箭头；各列内容/候选虚位卡/点卡抽屉不变；`selectedPersonId` 聚焦高亮跨列仍在；桌面 full 档舒展、half 档可用、移动端可切列；tsc + 单测 + preview。

## 第 3 刀 · 派发即 AI 预填六要素（中风险，"数据来自引擎、人微调"）

> ✅ 已施工（2026-07-02）：新端点 `/api/strategy/prefill`（11 缺口四要素模板 mock 兜底 + LLM + 按目标人真实态度微调 cautions，只返回初稿不写库）；`dispatchToPlanner` 改 async 预填→落草稿(origin=ai)→开抽屉人微调，失败降级无初稿手填；字段来源徽章 🤖AI建议/✍️手改 为前端态不落库，放弃编辑重开按库值校准；「✨ 让引擎补全」只补空白要素。curl 直测 4 场景 + preview 全链路实测（含 human-wins 不覆盖已填）。

**做什么**：让行动牌的六要素默认来自 AI 初稿，人微调。
- 后端 `strategy.ts`：复用/扩 `advisorActions` 或新端点：入参「策略卡(title/gapItem) + 目标人 + 缺口」→ 出六要素初稿 `{target,resources,cautions,props?}`（mock 兜底 + LLM）。
- `DeliberationDock.tsx`：`dispatchToPlanner`（策略卡「→ 派发」）改为：调 AI 预填 → 生成行动牌**草稿**（本地/落库带 origin=ai）→ 开六要素抽屉让人微调。
- 行动抽屉：每字段标来源徽章（🤖AI建议 / ✍️手改），加「✨ 让引擎补全」按钮。
- 守铁律②：AI 预填是"草稿人微调"，人保存才算定稿（不自动生效改分）。

**schema**：无（用现有 PlanAction 字段；来源可复用 origin，或前端态）。**风险**：中（后端 AI + 抽屉 UI）。
**验收**：策略卡派发→AI 六要素初稿→人改→保存；mock 演示可用；tsc + 单测 + preview（curl 直测端点）。

## 第 4 刀 · 拖上桌 = 状态跃迁 + 责任人/目标区分（较高风险，含 schema，放最后）

> ✅ 已施工·减配版（2026-07-02）：**字段语义反转**——schema 用 `PlanAction.draft`（默认 false=已上桌）而非图纸的 staged，存量牌零迁移不消失；四处同步齐（schema→types→mutate 写→state 读）。坞内建牌（＋手建/派发）打 `draft=true` 虚线草稿卡；「→ 上桌」双入口（列④卡+抽屉「📌 保存并上桌」），无 personId 时禁用带引导；Canvas 挂牌 filter 排除草稿；参谋采纳行动保持直接上桌（原语义）；上桌走 UPDATE 通用契约可 Undo。**减配拍板：真拖拽不做（按钮保底即够）；责任人/目标 ownerId 区分未做**（借力落点语义待产品定清，Canvas filter 仍按 personId）。E2E：建→派发→预填→上桌→点牌开抽屉闭环 + 存量 6 牌全程在。⚠️ 部署需 db:push（draft 纯增量）+ 完全重启 node。

**做什么**：坞草稿 → 画布作战令 的实体动作。
- `schema.prisma`：`PlanAction` 加 `staged`（Boolean，默认 false＝坞内草稿 / true＝已上桌挂画布）。**跨库可移植：用 Boolean 或 String status，不用原生 enum。**
  - 四处同步：`schema.prisma` → `types.ts` → `mutate.ts`(ADD/UPDATE pick) → `state.ts` planActionView(读)。改后 generate + db:push + **重启 node**。
- `Canvas.tsx`：节点旁挂牌只渲染 `staged===true` 的（草稿不上画布，只在坞列④）。
- `DeliberationDock.tsx`：行动列④卡加「→ 上桌」按钮（保底）：设 `staged=true` + 确认 personId。真拖拽（增强）：坞行动卡 pointer 拖 → 画布节点 → 落位 attach（成本高一档、移动端退化为按钮）。
- 责任人 vs 目标：行动抽屉区分 `personId`(打谁·目标对象) + `ownerId`(谁执行/借谁的力·落点)；画布牌挂在**执行落点**旁、副标「为撬动 目标」。
- Canvas 挂牌 filter 从 `personId` 改为「执行落点」（ownerId ?? personId），标注目标。

**schema**：`PlanAction.staged`（+ 可能 ownerId 语义启用）。**风险**：较高（schema 改 + 拖拽交互 + 画布渲染逻辑变 + 四处同步易漏读侧，参考 P2① 踩坑教训）。
**验收**：坞草稿不显画布、上桌后挂人、（拖拽落位）、责任人/目标分列显示；tsc + 单测 + preview 端到端（建→派发→预填→上桌→点牌反馈→局势重算闭环）。

## 施工顺序与依赖

`第1刀（对话收口）` → `第2刀（横向布局）` → `第3刀（AI预填）` → `第4刀（拖上桌+schema）`

- 1、2 是**纯前端、近零 schema**，风险最低、且 1 顺带清历史债 → 先做。
- 3 引入后端 AI 预填、4 引入 schema（最重）→ 放后。
- 每刀独立 commit + 验证（tsc 0 + 80 单测 + preview）。可在任一刀后停下评估。

## 跨刀注意

- **铁律②**：AI 预填/候选一律"草稿人审"，人保存/上桌才生效，绝不自动改分改图。
- **schema 四处同步**（仅第 4 刀）：schema→types→mutate(写)→state.ts(读)，漏读侧＝"写成功 reload 丢失"（P2① 踩过）。
- **暗色/移动端**：全语义变量（`--panel`/`--ink`/`--line`/`--accent`），四列布局在移动端退化为列切换。
- **别把旁支塞主链**：风险/弹药/假设留坞底汇总，主链只 局势→策略→倒排→行动。
