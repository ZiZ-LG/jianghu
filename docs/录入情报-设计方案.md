# 录入情报 · 语音口述 → 自动建档 + 关系图谱（设计方案）

> **定位**：销售用 **Typeless** 口述拜访情况 → 转文字、确认 → 粘进江湖「录入情报」→ 一键自动整理成 客户/商机/干系人/关系图谱/角色。**不逐项二次确认**；错了事后在现有 UI 改。
> **ASR 外包**：语音转文字由 Typeless（桌面 + 手机端）负责，**江湖侧零录音、零 ASR**，只接收已确认的文字。
> **分支**：`feat/intel-capture`（从 main 切）。
> **状态**：设计已与 LG 对齐（2026-06-05），**双轨合规边界已确认**。

---

## 0. 本质

又一个「数据生产端」，复用 M1 建好的落库契约（Action / MCP 工具）+ 人审边界。LLM 只做「把口语**解析**成结构」，**不做推断**。预计**零 schema 改动**（复用 Account/Opportunity/Person/Edge/OppRole/BurningIssue/PersonSuggestion/RelSuggestion/VisitNote 全部现成表）。

## 2. 双轨合规模型（核心 · 钉死边界）

**法理**：销售**本人口述** = 用户主动录入（等同手动打字建节点），**不属于铁律②的「AI 推断」**。铁律②防的是「机器/外部数据未经核实自动进库」（WorkBuddy/企查查/AI 联想）；销售自己说的第一手情报不在此列。LLM 在此只**解析/结构化**，不**推断/脑补**。

| 轨 | 内容 | 落库 |
|---|---|---|
| 🟢 **explicit（明说）** | 销售明确说出的 客户/商机/干系人/关系/角色/BI | **直接正式库**，带「🎙️ 口述录入·原话」溯源日志 |
| 🔴 **inferred（AI 补充）** | LLM 自己补的、销售没明说的、低置信度、敏感隐私 | **候选层**（PersonSuggestion/RelSuggestion）→ 进「🔮 荐关系」待人审 |

**护栏**（让 explicit 直落站得住）：
- LLM 系统提示**死命约束**：「只整理文本中**明确说出**的人、关系、事实；**绝不补充、推断、脑补**任何未提及内容。」
- 每个抽取项标 `kind: explicit | inferred` + `confidence` + `evidence`(原话片段)；LLM 自标 inferred 的、或 confidence 低于阈值的，一律落候选。
- **敏感个人信息**（家庭/籍贯/配偶子女等 FORM 七问）即便口述，也**仅存摘要或进候选**（PIPL 从严，不直接落 Person.form 敏感字段）。
- 全部可追溯、可在现有 UI 修改（满足「错了再改」）。

## 3. 端到端流程

```
Typeless 口述→转文字→确认  （销售在 Typeless 内完成，江湖不参与）
        │ 粘贴
        ▼
[录入情报] 输入框 + 归属选择(当前商机 / 新客户商机)
        │ 点「录入成图」
        ▼
POST /api/voice/extract  { text, accountId?, opportunityId? }
        │
        ├─ 加载上下文(当前 account + persons，用于实体去重)
        ├─ callLLM 严格抽取 → JSON（explicit/inferred 分类）
        └─ 双轨落库（复用 M1 Action）
        ▼
回执 { account, opportunity, personsCreated[], edgesCreated[],
       rolesSet[], candidates[], visitNote }
        │
        ▼
前端 getState → HYDRATE（关系地图立即出现新节点/连线）
回执 Modal 展示「建了什么 + 几条 AI 补充的待你在荐关系定夺」
```

## 4. LLM 抽取 Schema（实现核心）

复用 `enrich.ts` 已验证手法：让 LLM **只输出 JSON** + 正则 `/\{[\s\S]*\}/` 提取 + `JSON.parse` 容错。抽取结构对齐 M1 契约：

```jsonc
{
  "account": { "name": "中石油", "customerType": 1, "region": "华北",
               "kind": "explicit", "evidence": "今天见了中石油" } | null,
  "opportunity": { "name": "...", "pipelineStage": "方案认可",
                   "competitor": "...", "kind": "explicit" } | null,
  "persons": [
    { "name": "王总", "title": "信息化副总", "orgLevel": 2,
      "suggestedRole": "D", "suggestedSentiment": "plus",   // 复用阶段1.5 propose_person 扩展
      "kind": "explicit", "confidence": 0.9,
      "evidence": "分管信息化的副总，对方案挺认可" }
  ],
  "relationships": [
    { "source": "李处长", "target": "王总", "layer": "L1", "label": "直属下级",
      "kind": "explicit", "evidence": "他下面李处长管采购" },
    { "source": "李处长", "target": "(某竞品)", "layer": "L4", "label": "疑似旧关系",
      "kind": "inferred", "confidence": 0.5, "evidence": "跟竞品有点老关系" }
  ],
  "burningIssues": [ { "person": "王总", "description": "...", "category": "...", "kind": "explicit" } ],
  "rawNote": "整段拜访纪要原文（存 VisitNote.summary）"
}
```

- 必填仅 `rawNote`；其余皆可空（一段话可能只提到客户、或只提到人）。
- `kind` 缺省按 `confidence` 兜底：< 0.6 视为 inferred。
- 枚举值（customerType/pipelineStage/role/sentiment/layer）非法则丢弃或降级候选。

## 5. 落库编排（复用 M1，零新写逻辑）

| 抽取项 | explicit（直落） | inferred（候选） |
|---|---|---|
| 客户 | 按 name 找现有→`UPDATE_ACCOUNT` 补字段；无→`ADD_ACCOUNT` | —（客户是业务实体，不进候选） |
| 商机 | 同上，`ADD/UPDATE_OPP` | — |
| 干系人 | 按 name 在该客户找现有→复用；无→`ADD_PERSON`（正式，带🎙️ log + `placeAt` 坐标） | `PersonSuggestion`（origin='voice'） |
| 关系 | 端点解析到 personId→`ADD_EDGE`（origin='voice'） | `RelSuggestion`（origin='voice'） |
| 角色 | `SET_ROLE`（personId + role/sentiment） | —（依附于候选人物，随采纳落） |
| BI | `ADD_BI` / 幂等 `UPDATE_BI` | — |
| 拜访纪要 | `ADD_VISIT`（summary=rawNote，origin='voice'） | — |

- **实体去重**：明说的同名 Person 在该客户下默认复用（销售知道自己说的是谁，非 AI 推断不必防误合并）；客户/商机按 name 匹配现有，命中关联、未命中新建。
- **后端直接 `applyAction`** 编排（非前端 dispatch），落完返回回执；前端据回执提示 + `getState` 重新 HYDRATE。

## 6. 入口与窗口

**入口**：商机工作台 maintoolbar 第一个（商机名之后），强调态引导点击：
```
[西部风光储]  🎙️ 录入情报   编辑商机  📇 客户档案  …  🧠 AI 推演
   商机名      ↑.btn.cta 浅蓝描边  ╰── 灰 ghost ──╯    实蓝 primary
```
```css
.btn.cta { background: var(--accent-soft); border-color: var(--accent); color: var(--accent-ink); font-weight: 700; }
.btn.cta:hover { background: var(--accent); color: #fff; }
```
（客户 Hub 也放一个，便于从零口述建新客户。暗色走语义变量自动适配。）

**窗口**：复用 `Modal`，两态切换。

**状态 A · 输入**：大 textarea（占位示范一段口述）+ 归属单选（当前商机 / 新客户商机）+ `[取消] [📥 录入成图]`。

**状态 B · 回执**：原地切换，列出「建了什么」（客户/商机/干系人·角色/关系/纪要），并把「AI 补充、拿不准的」单独拎出来标「已放进🔮荐关系待你定夺」；`[看关系地图] [再记一条]`。

## 8. 合规与安全

- **语音原文**：存 `VisitNote.summary`（拜访纪要本是 M1 一等公民）；Typeless 处理音频，江湖不接触原始音频。
- **干系人/敏感信息**：明说基础身份（姓名/职务/层级/角色）直落；敏感隐私进候选（§2 护栏）。
- **LLM key**：BYO 加密代管（复用 AiConfig），用户自己额度，平台零成本。无 key → 提示先配模型（或退化为「仅存纪要、不抽取」）。
- **多租户隔离**：全程 `where { tenantId }`。

## 9. 不碰的红线

tenantId 隔离 · **AI 补充/脑补的人与关系仍走候选人审**（§2 双轨的红轨）· 敏感个人信息从严 · winProbability 不由本功能写 · BYO key 加密不外发 · 跨库可移植（origin='voice' 等用 String）。
