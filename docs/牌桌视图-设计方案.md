# 牌桌视图 · 人物卡片 — 设计方案

> **一句话定位**：关系地图的节点形态 = 拟物人物卡片（牌桌），把角色、支持度、经营状态、**G64111 逐人贡献分**直接印在卡面上，回答「这个人值多少分、还能再挖多少分」。
> **变更（2026-06-10 用户拍板）**：牌桌为关系地图唯一形态，拓扑圆点视图与双形态切换已整体移除（§2 原双形态方案作废）；角色印章正交摆放（去掉拟物旋转）。
> **来源**：用户原型研究（jianghu-power-map.html 纸牌卡片 + 实时诊断）× 江湖既有 G64111 引擎数据优势的融合。
> **铁律**：不推倒现有画布（五轮交互打磨成果保留）；评分权威唯一 = `packages/g64111/`（硬规则⑥）；本期**零 schema 变更**。
> **状态**：设计稿（视觉稿已过目）。

---

## 1. 背景：要解决的呈现缺口

现状（`Canvas.tsx` 圆点节点）只外显：姓名、职位、角色小徽章、支持度小徽章、完成度细条。看不出：

1. **此人对趋赢力值多少分**——D 的支持度牵动 P3 ±20、A 牵动 1K ±20、关键影响人 P4 10 分，这些引擎里算得清清楚楚，但 UI 上不逐人可见；
2. **此人还有多少分可挖**（经营潜力）；
3. **谁在失血**（D/A 倒向友商 = 负 20，目前只是一个小 x 角标）；
4. **机器写的待核实状态**（衔接「机器写初稿 · 人审」范式）。

原型研究证明了「卡片拟物」是承载这些信息的正确形态；江湖的升级 = 原型的形 + G64111 的魂（逐人贡献分是原型自创加权分没有的、且不引入第二套评分体系）。

## 2. 双形态：拓扑 ↔ 牌桌

| | 拓扑（现状） | 牌桌（新增） |
|---|---|---|
| 节点形态 | 圆点 r=NODE_R | 卡片 168×92（world 坐标） |
| 适合任务 | 看全局连线/层级结构 | 看单兵经营状态/分数分布 |
| 切换入口 | 工具栏「⊙ 拓扑 / ▤ 牌桌」segmented（移动端收进 ⋯ 菜单） | 同左 |
| 持久化 | `usePersistentState('jianghu.canvasMode', 'topo')` | 默认拓扑，不惊扰存量用户 |
| 移动端 | 默认拓扑；允许手动切牌桌，切换时自动 `fitAll()` | 卡片在小屏 scale 较小，靠捏合放大局部 |
| 沉浸模式 | 兼容（形态与 immersive 正交） | 同左 |

语义缩放（scale 阈值自动切形态）列为 P2 增强，本期只做手动切换——可预期、零惊吓。

## 3. 人物卡片规格

### 3.1 卡面布局（四层）

```
┌─┬──────────────────────────────┐
│色│ [D]印章 拍板人      [BI已明确]│  ← 顶行：角色印章(旋转-2°) + 角色名 + 右徽章区
│脊│ 孙建国                        │  ← 姓名 15px 加粗
│4 │ 设备部部长                    │  ← 职位 12px 次级
│px│ +30  / 满 34 · 可再 +4        │  ← 贡献行：nominal 大数字 + 潜力注
│  │ ▓▓▓▓▓▓▓░░ (贡献进度微条)      │
│  │ ☆ 核心支持·共识      FORM 5/7 │  ← 底栏：支持度+置信度 | FORM 完成度
└─┴──────────────────────────────┘
```

- **色脊**（左 4px）：取支持度色 `SENTIMENT_COLOR[sentiment]`；无角色/友商 = 中性线色。
- **角色印章**：mono 字体 + 1.5px 边框，正交摆放（不旋转），描边色 = ROLE_COLOR。友商卡无印章。
- **右徽章区**（按优先级最多 2 枚）：`失血`（nominal<0，红）＞`缺口`（A/D 未触达，红）＞`待核实`（机器候选，琥珀斜章）＞`P4 关键影响人 ★`（琥珀）＞`BI 已明确`（绿）。
- **贡献行**：`+30 / 满 34 · 可再 +4`；负值红色 + 失血徽章；多 A/多 D 聚合差异时次注改为「多 D 取低 · 商机实计 X」。
- **底栏**：支持度符号+文案+置信度；右侧 FORM n/7（D 才显示 FORM，非 D 显示完成度 completeness%）。

### 3.2 状态变体（与视觉稿对应）

| 变体 | 触发条件 | 视觉差异 |
|---|---|---|
| 常规 | 有角色有支持度 | 标准四层 |
| 缺口示警 | A/D 且 sentiment ∈ {unknown} 或贡献远低于潜力（nominal ≤ 0 且 upside ≥ 20） | 2px 红边框；桌面端红框呼吸动画（`desktopFx` 守门），移动端静态 |
| 失血 | nominal < 0 | 大数字红色 + 失血徽章 |
| 待核实（候选/机器初稿） | PersonSuggestion 投影 或 Person 带未核实溯源 | 灰虚线边框 + 斜盖「待核实」章 + 贡献行「— 采纳后计分」+ 来源/置信度替换底栏 |
| 友商 | isCompetitor | 沿用深色预设；无印章、无贡献行（友商不计分），只显名称 |
| 无角色路人 | 无 OppRole | 色脊中性、印章区显「未指派」、贡献行 0 / 潜力 +1 |

### 3.3 视觉与主题

- 全部用语义 CSS 变量（`--panel/--ink/--line/--node-*` 体系），新增 `--seal`（印章红）与 `--card-shadow` 时给出 `html[data-theme="dark"]` 覆盖值——**不硬编码颜色**（CLAUDE.md 红线）。
- 原型的水墨/宣纸气质本期只吸收「印章」元素；整体卡面跟随现有亮暗主题。

## 4. G64111 逐人贡献分口径 ★核心

### 4.1 定义

- `nominal(p)`（名义贡献）：按下表把「人维度分项」归因到个人后的合计，可为负。
- `potential(p)`（满配潜力）：此人全部适用分项满分之和。
- `upside(p) = potential(p) − nominal(p)`（可再挖）。
- 商机级分项（C3/C4/C5 共 15 分 + C1 的角色齐备 0..7 分）**不归人、不上卡**——归因噪声大，强行摊派会误导。

### 4.2 归因规则表（严格对齐 `g64111.ts` 实现）

| 分项 | 满分 | 归到谁 | 个人名义分 | 与商机实计的差异（须在卡面小注） |
|---|---|---|---|---|
| P3 与D密谋 | ±20 | 每个 D | `P3_1K_MAP[sentiment]` | 多 D 实计 `aggregateLow(全部D)`（取低中位）；差异时注「多D取低 · 商机实计 X」 |
| 1K 与A | ±20 | 每个 A | 同上 | 多 A 同上 |
| P4 关键影响人 | 0..10 | 引擎 `roles.find(isKeyInfluencer)` **第一个** | `P4_MAP[sentiment]` | 多人标记时仅第一个计分，其余注「P4 已由他人占用」（见 §8 开放问题） |
| P1 多数人支持 | −5..+5 | confidence ≥ 明确 且 sentiment ∈ {☆,+,−,x} 者 | ☆/+ → +1；−/x → −1 | 总和被 clamp ±5；饱和时个人仍显名义 ±1 |
| P2 招采关键人 | −5..+10 | 有 procurementType 者 | collude → 权重(purchasing 4 / agency 2 / ownerRep 4)；verbal → +1；其余 0 | 全 none 的整体 −5 是商机级失血不归人；同 type 多人引擎后者覆盖前者，按引擎实情 |
| C1-FORM | 0..3 | **主 D**（dRoles[0]） | strict 曲线 `max(0, 3-(7-family7Filled))` | 多 D 时其余 D 不计 FORM 分（但 FORM n/7 仍显示） |
| C2 拍板人BI | 0/5 | 持有 confidence ≥ 明确 BI 的 D | 5 | 多 D 多 BI 合计仍 5，归第一持有者 |
| C6 UCV | 0/3/5 | 目标 BI 的持有 D | 状态分（已解决5/获认可3） | 同上 |

潜力速查：D=34（P3 20+FORM 3+C2 5+C6 5+P1 1）；A=21；关键影响人=11；招采 purchasing/ownerRep=5、agency=3；普通确认角色=1。身兼多职叠加（D+KI = 44）。

### 4.3 实现约束

- 纯函数 `personContributions(account, opp): Map<personId, { nominal, potential, upside, parts: {item: ItemKey, value: number, note?: string}[] }>` 由 `packages/g64111/` 导出，App adapter 直接 re-export。
- **复用** `P3_1K_MAP / P4_MAP / isConfirmed / aggregateLow` 等既有常量与函数，**绝不另造第二套算法**；`scoreOpportunity` 与既有 17 个单测一行不改。
- 新增单测覆盖：单 D / 多 D 取低 / 失血负分 / P1 clamp / 身兼多职叠加 / KI 多标记只计第一 / 待核实不计分，≥ 8 例。
- 改动前重读 `docs/G64111-评分规格.md`；收尾跑共享包、App 与 Server parity 的类型检查和单测。

## 5. 画布实现要点

1. **纯 SVG 画卡**（rect + text + 微元素），不用 `foreignObject`——规避 iOS Safari 渲染雷区（项目已有 iOS 平移残影前科，勿再引入合成层变量）。
2. **交互零破坏**：卡片整体仍包在 `<g data-node={id} transform=translate(...)>` 内——拖拽/单击选中/双击详情/`secondTapOpens`/框选/内联命名的命中逻辑（`closest('[data-node]')`）完全不变；锚点改挂卡片四边中点（`DIR_VEC × 半宽/半高`）。
3. **连线几何**：`edgeGeom` 的端点收缩当前按圆 `NODE_R`；牌桌形态按矩形边框点裁剪（borderPt：中心连线与矩形边的交点，原型 power-map 已有参考实现）。形态作为参数传入，拓扑路径保持原样。
4. **文本截断**：SVG text 无 ellipsis——姓名 > 6 字截断加 `…`；职位 > 10 字同理。
5. **性能**：贡献分 `useMemo`（依赖 persons/roles/bis/ucvs），整图一次 O(n)；50 节点 × ~14 SVG 元素可接受；缺口呼吸等**常驻动画仅桌面**（`desktopFx`，动效铁律），进入动画复用现有 `node-pop`。
6. **候选投影**：牌桌模式下 PersonSuggestion（pending）以「待核实卡」灰虚线形态出现在画布空位（现状候选只有灰虚线连线❓）——这是「审核收件箱」在画布上的化身，点击卡片 = 打开采纳/驳回（复用 SuggestionPanel 的 accept/reject 接口）。

## 6. 本期边界（明确不做）

- **不动 schema**：覆盖度（我方经营深度）/ 接触线数 / 关系归属人 / 他的赢点 四个新维度，随「统一变更提案层」批次进 schema（V2），卡片底栏已为其预留位。
- **不改评分引擎**与既有 17 单测。
- **不做语义缩放**（scale 阈值自动切换，P2）。
- **不做原型的自创覆盖度加权分**——分数只有 G64111 一套。
