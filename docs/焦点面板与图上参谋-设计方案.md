# 交互升级 · 右栏「焦点面板」与「图上参谋」设计方案

> **定位**：把右侧「详情抽屉」升级为跟选中对象走的「焦点面板」，并把 AI 与关系图打通为「图上参谋」。是 [交互模式升级-设计方案.md](交互模式升级-设计方案.md)（v0.2 三位一体）里「地图主战场」右栏 + 「AI 后台/推演」前台入口的具体化。
> **状态**：设计探讨成型（2026-07-01，方案 A 已拍板），**原型已出、未动代码**。本文＝动手前的图纸。
> **配套原型**（docs/，纯静态可点）：`焦点面板-精简三tab.html`（最终）、`图上参谋-原型.html`、`添加情报-单入口原型.html`。

---

## 0. 一句话

右栏不再是「双击才弹出的详情抽屉」，而是**始终跟着你选中的那个人/那条关系走的工作台**：顶部身份头 + 三个 tab（📇 档案 · 📝 动态 · 🧭 参谋）＝「他是谁 / 他经历了什么 / 怎么打他」。其中「参谋」把 AI 接上整张图，让你对着图产生思考后，给 AI 具体而有深度的命令。

---

## 1. 背景 · 三个现状痛点（改动前锚点）

当前 `wall` 布局（App.tsx）：左栏 `Sidebar`(趋赢力诊断台 + `ChatPanel` 对话框) + 中 `Canvas` + 底 `DeliberationDock`(推演坞) + 右侧 `DetailDrawer`(详情抽屉)。

| 痛点 | 现状 |
|---|---|
| **详情与 AI 抢右侧** | 双击节点开 `DetailDrawer`（`.drawer` `position:absolute;right:0;width:372px`）；若右栏再放 AI 参谋，两者位置尺寸几乎重合、互抢。 |
| **AI 与图脱节** | 画布选中 `selectedId` 只驱动高亮 / 坞聚焦（`selectPerson`），**从没喂给 AI**。`aiContext.ts:buildAiContext` 已打包整图上下文，但只有推演坞的顺推/倒推（`DeliberationDock:runSuggest`）在用，且产出锁死为策略卡/里程碑。`ChatPanel`（和地图对话）只调 `voiceExtract` 双轨、几乎不带图上下文。 |
| **信息入口散落** | 拜访 log 埋在 `DetailDrawer` 底部；情报录入 / 录音 / 自算补全散在 Hub 顶栏与侧栏。 |

**单击 / 双击现有语义**（App.tsx:71 注释）：单击＝选中(出锚点)+坞聚焦；双击＝开右侧详情。**本方案完全复用，不改肌肉记忆。**

## 2. 焦点面板（右栏重构）

### 2.1 结构：身份头 + 三 tab

```
┌─ 右栏 = 焦点面板（宽 ~390px，替代 .drawer）──────┐
│ 身份头：头像 · 姓名 · 职务                        │
│         [角色印章] [态度] [趋赢力±] [FORM n/7]     │  ← 三 tab 共享
├──────────────────────────────────────────────────┤
│  📇 档案   |  📝 动态   |  🧭 参谋                  │  ← tab 条
├──────────────────────────────────────────────────┤
│  （选中 tab 的内容）                                │
└──────────────────────────────────────────────────┘
```

### 2.2 单击 / 双击 → tab 映射（复用现有语义）

| 操作 | 行为 |
|---|---|
| **单击**节点 | 选中 + 画布锚点/坞聚焦（照旧）+ 右栏聚焦他、落 **🧭 参谋** tab |
| **双击**节点 | 选中 + 右栏聚焦他、跳 **📇 档案** tab（＝原「双击开详情」） |
| 手动点 tab | 在三面间切，身份头不变，各 tab 状态保留（改档案不清参谋对话） |
| **不选**（空白） | 右栏＝**全局参谋**，档案/动态 tab 灰置 |
| 选中**关系**（边） | 身份头换成「关系头」，tab 退化为 档案(边字段=EdgeDrawer) + 参谋（问这条关系） |

### 2.3 各 tab 内容与数据来源（复用现有，尽量零新表）

| tab | 内容 | 数据来源（现有） |
|---|---|---|
| 📇 **档案** | 角色(A/D/U/R/C)、态度、置信、FORM 七问、燃点 BI、UCV、字段编辑 | `DetailDrawer` 原样搬入（`Person`/`OppRole`/`BurningIssue`/`UCV`；Action：`UPDATE_PERSON`/`SET_ROLE`/`ADD_BI`…） |
| 📝 **动态** | 时间线：拜访 log + 录音抽取 + 态度变更 + 采纳记录，**每条带溯源** | `Person.logs`(`ADD_LOG`)、`VisitNote`、`Transcript`(录音)、候选采纳事件；聚合按 `personId` + 时间倒序 |
| 🧭 **参谋** | 对着他的对话 / 分析 / 可落地候选（见 §3） | `buildAiContext` + `selectedId` + 会话历史 → 用户自己的模型 |

> 「动态」是把原本埋在档案底部的拜访记录**拆出来独立成面**，并汇入录音抽取、态度变更、候选采纳，形成「他经历了什么」的溯源时间线。

### 2.4 收编关系（一个面板归拢多处）

- 详情抽屉 `DetailDrawer` → **档案 tab**
- 拜访 log / 情报流 → **动态 tab**
- AI 推演（`DeliberationDock:runSuggest`）+ 和地图对话（`ChatPanel`）→ **参谋 tab**（见 §3.4）

### 2.5 取舍原则（防 tab 爆炸）

一个切面够格进右栏，须同时满足：①**锚定焦点对象**（关于「这个人/这条关系」，非全局）；②**独立成面**（信息量/交互撑得起、不与现有 tab 重叠）。

- **精简三 tab 常驻**：档案 / 动态 / 参谋（已定）。
- 关系人脉 / 按人待办候选 / 挂他的策略卡 / 跟进日程等：**归参谋当总入口去调起**（"看他连了谁""他有哪些待审候选"），不每样单开 tab。全局的收件箱、企微日历总览、团队设置 → 属 Hub/顶栏，**不进右栏**。

### 2.6 无焦点 / 移动端

- 无焦点 = 全局参谋（可问全局、顺推倒推）。
- 移动端：右栏改为**底部上拉面板**或全屏切换（沿用 `.drawer` 移动端 `width:100%` 的既有降级），三 tab 保留。

## 3. 图上参谋（参谋 tab 的交互逻辑）

### 3.1 交互循环

```
看图 → ①选焦点(点人/关系/不选=全局) → ②下指令(自由文本+焦点快捷指令)
   → ③AI 深思(全图上下文+焦点+会话历史) → ④产出(分析+可落地候选)
   → ⑤采纳闸门(候选→人审→落库;分析不改图) → 回到①对着图继续追问(多轮,焦点可切)
```

三处补现状缺口：**焦点感知**（`selectedId` 接进 AI）、**深度而非固定**（不锁策略卡/里程碑）、**多轮深挖**（会话有记忆）。

### 3.2 上下文组装

`ctx = buildAiContext(account, opp, breakdown)` ＋ `focus = { kind:'person'|'edge'|null, id }` ＋ `history`（本轮会话）。`buildAiContext` 现有字段：account / opportunity / winTendency(percent·band·逐项 items) / people(角色·态度·置信·关键影响者) / relationships(≤40) / bis。**新增**：把 `focus` 明确标给模型（"用户此刻盯着王副总"）。

### 3.3 产出与落库闸门（守铁律②）

AI 回**结构化分析**（不锁格式），其中「可落地项」抽成**候选卡**，采纳才落库、绝不自动改图：

| 候选类型 | 落库通道（复用现有） |
|---|---|
| 新关系 / 新人物 | `RelSuggestion` / `PersonSuggestion` → 收件箱人审 |
| 策略卡 | `ADD_STRATEGY_CARD`（origin='ai'，＝顺推采纳路径） |
| 里程碑 | `ADD_MILESTONE`（倒推采纳路径） |
| 行动 | `planAction`（挂 personId，勾完成→结果回填录证据飞轮） |
| 态度/角色变更 | `SET_ROLE` 等——**明说的执行指令**可延续 `voiceExtract` 明说轨**直落**；AI 推断的进候选 |

### 3.4 收编三挡

| 现有 | 新角色 |
|---|---|
| 和地图对话（`ChatPanel`，改图直落） | 参谋的**「执行」挡**：明说指令直落 |
| AI 顺推/倒推（`runSuggest`） | 参谋的**「快捷指令」**：无焦点时的两个 prompt 模板，产出照进策略/里程碑泳道 |
| —（新核心） | **焦点 × 自由深度指令 × 多轮** |

## 4. 添加情报（配套 · 入口收敛）

另一条线，独立可先落：把**人工喂料**收敛成一个「＋ 添加情报」单入口 = 口述录入 / 录音转写 / 和地图对话三种（都是「我手上有条具体线索，喂进去」）。「🔍 自算补全」是 **AI 后台主动挖**、非「添加」动作 → 移到收件箱线（产物进收件箱人审）。删过时的独立「🧠 AI 推演」入口（已并入参谋）。详见 `添加情报-单入口原型.html`。

## 5. 落地要点

### 5.1 涉及文件（预估）

- `App.tsx`：`selectedId`/`selectedEdgeId` 接入参谋上下文；`drawerPersonId`/`drawerEdgeId` 与 tab 状态统一；右栏容器由「抽屉」改「常驻焦点面板」；单击落参谋、双击落档案。
- 新组件 `FocusPanel.tsx`（身份头 + tab 容器）；`DetailDrawer.tsx` 内容迁入档案 tab；新 `DynamicTab`（动态时间线聚合）；`ChatPanel.tsx` 升级为参谋（吃 `buildAiContext`+焦点+多轮）。
- `EdgeDrawer.tsx` → 关系焦点态。
- `aiContext.ts`：`buildAiContext` 增加 `focus` 字段。
- `DeliberationDock.tsx`：顺推/倒推降级为参谋快捷指令的产出路径（泳道候选不变）。
- 后端 `ai.ts`/`suggest.ts`：参谋深度问答端点（带 focus + history），产出候选走既有 `RelSuggestion`/策略卡/planAction。

### 5.2 分期建议

1. **P1 焦点面板（纯前端重排，近零 schema）**：右栏三 tab 容器 + 档案迁入 + 动态时间线（聚合现有 log/VisitNote/Transcript）+ 单双击映射。风险最低、收益最高，先做。
2. **P2 参谋接图**：`buildAiContext`+`selectedId`+会话历史 → 深度问答；候选落既有通道；收编顺推/倒推为快捷指令。
3. **P3 添加情报单入口**（独立，可与 P1 并行）。

### 5.3 数据契约

尽量零新表：档案/动态复用 `Person`/`OppRole`/`BI`/`UCV`/`VisitNote`/`Transcript`/`logs`；参谋候选复用 `RelSuggestion`/`PersonSuggestion`/`StrategyCard`/`Milestone`/`planAction`。参谋会话历史可先前端内存态（不落库），或后续加轻量表。

## 6. 不碰的红线

- **铁律②**：参谋的分析/推断产出**一律候选**，人审采纳才落库；分析**绝不自动改图**。明说的纯执行指令走 `voiceExtract` 明说轨直落。
- **多租户隔离**：全程 `where { tenantId }`。
- **BYO Key**：参谋用用户自己的模型 Key（AES-256-GCM 代管），无 Key 降级（存纪要/演示）。
- **跨库可移植**：不新增原生 enum/json；新增来源用 String。
- **PIPL**：动态时间线含敏感项（FORM 七问等）按现有护栏，敏感进候选/仅摘要。

## 7. 待决项

- 参谋放**右侧**（本方案 A，已定）曾对比「放底部并进推演坞」——被「对话纵向 vs 底栏浅」+ 抢坞空间否掉；除非做成坞的「指令入口·产出落泳道」形态（弱化多轮，另议）。
- 动态 / 关系 / 待办候选是否再加 tab（当前精简三 tab；其余归参谋总入口）。
- 参谋会话历史是否落库、多轮上下文窗口大小。
- 关系焦点（选边）态的完整字段与参谋话术。
- 移动端右栏形态（底部上拉 vs 全屏切换）。
