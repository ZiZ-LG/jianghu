# 交互升级 · 主线闭环与焦点面板设计方案

> **定位**：把「关系图 + 右栏详情 + 底部推演」三块，收敛成一条**销售作战主线闭环**——情报沉淀 → 推导出牌 → 落画布执行 → 反馈回流。是 [交互模式升级-设计方案.md](交互模式升级-设计方案.md)（v0.2 三位一体）的落地总纲。
> **状态**：主线 2026-07-01 拍板（A/B①/C 确认）。**P1 焦点面板 + P2 全套（牌六要素 / 牌落画布 / 点牌反馈 / 参谋接图 P2④a / 参谋出牌 P2④b）+ 添加情报单入口 均已实现并 push**（`762a66a`→`8823b4f`）。**已知缺口**：参谋出牌目前只产「行动牌」1 种候选，原型设计的 策略卡 / 风险登记 / 进收件箱核实关系·角色 三类未做；「不选人→全局参谋」态未做（分流到推演坞顺推/倒推）。P3 道具×WB 待做。详见 `jianghu-design-code-gaps` 审计基线。
> **配套原型**（docs/，可点）：`焦点面板-精简三tab.html`、`图上参谋-原型.html`、`添加情报-单入口原型.html`。

---

## 0. 一句话

销售的一天是一条闭环：在**右栏**把一个个人/关系的情报沉淀下来（点），在**策略屋**结合目标把情报推导成一张张**行动牌**（线），把牌**摆到画布战场上挂给责任人**执行（面），执行完**点牌反馈**、现状随之更新，再回策略屋重推。三区各司其职，一根主线串起来。

---

## 1. 主线闭环（总纲）

### 1.1 三区角色

| 区 | 角色 | 维度 | 干什么 |
|---|---|---|---|
| 右栏 · 焦点面板 | **情报** | 点 | 这个人/关系是谁：档案 · 动态 · 参谋 |
| 底部 · 策略屋（坞） | **推导** | 线 | 结合已知＋销售目标，现状锚→策略→里程碑，**出厂行动牌** |
| 中央 · 画布 | **战场 + 行动令** | 面 | 关系地形 ＋ 挂责任人节点旁的行动牌 ＋ 执行反馈 |

### 1.2 闭环流转

```
右栏(情报·点)  ──喂──▶  策略屋(推导·线)  ──出厂──▶  「一张完整的牌」
                                                        │ 确认
                                                        ▼
现状更新·再推导  ◀──回流──  点牌反馈(完成/效果/证据)  ◀──执行──  牌落画布·挂责任人(待办)
```

### 1.3 现有雏形 vs 待建（离落地多远）

| 环节 | 现在 | 距离 |
|---|---|---|
| 策略屋推导链（策略→里程碑→行动） | ✅ `DeliberationDock` 三泳道 + 策略卡「→ 派发」生成行动 | 方向一致 |
| 右栏焦点面板（情报·点） | ✅ **P1 已实现**（三 tab：档案/动态/参谋） | 见 §2.1 |
| 「牌」六要素 | ⚠️ `planAction` 仅 标题/时间/责任人/缺口 | **缺 目的/资源/注意/道具**（§3） |
| 牌落画布·挂节点 | ❌ 行动现在只在坞行动泳道 | **全新交互**（§2.3、B①） |
| 点牌反馈闭环 | 🟡 勾完成→录证据→局势飞轮（在坞里） | 从坞搬到画布（§5） |
| 道具 → WorkBuddy | 🟡 集成已探明（[[jianghu-workbuddy-probe]]） | prompt 生成 + 带入 WB（§6） |

## 2. 三区角色详解

### 2.1 右栏焦点面板 · 情报（点）—— P1 已实现

跟选中对象走的工作台：身份头（头像/姓名/职务 + 角色/态度/趋赢力/FORM）＋ 三 tab。

| tab | 内容 | 数据来源 |
|---|---|---|
| 📇 档案 | 角色/态度/FORM 七问/燃点 BI/UCV/字段编辑 | `DetailDrawer`(embedded) 搬入 |
| 📝 动态 | 时间线：`person.logs` + 该人参与的 `VisitNote`，带溯源、倒序 | 聚合，按 personId/name |
| 🧭 参谋 | 对着他的对话/分析/候选（P2，§4） | `ChatPanel` → 升级 |

**单击→参谋 tab（选中即现）、双击→档案 tab、点空白→消失**；`selectedId` 统一驱动 画布高亮 / 坞聚焦 / 右栏面板。已随 P1 落地，真机验证通过。

### 2.2 策略屋 · 推导（线）

现有 `DeliberationDock`：局势栏(`EngineBar`) + 策略泳道(正推·现状锚→策略卡→AI 顺推) + 里程碑泳道(倒推·终局锚→里程碑→AI 倒推) + 行动清单泳道 + 信号汇总。

**升级**：
- **专注推导**：策略屋只留「现状锚 → 策略 → 里程碑」，出厂是**行动牌**。
- **行动泳道退役 / 降为总览**：行动的主场搬到画布（§2.3）；坞因此**收窄**，缓解空间夹击。
- **出牌口**：策略卡「→ 派发」不再落坞行动泳道，而是**生成一张行动牌、摆上画布挂责任人**（沿用 `dispatchToPlanner` 的派发动作，落点改画布）。

### 2.3 画布 · 战场 + 行动令（面）· B①

现有 `Canvas`：关系图（`data-node` 节点 + pointer 交互 + 层级 L1-L4）。

**升级**：
- **牌挂责任人节点旁**（B①）：一张行动牌视觉上挂在它责任人节点侧边，像"发给这个人的行动令"，和关系地形天然咬合。
- **画布 = 战场（关系）+ 行动令（牌）**：关系图告诉你战场地形，牌告诉你这一手打谁、怎么打、带什么。
- **点牌 → 牌详情 + 反馈**（§5）；节点旁「＋ 挂牌」可手动补。

## 3. 「牌」= 行动计划（核心产物）

### 3.1 六要素

一张牌 ＝ 策略屋的**出厂产物 = 升级版行动**（坞的策略卡/里程碑是产出牌的推导上游，不是每个都变牌）：

| 要素 | 说明 | 现状 |
|---|---|---|
| 目的 | 这一手要达成什么（对齐哪个缺口/局势） | 🆕 |
| 完成时间 | 截止 | ✅ `planAction.startDate/endDate` |
| 责任人 | 挂谁（决定落画布哪个节点旁） | ✅ `planAction.personId` |
| 所需资源 | 人/预算/内部支持等 | 🆕 |
| 注意要点 | 风险/红线/话术提示 | 🆕 |
| 道具 | 方案/POC/报告/会议大纲…（§6 由 WB 产） | 🆕 |

### 3.2 生命周期

`策略屋推导出牌` → `确认` → `落画布·挂责任人·待办` → `执行` → `点牌反馈` → `现状更新` → `再推导`。

### 3.3 vs 现有 `planAction`

牌是 `planAction` 的**扩展**：现有 4 字段（标题/时间/责任人/缺口）补上 目的/资源/注意/道具。跨库可移植：新增字段用 String/文本，不引原生 enum/json。

## 4. 图上参谋（P2 · 右栏人焦点的推导触发口）

参谋 ＝ 右栏对着某人的**策略对话入口**，问出的策略/行动 → **汇入策略屋 → 出牌 → 落画布**。与坞的顺推/倒推（全局触发口）**并流、都产牌**——解「策略两个产出口」（§7）。

### 4.1 交互循环
```
①选焦点(点人/关系/不选=全局) → ②下指令(自由文本+焦点快捷指令)
 → ③AI 深思(全图上下文+焦点+会话历史) → ④产出(分析 + 可落地候选)
 → ⑤采纳闸门(候选→人审→落库;分析不改图) → 多轮追问、焦点可切
```
三处补缺口：**焦点感知**（`selectedId` 接进 AI）、**深度而非固定**、**多轮**。

### 4.2 上下文组装
`ctx = buildAiContext(account, opp, breakdown)` ＋ `focus{kind,id}` ＋ `history`。`buildAiContext` 已打包 account/opportunity/winTendency(逐项)/people(角色态度置信)/relationships/bis；**新增** `focus`（"用户此刻盯着谁"）。

### 4.3 产出与落库闸门（守铁律②）
AI 回结构化分析，可落地项抽成候选，**采纳才落、分析不改图**：

| 候选 | 落库通道 |
|---|---|
| 新关系/人物 | `RelSuggestion`/`PersonSuggestion` → 收件箱 |
| 策略 | `ADD_STRATEGY_CARD`（＝顺推路径） |
| 里程碑 | `ADD_MILESTONE`（＝倒推路径） |
| **行动牌** | `planAction`（扩六要素）→ 落画布挂责任人 |
| 态度/角色 | 明说直落 `voiceExtract` 明说轨；推断进候选 |

### 4.4 收编三挡
和地图对话（`ChatPanel`，改图直落）＝「执行」挡；AI 顺推/倒推（`runSuggest`）＝全局「快捷指令」；新核心 ＝ 焦点 × 自由深度指令 × 多轮。

---

## 5. 反馈闭环（录证据飞轮搬画布）

点画布上的牌 → 反馈（完成 / 效果好坏 / 留证据）→ 喂 `G64111`·态度 → 局势重算 → 策略屋「现状锚」随之更新 → 再推导。

＝ 把现有「勾完成→`newEvidence`→局势飞轮」（现在在坞行动泳道）**搬到画布点牌操作**，闭合"执行→证据→局势→再推"。

## 6. 道具 × WorkBuddy 生产线

牌里的「道具」不是静态附件，是一条生产线：

```
江湖出 prompt(带全 context) → 销售带进 WorkBuddy
   → WB＝jianghu MCP 全上下文(客户/商机/干系人) + 产品方案 + 案例库
   → 产出道具(方案 / POC 环境 / 文字报告 / 会议大纲…)
```

江湖管"作战图谱"，WB 管"内容生产"，在**道具**这点咬合。集成路径见 [[jianghu-workbuddy-probe]]（jianghu MCP server + flow 插调用）。**待设计**：prompt 模板（吃牌的目的/责任人/道具类型 + `buildAiContext`）、带入 WB 的方式（复制 vs 调用）、产物回挂牌。

---

## 7. 三张力如何被主线化解

| 张力 | 主线化解 |
|---|---|
| ① 点坞卡「双详情」 | 对象分层：点**人节点**→右栏看人 / 点**节点旁牌**→牌详情+反馈 / 点**坞推导卡**→编辑推导。三类对象三种详情，不再混 |
| ② 策略两个产出口 | 一切推导汇成「牌」一个出厂产物；参谋（右栏）产出也汇入策略屋 → 一个出口 |
| ③ 空间三面夹击 | 行动搬画布、坞行动泳道退役收窄 → 空间重新分配，不再三面挤 |

## 10. 不碰的红线

- **铁律②**：参谋/AI 的分析·推断产出**一律候选**，采纳才落、绝不自动改图；明说执行指令走 `voiceExtract` 明说轨直落。
- **多租户隔离**：全程 `where { tenantId }`。
- **BYO Key**：参谋/道具 prompt 用用户自己的模型，无 Key 降级。
- **跨库可移植**：不新增原生 enum/json；牌新增字段/来源用 String。
- **PIPL**：动态时间线 + 道具 prompt 含敏感项按现有护栏；发 WB 的 context 走字段白名单（**绝不发 FORM/态度/弱点**，对齐企微日历同款约束）。

## 11. 待决项

- 牌落画布的视觉密度（一人多牌怎么叠 / 只显当前活跃牌 / 缩略与展开）。
- 策略屋「行动泳道退役 vs 降为总览」二选一（总览便于跨人看全部待办）。
- 参谋会话历史是否落库、多轮窗口大小。
- 道具生产：prompt 带入 WB 是「复制粘贴」还是「江湖调 WB」；产物如何回挂牌。
- 关系焦点（选边）态的字段与话术；移动端右栏/画布牌形态。
