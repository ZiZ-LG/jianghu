# 架构纲领 · 江湖自算主线 + 可插拔计算引擎(v1)

> **定位**:这是 v2 阶段的**主线纲领**,统辖数据模型与交互。它**取代**「集成-端到端最小链实施方案v1」作为方向权威——从"WorkBuddy 主导、双系统"转为"**江湖自己算、单系统;外部 Agent 可插拔**"。
> **已做工作的处置**:M-A/B/C 里**江湖侧**(MCP 工具 / 提案层 / 收件箱 / externalRef / human-wins / SSE)**全部复用**;**WorkBuddy 侧** flow 改造在本主线下大幅收窄(见 §3、§8),不作废但退居"道具"通道。
> **状态**:设计稿(2026-06-25,基于多轮拍板)。

---

## 0. 一句话 + 决策快照

**一句话**:用户**只在江湖里操作**;江湖**后端自己算**(企查查/LLM/策略/评分);**DB 是唯一真相**,`.md` 是它的**单向导出**;WorkBuddy 退成按 **spec 生产道具(PPT/Word/原型)** 的可插拔外部 Agent。

| 项 | 定的 |
|---|---|
| 形态 | 江湖前端 + 后端(主计算)= 完整产品;外部 Agent = 可插拔挂件 |
| 计算 | **江湖自己算**(复用现有 enrich/voice/suggest/ai/strategy/pde/g64111) |
| 录音 | 江湖后端接 得到大脑(MCP)/ 飞书妙记 · 钉钉听记(OpenAPI),BYO 凭据,拉**转写文字**(不自建 ASR) |
| 数据真相 | **DB 唯一可写源(SoR)**;`.md` = DB 的**只读单向导出**;不做 .md→DB 回写 |
| DB 构成 | **结构化层(算分/筛选/画图)+ 自由文本层(零散/长尾)** |
| 信息分层 | **原始(保真不可变)/ 结构化(AI 提炼·提案人审)/ 梳理(AI 整理·标待核·不覆盖原始)** |
| 道具生产 | **「导出道具文档」按钮**:江湖出 spec(.md)下载本地,用户带去**任意 Agent 平台**生成 PPT/Word/Excel/PRD/原型;平台无关、前端弱化 |
| 交互 | **极简:不新增对话框、操作集中、尽量一屏完成、语音驱动、就地确认** |
| 大模型 | **平台统一配置(代付 token、用户免配 key)**;国产模型 ¥数元/销售/月,**需用量配额管控**;服务器基本不增 |

## 1. 总架构:三层 + 可插拔计算引擎

```
┌─────────────────────────────────────────────┐
│ ① 江湖前端  地图主战场 / 左栏诊断台·对话 / 推演坞 / 收件箱   │  显示·交互·人审
├─────────────────────────────────────────────┤
│ ② 江湖后端  SoR(DB) + 自算引擎 + 人审通道(提案层) + MCP 契约 │  ★ 主计算层
├─────────────────────────────────────────────┤
│ ③ 外部 Agent(可选)  WorkBuddy / Claude Desktop / …          │  道具生产·额外算力
│     经 MCP 契约接入,产物一律走 ② 的提案层 → 人审            │
└─────────────────────────────────────────────┘
```

**解耦的边界 = MCP 契约 + 提案层(这条最关键)**:
无论计算源是江湖自己、还是外部 Agent,**产物都走同一条「提案 → 收件箱人审 → 落库」通道**。这样计算源可换(自算 / WorkBuddy / 未来任何 MCP Agent),前台与人审逻辑一行不改。**江湖自算的机器产物也走提案层,不走"直接写库"**——内外一致,才叫真解耦。

## 2. 计算层:江湖自己算

### 2.1 已有家底(不是从零)
后端约 1300 行已具备:`qccMcp.ts`+`enrich.ts`(企查查建图)、`voice.ts`(文字→结构化抽取·双轨)、`suggest.ts`(关系推断)、`ai.ts`+`strategy.ts`(LLM 推演/策略,AES 加密 BYO key);前端 `g64111`(评分)+`pde/`(策略引擎)。`ai.ts`/`qccMcp.ts` 已在调外部 LLM/企查查。**"自算"≈ 把这些串成自动化编排 + 加后台 job 队列。**

### 2.2 录音接入选型(三源不同接法)
- **得到大脑**:有 MCP → 江湖后端当 MCP client 调,**复用 `qccMcp.ts` 模式**(最顺)。
- **飞书妙记 / 钉钉听记**:优先走**开放平台 OpenAPI(HTTP)**,**不要在云端跑 lark-cli / dws CLI**(CLI 为本地 Agent 设计,服务端跑重)。
- 共性:**BYO 凭据 + OAuth 授权**(销售授权江湖代拉其录音);江湖只拉**转写文字**,**不自建 ASR**(三源自带语音转写)。
- 待实测:三家 API 的开放度/配额/稳定性(得到大脑已验,飞书钉钉待验)。

### 2.3 PIPL 配套(真风险,必须做)
录音转写含客户隐私,从"WorkBuddy 本地处理"变为"**江湖云端处理**",暴露面变大。配套:转写内容加密存、严格 tenantId 隔离、最小留存(原文用完可降解/可删)、必要时脱敏。**这是红线级要求,不是普通字段。**

## 3. 道具生产:导出「道具文档」,平台无关

- 江湖**不**生产 PPT/Word(它不是通用 coding agent);它只输出一份**道具文档(spec,.md)**。
- 流程:行动计划/任务上有一个低调的 **「导出道具文档」按钮** → 点击 → 江湖据该任务生成一份 spec(.md,含道具要求 + **自带必要数据**)→ **下载到用户本地** → 用户带着这份 .md **去任意 Agent 平台**(WorkBuddy / Claude Desktop / 其他)生成 PPT/Word/Excel/PRD/原型。
- **平台无关、前端弱化**:不绑定、也不特别展示任何外部系统,前端就一个"导出道具文档"按钮。
- **spec 自包含数据**(下载即用,带去任何平台都能跑);若该 Agent 恰好也接了江湖 MCP,可选让它回拉最新数据(非必须)。
- 含义:外部 Agent 从"集成挂件"退成"**用户自带的下游工具**"——江湖产权威 spec,用谁生产道具由用户自选。

## 4. 数据模型(本主线的核心)

### 4.1 DB 单源 + MD 单向导出(否决双向同步)
- **DB = 唯一可写真相源**;**改只在江湖 GUI**(作战档案字段内联编辑,失焦写 DB = 既有"路A")。
- **`.md` = DB 的只读导出快照**:随时从 DB 渲染最新一份,供人下载/Obsidian/喂 WorkBuddy。**不回写**。
- **明确不做 `.md`→DB 回写**:双向同步在"多人 + AI 后台 + 两边改"下必然产生 merge 冲突,"打开/关闭时机+勾选"解决不了;且 .md 文本解析回写已在"路B/`mdParse`"试过并废弃。**单向 = 简单且自洽。**

### 4.2 DB = 结构化层 + 自由文本层
DB 不只是结构化字段;它**两层都装**:
- **结构化层**(算分/筛选/画图):角色/支持度/必清项/阶段/金额/关系…
- **自由文本层**(零散/长尾):已有 `Person.logs`、`VisitNote.summary`、`Account.profile`、`Person.form`、`Opportunity.meta`;**补一张通用 `Note` 流表**接住无归属长尾。
- **Note 方案 = "流的里子 + 内联的面子"(已定)**:
  - **数据层** = 独立 `Note` 流表(`挂载对象可空` + 内容 + 来源 + tag + 时间)→ 随手记不卡(可先不挂对象),且天生支持将来做"情报流"全局视图。
  - **呈现层** = 实体内联(打开客户/商机/人的作战档案 → 只显示挂在它上的 note)+ 一个轻量"未归类"收集口 → **不新增独立页面**,符合极简约束。
- **结构化/非结构化边界可移动**:长尾先自由记,反复出现且有价值的逐步升级为结构化字段。

### 4.3 三层信息(零散信息的处理铁律)
| 层 | 是什么 | 规则 |
|---|---|---|
| **原始 raw** | 销售原话 / 录音转写 / 随手 note | **保真、不可变、带溯源**(谁/何时/来源) |
| **结构化 structured** | AI 从原始提炼的字段 | 走**提案 → 人审**才落库(铁律②) |
| **梳理 curated** | AI 按模板把非结构化整理成有条理叙述 | 标"**AI 整理·待核**",**不覆盖原始**,可下钻回原始,人可改 |

**红线:AI 的"梳理"是加一层,绝不改写/覆盖原始**(否则丢"大概/好像"、脑补 → 污染真相、无法追溯)。

### 4.4 呈现:模板分章节
`.md` 导出 / 作战档案视图按既定模板渲染(扩展现有 `mdProfile.ts`):每章节 = **结构化字段 + AI 梳理叙述(默认展示·带角标)+ 原始记录(可折叠下钻核对)**。GUI 卡片 = 结构化核心的精简呈现;`.md` = 全量呈现。同一 DB,两种呈现。

## 5. AI 引擎工作方式
- **读**:直接读 DB(结构化 + 自由文本两层),不读 `.md` 文件。
- **写**:① 提炼结构化 → **字段提案**进收件箱;② 梳理非结构化 → 生成"待核"叙述层(不动原始);③ 策略/行动 → 提案进收件箱。一律不自动落库(铁律②)。
- **触发与缓存(已定 = 懒生成 + 脏标记 + 按实体缓存)**:原始层有变 → 给该实体打"待梳理"标记,**不立即调 LLM**;**打开作战档案 / 导出 .md 时**——有标记→梳理一次→缓存进 DB + 清标记,无标记→**直接用缓存(零 LLM)**。缓存按实体存(梳理结果 + 它基于的原始时间戳),某实体原始变了只重梳理它。token 只在"有新内容 且 用户要看"时花(一次约 5–10k)。可选低频后台 job 预梳理(要"打开即最新"时)。
- **同步状态不同步分数**:趋赢力恒由 `g64111` 从结构化层算,AI 不写死分。

## 6. 交互原则:极简(本主线硬约束)
- **不新增对话框**:复用现有承载——左栏**对话框/诊断台**、底部**推演坞**、**收件箱面板**、**作战档案视图**。新能力嵌入这些,不弹独立 modal。
- **操作集中、尽量一屏**:地图主战场 + 左栏(诊断台/对话)+ 推演坞 + 收件箱角标,核心动作都在这一屏内完成,不跳页。
- **语音驱动**:"新建某客户 / 我有个商机 / 同步拜访录音" 一句话触发,不填表单。
- **就地确认,不弹窗**:人审在**收件箱面板就地**采纳/改后采纳/驳回;档案修改在**作战档案就地**字段编辑。DB 单源消灭了"同步勾选弹窗"(单向导出无需确认)。
- **渐进披露**:核心在卡片,全量在作战档案(同屏切换/抽屉,不是新页)。
- 这条延续既有交互重构方向(地图吸收沙盘 + 左栏诊断台 + 推演坞)。

## 7. 成本估算(量级)
- **token(已定:平台统一配置代付)**:按 ~1M token/销售/月估——国产模型(DeepSeek/通义)**¥数元/销售/月**(10 人团队 ¥数十/月),高端模型 $8–15/销售/月。
- **⚠️ 因平台代付,必须配套用量管控**:每租户/每销售**配额** + 用量监控 + 超额降级(否则被刷爆把平台成本打飞)。这是平台代付模式的核心运营动作。
- **服务器**:LLM/企查查/录音均**调外部 API**,不跑本地模型 → 不需 GPU,内存小升即可;存储是文本,千客户级几百 MB–1GB,现有盘充足。
- 结论:单位成本极低,主要变量是"国产 vs 高端模型";关键运营动作 = **配额管控**。

## 9. 分期路线(里程碑)
- **P0 数据地基**:DB 补自由文本层(通用 `Note`)+ 三层信息约定 + 作战档案/`.md` 单向导出补全(大半已有)。零售点:统一"提案层"为内外计算源唯一写入通道。
- **P1 江湖自算编排**:语音建客户/商机 → 后台 job → 企查查+LLM 生成档案/干系人候选 → 提案入收件箱(复用 enrich/voice/suggest + 加轻量 job 队列)。
- **P2 录音接入**:得到大脑 MCP / 飞书·钉钉 OpenAPI(BYO+OAuth)→ 拉转写 → voice 抽取;PIPL 配套同期。
- **P3 AI 梳理层**:后台把原始梳理成模板叙述(标待核·可下钻);呈现模板分章节。
- **P4 spec → 道具**:江湖出 spec + WorkBuddy 道具 skill 消费(回拉 MCP 数据)。
- **P5 引擎契约固化**:外部 Agent 经统一提案层接入的契约文档化(可插拔)。
- 交互极简贯穿全程;每个 P 独立可验、可上线。
