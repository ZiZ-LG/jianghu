## 一、§三问题清单·逐条回答

| # | 问题 | 回答 |
|---|---|---|
| 1 | 客户/商机页现在有没有可寻址 URL？ | **此前没有**（纯 state 驱动 SPA，URL 恒为 `/`）——本期已实现页面级路由：**`/account/{id}`（客户页）与 `/account/{id}/opp/{oppId}`（商机页）**。`{id}` 与 `{oppId}` **同时接受江湖 id 和销售包 externalRef**：销售包可直接用自己的 `customer_id` / 商机锚拼链接（如 `https://nova-jianghu.glodon.com/account/WB-CUST-001`），打开后 URL 自动规范化为江湖 id 形式。URL 稳定性：路由按 id 解析（externalRef 兜底），改名不影响；生产 Nginx 已有 SPA fallback（`try_files … /index.html`），刷新/直开均可。 |
| 2 | viewer 角色开关的实现位置？ | **前后端双层，后端为真防线**：① 后端——写总入口 `/api/mutate` 及全部旁路写口（候选采纳/驳回、提案拍板、证据审核、克隆商机、口述抽取、录音、AI 配置/调用、企微、令牌创建、demo/reset）对 viewer 一律 403；② 前端——`role === 'viewer'` 时编辑/录入控件**不渲染**（非置灰）。排期：**已完成**（本次发布）。 |
| 3 | `updated_at` 是否已记录？ | **已有，且语义恰好精确**：每次 MCP upsert 落库时会在 `Account.profile._mcpOrigin` / `Opportunity.meta._mcpOrigin` 写 `{source:'mcp', at:<ISO时间>, needsReview:true}`，`at` 每次幂等重推都会刷新。新鲜度**直接以 `_mcpOrigin.at` 为数据源**，而不是加数据库级 `updatedAt` 列——后者会被江湖侧人工编辑刷新，"我多久没被数字员工推过"的语义就失真了（黄点会被本地小改动洗绿）。 |
| 4 | 销售↔客户归属用什么字段承载？ | **`Account.primaryOwner`（销售包 upsert_account 已在推送的字段）**。对齐约定：**viewer 账号的江湖用户姓名（User.name）必须与销售包推送的 `primaryOwner` 完全一致**（例：销售包推 `primaryOwner: "销售A"`，管理员在江湖「团队」里建 viewer 账号时姓名填「销售A」）。viewer 拉取数据时按 `primaryOwner === 姓名` 过滤；`primaryOwner` 为空的客户对所有 viewer 不可见。编辑角色（owner/admin/member）不受影响，维持租户内全员共享。 |

## 二、四项需求·实现与验收对照

### 需求 1 · 只读呈现 ✅

- viewer 下**不渲染**（非禁用）：新建/删除客户、新建商机、画布全部写手势（双击建人/拖动/连线/改名/节点边工具框/框选对齐）、干系人档案编辑器（换只读档案视图）、关系编辑抽屉（换只读详情）、推演坞、参谋 tab、收件箱、口述录入、接入录音、重新补全、AI/企微/接入配置、载入示例。
- **视图交互全保留**：缩放（滚轮/捏合/按钮/总览 fit）、层级筛选（L1–L4 点亮）、hover 高亮、单击选中/再击进档案、动态时间线、作战档案（.md **复制/导出保留**——喂 WorkBuddy 的工作流不受影响）、全屏白板、暗色主题。
- 不落盘 what-if：本期未做前端入口，但**后端 `/api/pde/:oppId/what-if`（纯计算零写库）对 viewer 放行**（带归属校验）——架构未封死，随时可加 UI。
- 实测：viewer 账号全页面找不到可写入口；双击空白不建人；缩放/hover/筛选与编辑角色一致。

### 需求 2 · 时点戳 + 新鲜度点 ✅

- 渲染位置：Hub 客户卡、作战室左栏客户名下（客户级）、商机选择器下（商机级）。
- 文案：`N 分钟/小时/天前由数字员工更新`；🟢 ≤36h；🟡 >72h；36–72h 之间只显时点戳不标点（两侧不纠结）。无 `_mcpOrigin` 的对象（纯江湖手工建）不渲染——零噪音。
- **语义红线遵守**：无「在线/离线」字样；viewer 端连「引擎监测中」心跳条也一并隐藏，不造监控假象；同步失败状态江湖不展示（按契约归销售包收口对话告知）。
- 实测：MCP 幂等重推后刷新页面，`at` 刷新、点变绿；将对象 `at` 拨至 4 天前，显示「4 天前由数字员工更新」+ 黄点。
- 备注：时点戳对**编辑角色同样显示**（对管理者也有信息价值，且不涉写入语义）。

### 需求 3 · Deep link ✅

- URL 形态见问题 1。**已实测三条验收**：
  - 登录态点击链接 → 直达该客户/商机作战室；
  - 无登录态打开 → 登录页（URL 保持）→ 登录成功落到目标页，**不丢目标**；
  - externalRef 形式（`/account/WB-CUST-002`）→ 解析成功并规范化 URL。
- 商机段解析不到（改锚/删除）时兜底落客户页首个商机，不废整条链接。
- 元素级联动（聚焦某条关系线/某人）按契约列远期，本期未做。

### 需求 4 · 认证与数据隔离 ✅

- 登录门禁保留（手机/邮箱+密码，JWT 7 天）；viewer 的「极简」只减操作、不减门禁。
- 行级隔离（仅对 viewer 收紧）：整树接口按 `primaryOwner === User.name` 过滤；按 id 直查的读接口（评分引擎、候选列表、AI 综述等）同样做归属校验，**越权返回 404（不泄漏存在性）**。
- Deep link 落在认证与隔离之内——实测：销售 A 的链接发给销售 B，B 登录后提示「链接指向的客户不存在，或你没有查看权限」；未登录打开任何直链都先经登录。
- 加固两条（超出清单但同属"杜绝拿到链接就能看"精神）：**viewer 不能创建 MCP 接入令牌；viewer 身份（令牌或 JWT）接 `/api/mcp` 一律 403**——写工具不可能被 viewer 触达，读工具也不会绕过归属过滤。销售包推送请继续使用**编辑角色成员的令牌**（现状即如此，无需改动）。

## 三、销售包侧需要知道的三件事

1. **归属对齐约定（需求 4 的前提）**：viewer 账号的江湖姓名 = 销售包 `primaryOwner` 推送值，一字不差（建号时请照抄）。销售改名/换区时两边同步改。
2. **直链拼法（推荐）**：`https://<江湖域名>/account/{customer_id}`，商机级 `…/account/{customer_id}/opp/{商机externalRef}`——直接用销售包自己的锚，无需维护江湖 id 映射；用江湖 id（upsert 响应里的 `id`）拼同样有效。
3. **MCP 通道零改动**：`upsert_account / upsert_opportunity / append_visit_note` 的幂等与「外部来源·待核」标记未动；每次 upsert 顺带刷新新鲜度时点（`_mcpOrigin.at`），晚间全量重推 = 全对象变绿，天然一致。
