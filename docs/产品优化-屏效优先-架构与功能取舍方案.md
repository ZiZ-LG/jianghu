# 产品优化方案 · 屏效优先：架构重构与功能取舍

> **前置文档**：`docs/评估-三环理论-用户旅程与交互整体评价.md`（2026-07-01）。本文承接其结论，加入一条第一性约束后给出动刀方案。
> **第一性约束**：销售的主战场在现实生活（拜访、饭局、电话），对着屏幕用系统天生抵触。**屏幕时间是成本，不是参与度**——江湖的 KPI 不是停留时长，而是「每分钟屏幕时间换回多少赢单动作」。
> **状态**：产品方案（未动代码）· 2026-07-01。

## 0. 设计哲学：屏幕时间预算制

### 0.1 一天 10 分钟的预算表

给销售设定一个现实的屏幕时间预算，并把整个产品架构对齐到这张表上：

| 时刻 | 时长 | 场景 | 该给他什么 | 设备 |
|---|---|---|---|---|
| 早上出门前 | ≤1 分钟 | 通勤/电梯 | **今日一屏**：见谁、审什么、缺什么 | 手机竖屏 |
| 每次拜访前 | ≤1 分钟 | 车里/楼下 | **拜访卡**：他是谁、上次聊到哪、这次问什么 | 手机竖屏 |
| 每次拜访后 | ≤2 分钟 | 车里 | **口述回填**：说一段话，系统建档 | 手机·说话 |
| 碎片时间 | 30 秒×N | 任意 | **速审**：企微推来一条提案，点一下 | 企微内 |
| 周复盘 | 20 分钟×1–2 次 | 办公室 | **作战室**：看图、推演、定下周打法 | 桌面 |

**结论先行**：现有产品把全部功能压进了最后一行（桌面作战室），前四行几乎不存在——移动端甚至被 `OrientationGate` 强制横屏推向桌面形态。**本方案的主轴就是把产品重心从「一个工作台」迁移到「五个时刻」。**

### 0.2 三条产品定律（所有取舍的判据）

1. **说 > 打 > 点 > 拖**：说话优先于打字，打字优先于点选，点选优先于拖拽。任何要拖拽/多次点击才能完成的高频操作都是候选砍除对象。
2. **推 > 拉**：系统找人（企微推送/角标/一屏摘要）优先于人找系统（进来层层挖）。躺在 3 层深处的信息等于不存在。
3. **一屏一决策**：每个界面只要求人做一件事（采纳一条 / 回答一问 / 读完一卡）。信息元素超预算的一律折叠或砍除。

### 0.3 屏幕秒数经济学（性价比标尺）

| 动作 | 现状成本 | 目标成本 | 手段 |
|---|---|---|---|
| 录入一个人+完整档案 | 3–5 分钟表单 | ~30 秒说话 | 口述抽取（已有，扶正为唯一主录入） |
| 知道今天该干什么 | 无处可看（自己想） | 30 秒 | 今日一屏（新建） |
| 拜访前做功课 | 翻档案+动态 2–4 层 | 20 秒 | 拜访卡（新建） |
| 审一条 AI 提案 | 登录→收件箱→找到它 | 5 秒 | 企微推送+速审流 |
| 回填拜访结果 | 记得回来→找到牌→点 | 3 秒（↑—↓三键）或 1 分钟说话 | 点牌反馈（已有）+ 企微钩子 |
| 维护画布美观 | 无上限（时间黑洞） | 0 | 砍手工美化，一键自动布局 |

## 1. 架构重构：一个工作台 → 三个场景

```
场景 A · 手机竖屏「时刻流」（高频·每天多次·每次 ≤2 分钟）
   今日一屏 → 拜访卡 → 🎙️ 口述回填 → 速审流
   ═══ 只消费与回填，不编辑、不画图、不推演 ═══

场景 B · 企微内（零打开成本·碎片化）
   日程 = 行动牌（双向同步）；提醒/提案推送 → 一键采纳/驳回
   ═══ 江湖长出腿，走到销售已经在的地方 ═══

场景 C · 桌面「作战室」（低频·每周 1–2 次·深度 20 分钟）
   画布 + 推演坞 + 收件箱批量审 —— 唯一保留丰富度的场景
   ═══ 深思在这里发生，但日常不依赖它 ═══
```

**对现有架构的修订**：
- 三位一体（地图 + AI 后台 + 企微日历）不变，但**权重重排**：企微日历从 P2 提到 P0 级——它不是集成功能，是场景 B 的全部载体；
- **移动端战略反转**：`OrientationGate` 强制横屏废除。手机默认=竖屏时刻流（新首页），横屏地图降为「查看模式」可选入口；
- AI 后台不变（评价报告已确认架构正确），补齐心跳与推送出口。

## 2. 功能大盘点：砍 / 简 / 保 / 强

> 判决口径：**砍**=入口移除、代码退役或雪藏；**简**=保留但删除低价值操作面；**保**=不动；**强**=追加投入。

### 2.1 砍（性价比不足，直接去掉）

| # | 功能 | 现状 | 砍法 | 理由（秒数经济学） |
|---|---|---|---|---|
| 1 | **连线手工美化**：8 色自选、直线/折线/曲线切换、控制点拖曲率 | `EdgeDrawer`+`Canvas` 控制点 | 连线只按 L1–L4 四层语义自动配色配形，EdgeDrawer 只留「层/标签/方向/删除」 | 画图工具残留。销售调一条线的弧度换不回任何赢单概率；且是时间黑洞 |
| 2 | **MD 作战档案在线编辑** | `MdDocPanel` 可编辑 | 只留只读渲染+导出（架构 v1 本就定了「单向导出」，编辑器与之矛盾） | 销售不写 markdown；写了还破坏 DB 单源 |
| 3 | **左栏常驻 ChatPanel** | 对话占左栏下半+可拖高度 | 与口述/参谋三口合一（见 §2.2-6），左栏纯化为诊断台（推演坞施工方案第 1 刀，照做并加码） | 三个「对 AI 说话」入口，用户永远选错 |
| 4 | **AddIntel 的 tab 结构** | 口述/录音/对话三 tab | 合并为**一个输入口**：一个框（说话/粘贴皆可）+ 一个「传录音」按钮，后端同一条 voiceExtract 双轨 | tab 是分类学，不是用户任务。少一次选择 |
| 5 | **PersonForm 独立建人表单** | 弹窗表单 | 雪藏。建人=画布双击空白就地起名，或口述 | 表单是三种建人方式里最慢的 |
| 6 | **第 4 刀的「真拖拽上桌」** | 施工方案里的增强项 | 砍拖拽，只留「→ 上桌」按钮 + `staged` 字段 | 拖拽违反定律 1，且与手机不兼容；仪式感换不回效率 |
| 7 | **BYO 大模型 Key 配置界面** | `AiSettings` 面向用户 | 平台代付落地后对普通用户隐藏（管理员/自托管保留） | 配置断崖赶客（架构 v1 已拍板，落实它） |
| 8 | **simulate 长文分析默认展示** | 参谋/推演返回整页 markdown | AI 产出默认 = 「3 行结论 + 候选卡」，全文折叠可展开 | 销售没有读 500 字的屏幕预算；分析阅后即焚本就不沉淀 |
| 9 | **趋赢力明细的多处重复呈现** | 左栏 11 项 + 坞现状锚 + 全展开明细 | 常态只留「一个数字 + band 色 + top3 缺口」；11 项明细收敛为一处点开 | 同一信息三处渲染=三份注意力税 |
| 10 | **克隆商机、报表导出等低频项** | 顶级入口/对话框选项 | 雪藏进 ⚙️ 菜单，不占一级视野 | 低频功能不配一级入口 |

### 2.2 简（保留，删掉操作面）

| # | 功能 | 精简方案 |
|---|---|---|
| 1 | **画布关系地图**（产品灵魂，看的价值极高、维护成本极高） | ① **一键自动布局**（按 L1 组织树 / 按阵营聚类两种预设），手工拖拽变为微调而非必须；② 节点卡**三级缩放渐进披露**：远景=姓名+支持度色条（2 元素），中景=+角色/职务（4 元素），近景=现有全量（8–10 元素）；③ 徽章限额：每卡最多 1 枚（按 失血>缺口>待核实>★P4 优先级取最高） |
| 2 | **焦点面板·档案 tab** | 从「录入表单」转为「**AI 填、人改**」：字段默认由口述/录音/企查查抽取预填（带来源徽章），人工操作预期=修正而非录入。表单结构不动，心智换位 |
| 3 | **推演坞** | 日常态=**收起一条局势句**（EngineBar）；推导态=第 2 刀横向四列照做，但**列内容默认 AI 初稿**（顺推/倒推候选自动预生成，人做选择题）；策略卡/里程碑手工编辑保留但降为修正动作 |
| 4 | **补分卡 GapCards** | **改名换骨**：「补分」framing → 「**下次拜访问什么**」framing。同一数据两种货架：能当场勾的（C3/C5 材料项）留刷卡；需要见人才知道的（支持度/FORM/BI）转为拜访问题清单，挂到拜访卡上 |
| 5 | **LayerTabs L1–L4 多选** | 保留（方法论核心），加三个**预设视角**一键切：「组织」（L1）「权力」（L1+L2）「阵营」（L3+L4） |
| 6 | **「对 AI 说话」三口合一** | ChatPanel（改图）+ 口述录入（建档）+ 参谋（问策）后端本就同源分流——前端合并为一个 🎙️ 全局按钮：说的是事实→双轨落库；问的是问题→参谋应答。意图识别交给引擎，不让用户先自我分类 |
| 7 | **色码体系** | 四套→两套：支持度 6 色（核心语义）+ band 4 色保留；角色改用字母徽章不占色道；连线色随 L1–L4 层固定 |
| 8 | **收件箱** | 桌面保留批量模式；新增**速审流**（一次一卡、按影响排序、大按钮采纳/驳回）作为手机/企微形态 |

### 2.3 保（不动）

- 口述双轨抽取（明说直落/推断候选）、影响预览、候选四表与人审闸门、G64111 确定性引擎与局势条、点牌反馈（↑—↓ 三键 3 秒回填）、企查查一键建图（凭证配置移到管理员侧）、撤销重做、载入示例、MCP 外脑通道（propose 候选制）。

### 2.4 强（追加投入，全部服务于「短时间取主信息」）

| # | 投入 | 交付物 | 屏幕成本 |
|---|---|---|---|
| 1 | **今日一屏**（手机新首页 / Hub 顶部条） | 三段式：①今天的行动牌（企微日程同步）②按影响排序的待审 top3 ③今日拜访对象的问题清单入口 | 30 秒 |
| 2 | **拜访卡**（call prep，新） | 选人或由日历触发：他是谁（角色/支持度/趋赢力贡献）+ 最近 2 条动态 + **这次该问的 3 件事**（由 gaps/FORM 空项/unknown 支持度自动生成）+ 该带的道具 | 20 秒 |
| 3 | **企微出口**（P2→P0 级） | 行动牌⇄企微日程双向；巡检提醒/高影响提案推送到企微，附一键采纳链接；拜访日程结束后 30 分钟推「说两句？」口述钩子 | ≈0（在企微里） |
| 4 | **收件箱按影响排序** | 用现成 `previewProposalImpact` 按 \|趋赢力变化\| 降序，提醒按 severity | 半天工作量 |
| 5 | **心跳一行字** | 顶栏/今日一屏角落：「引擎 · 昨夜巡检 N 商机 · 新 M 条」 | 一行 |
| 6 | **AI 梳理默认、原始折叠** | 档案/动态默认显示 curated 三行摘要（架构 v1 §4.3 已定），原始记录下钻可查 | 阅读减半 |

## 3. 三个新界面（场景 A 的骨架）

### 3.1 今日一屏（手机竖屏首页）

```
┌──────────────────────┐
│ 早上好。今天 2 场拜访。        │
│──────────────────────│
│ 📅 10:00 张总（西部风光储）    │ ← 点开=拜访卡
│    ❓ 备好 3 个问题 · 🎒 带方案 │
│ 📅 15:00 李处（数字化项目）    │
│──────────────────────│
│ 📥 3 条待你拍板（按影响排序）   │ ← 点开=速审流
│    最大一条：D 支持度 −12%     │
│──────────────────────│
│ ⚙️ 引擎昨夜巡检 4 商机·新 2 条  │ ← 心跳
│         [ 🎙️ 说点什么 ]       │ ← 全局唯一录入口
└──────────────────────┘
```
规则：**≤7 个信息元素、1 个主行动（说话）**。客户列表 Hub 降为二级页（按「需要你」信号排序）。

### 3.2 拜访卡（20 秒读完就走）

```
┌──────────────────────┐
│ 张总 · 信息化副总 · D 拍板人   │
│ 支持度：中立 ＝ （30 天未更新⚠️）│
│──────────────────────│
│ 最近：6/18 参观工厂，对成本敏感 │ ← curated 2 行
│──────────────────────│
│ ❓ 这次问什么（缺口自动生成）：  │
│ 1. 预算走集团还是子公司？(C5)  │
│ 2. 他和王总监什么关系？(L2 缺) │
│ 3. 家里孩子高考完了吗？(FORM)  │
│──────────────────────│
│ 🎒 带：POC 报告（道具已出）     │
└──────────────────────┘
```
这是评价报告「机器主动向人提问」的落地形态——**缺口不再是补分表单，而是塞进口袋的问题清单**。拜访结束，企微推「说两句？」，闭环回口述。

### 3.3 速审流（一次一卡）

```
┌──────────────────────┐
│ ✏️ 提案 1/3 · 来自录音分析      │
│ 钱大钧：支持 ＋ → 倒向对手 ✕   │
│ 依据：「他上周去了友商答谢宴」   │
│ 影响：趋赢力 62% → 50% ▼      │
│                              │
│   [ ✗ 驳回 ]    [ ✓ 采纳 ]    │
└──────────────────────┘
```
按影响降序，一屏一决策，5 秒一条。桌面收件箱批量模式保留给周复盘。

## 4. 桌面作战室的精简（场景 C）

作战室是唯一保留丰富度的场景，但同样执行信息预算：

- **顶栏**：维持 5 项收敛成果；「+ 添加情报」变为全局 🎙️（同场景 A 的统一入口）。
- **左栏**：纯诊断台——一个数字 + band + top3 缺口（点开才见 11 项）；对话移除（三口合一后）。
- **画布**：三级缩放 + 一键布局 + 徽章限额（§2.2-1）。
- **右栏焦点面板**：三 tab 不动；参谋产出改「3 行结论+候选卡」默认态。
- **底坞**：收起=一条局势句；展开=横向四列（第 2 刀）+ AI 初稿预生成（第 3 刀）。
- **收件箱**：批量审模式，按影响排序。

**周复盘的理想剧本**（20 分钟）：进作战室 → 局势句 → 展开坞看四列推导 → 批量审一周积压候选 → 采纳/微调下周行动牌 → 牌自动进企微日程 → 关屏幕。一周只此一次深度屏幕时间。

## 5. 信息预算规则（「舍非关键信息」的制度化）

| 界面 | 预算 | 超预算处理 |
|---|---|---|
| 手机时刻卡 | ≤7 元素、1 决策 | 折叠或移到二级 |
| 画布节点（远/中/近） | 2 / 4 / 全量 | 缩放分级 |
| 画布徽章 | 每卡 ≤1 枚 | 按严重度取最高 |
| AI 文本产出 | 默认 ≤3 行 | 全文折叠可展开 |
| 收件箱速审卡 | 1 条/屏 | 排序保证先见最重要 |
| 色码 | 2 套（支持度+band） | 角色转字母、连线随层 |

**「20% 信息覆盖 80% 决策」白名单**（永远第一眼可见）：趋赢力 % 与 band、A/D 的支持度、top3 缺口、今日行动、最高影响提案。其余一律至少一层折叠。

## 6. 对已立案方案的修订 + 实施路线

### 6.1 已立案方案的判决

| 方案 | 判决 |

| 第 2 刀（横向四列） | **照做**（环三(b) 补强，与本方案兼容） |
| 第 3 刀（AI 预填六要素） | **照做**（正是「AI 写人改」哲学） |
| 第 4 刀（拖上桌+schema） | **减配**：保留 `staged` 字段与「→ 上桌」按钮，**砍真拖拽** |
| 企微日历（原 P2） | **提级 P0**：场景 B 的全部载体 |

| OrientationGate 强制横屏 | **反转**：手机默认竖屏时刻流，横屏地图为查看模式 |

### 6.2 分期（按屏效收益/成本排序）

- **P0 · 一周内见效（近零 schema）**：收件箱按影响排序；AI 产出折叠为 3 行+候选；趋赢力明细收敛一处；心跳一行字；「补分」→「拜访问题」文案与货架重排；砍连线美化与 MD 编辑入口。
- **P1 · 场景 A 骨架（前端为主）**：今日一屏（手机新首页）+ 拜访卡（gaps→问题生成器）+ 速审流；三口合一 🎙️；画布三级缩放+一键布局。
- **P2 · 场景 B 打通（重，含外部 API）**：企微日程双向 + 提醒/提案推送 + 拜访后口述钩子；平台代付 LLM。
- **P3 · 深化**：第 2/3 刀施工；第 4 刀减配版；curated 梳理层全量铺开。

### 6.3 不动的红线

多租户隔离、铁律②人审闸门、双轨录入、G64111 引擎与单测、跨库可移植、PIPL 字段白名单——本方案全部动作均在 UI/流程层与出口层，不触碰以上任何一条。

## 7. 结语

评价报告的结论是「把机器管住之后，该把人服务好」；本方案把它推进一步：**服务好一个不想看屏幕的人**。判据只有一条——每一秒屏幕时间都要换回赢单动作。砍掉的（画图美化、markdown 编辑、表单录入、拖拽仪式）都是换不回的；强化的（说话、拜访卡、速审、企微推送）都是 30 秒内完成交换的。地图与推演的深度没有丢，只是退到每周一次的作战室里——**日常极简，复盘极深**。
