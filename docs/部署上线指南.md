# 江湖 · 部署上线指南（大陆友好版）

> 目标：把「江湖」从本地跑通，变成团队在中国大陆**随时打开就能用**的在线服务。
> 约束（来自项目定位）：作者是**个人开发者、暂不注册公司**；用户**多在中国大陆**，要低延迟、稳定、可长期访问。

## 1. 关键决策：上线走哪条路？

大陆用户访问，本质是「**服务器放哪 + 域名要不要备案**」的取舍：

| 路线 | 服务器位置 | 是否需备案 | 大陆访问体验 | 多久能上线 | 适合 |
|---|---|---|---|---|---|
| **A. 大陆服务器 + ICP 备案**（推荐终态） | 阿里云/腾讯云 大陆地域 | **必须**（个人备案） | ⭐⭐⭐⭐⭐ 最快最稳，可用 80/443 | 备案审批约 **1–3 周** | 长期正式运营 |
| **B. 香港服务器（免备案）** | 阿里云香港/腾讯云香港轻量 | 不需要 | ⭐⭐⭐ 可用，延迟略高(~50-120ms)、偶有抖动 | **当天上线** | 立刻给团队用 / 备案过渡期 |
| C. 海外服务器（非港） | 美/新/日 等 | 不需要 | ⭐ 慢、可能被干扰 | 当天 | 不推荐面向大陆 |

> ⚠️ **大陆服务器的硬规则**：域名未完成备案前，大陆服务器的 **80/443 端口会被云厂商阻断**，网站打不开。所以「大陆服务器」和「备案」是绑定的——没备案就用不了。

### 推荐打法（鱼和熊掌）
1. **今天**：先在**香港轻量服务器**上按本指南部署（路线 B），团队**当天就能在线用**起来。
2. **同时**：买好要长期用的域名，在阿里云/腾讯云提交**个人 ICP 备案**（路线 A，免费，约 1–3 周）。
3. **备案通过后**：再开一台**大陆轻量服务器**，同样 `docker compose up`，把域名 DNS 切到大陆 IP。大陆访问体验立刻拉满，香港那台可关。

> 如果团队不急这两三周，也可以直接走路线 A：先备案、再部署，省一台香港机器的钱。

## 2. 个人 ICP 备案：能不能办、怎么办（大陆上线的关键卡点）

**结论先说**：个人（非企业）**可以**办 ICP 备案，免费，但有要点和不确定性，务必先读。

### 2.1 个人备案能办，但内容要"干净"
- 个人备案主体 = 你本人（身份证）。**不能**用于「经营性」网站（在线交易/广告经营等）。
- 「江湖」是**团队内部使用的销售工具**，无在线支付（只有捐赠链接）。属于可备案范围，但带**登录注册的 SaaS** 在个别省份管局眼里偏"敏感"，审核口径**因省而异**。
- **降低被拒概率的做法**：
  - 备案时网站名称/描述写成**中性的个人项目/工具**（如「个人效率工具」），**不要**写"销售/CRM/SaaS/平台/企业服务"等像经营的词。
  - 备案审核期间，**首页先放一个简单的静态介绍页**（纯展示，无登录入口）；备案号下来后再把完整应用挂上。
  - **把捐赠按钮、企业相关字样先隐藏**（看起来像经营行为）。备案通过后再视情况开启。

> 实话：个人备案 SaaS 存在被管局打回的可能，且各省尺度不一。若多次被拒、或团队规模/正式度要求高，最终解仍是**注册一个个体户/公司做企业备案**（个体户门槛低，也能办经营性资质，未来还能开微信登录/微信支付）。本阶段先按个人备案推进。

### 2.2 备案需要准备的材料（个人）
- 身份证正反面照片
- 本人手脸核验（阿里云/腾讯云 App 扫脸，随时随地完成）
- 备案幕布拍照（云厂商免费寄送，或就近自拍背景）
- 域名证书（在域名控制台一键下载）
- 一台**已购买的大陆云服务器**（备案要挂在它名下，需买够规定时长，通常 ≥3 个月）
- 真实性核验单/承诺书（按云厂商引导线上签）

### 2.3 备案流程（以阿里云为例，腾讯云几乎一致）
1. 域名实名认证（买域名时已要求，确保通过）。
2. 进入**阿里云备案系统**（App「阿里云」→ 备案，或 PC 控制台 → 备案）。
3. 填主体信息（你本人）+ 网站信息（中性名称/用途）。
4. 选「**接入服务器**」= 你买的那台阿里云大陆服务器。
5. 上传材料 + App 扫脸核验。
6. 阿里云**初审**（1–2 天）→ 提交**通信管理局终审**（各省约 **3–20 个工作日**）。
7. 下发**备案号**（形如「粤ICP备2026xxxxxx号」）→ 必须展示在网站**页脚**（已为你预留，见 §6.4）。

> 备案是**跟着服务器走**的：在阿里云备案就得用阿里云的大陆服务器；换厂商需做"接入备案"。所以先想好长期用哪家。

## 3. 准备工作（30 分钟）

### 3.1 买服务器
- **香港（路线 B / 过渡）**：阿里云**轻量应用服务器·香港** 或 腾讯云**轻量·香港**，2核2G 起步足够，约 ¥24–60/月。镜像选 **Ubuntu 22.04**。
- **大陆（路线 A / 终态）**：同上选**大陆地域**（就近团队，如华东/华南），2核2G/4G。
- 安全组/防火墙放行：**22（SSH）、80、443**。

### 3.2 买域名
- 阿里云/腾讯云 注册 `.com` 或 `.cn`（约 ¥30–80/年），**完成实名认证**。
- `.cn` 备案略快但需实名；`.com` 通用。二选一皆可。

### 3.3 装 Docker（登录服务器后执行）
```bash
# Ubuntu 22.04
curl -fsSL https://get.docker.com | sh        # 大陆机器若慢，见下方镜像加速
sudo systemctl enable --now docker
docker version && docker compose version       # 确认 compose v2 可用
```
> 大陆服务器拉 Docker 镜像慢时，配置镜像加速（阿里云控制台「容器镜像服务」给的专属地址）：
> ```bash
> sudo mkdir -p /etc/docker
> echo '{"registry-mirrors":["https://你的加速地址.mirror.aliyuncs.com"]}' | sudo tee /etc/docker/daemon.json
> sudo systemctl restart docker
> ```

## 4. 部署（核心，约 10 分钟）

### 4.1 拉代码
```bash
# 服务器上
git clone https://github.com/ZiZ-LG/jianghu.git
cd jianghu
```
> 私有库需先配置访问：用 GitHub Personal Access Token，或把服务器 SSH 公钥加到仓库 Deploy keys。

### 4.2 配置环境变量
```bash
cp .env.production.example .env
# 生成两段强随机密钥：
openssl rand -hex 32   # 复制到 .env 的 JWT_SECRET
openssl rand -hex 32   # 复制到 .env 的 AI_KEY_SECRET
nano .env              # 填好 POSTGRES_PASSWORD / JWT_SECRET / AI_KEY_SECRET
```
`.env` 关键项：
```ini
POSTGRES_PASSWORD=（一段强密码）
JWT_SECRET=（openssl 生成的64位十六进制）
AI_KEY_SECRET=（另一段64位十六进制）
CORS_ORIGIN=            # 同源部署留空
VITE_API_URL=          # 同源部署留空（前端走相对 /api）
WEB_PORT=80            # 若用宿主机 Caddy 做 HTTPS，改成 8080
```

### 4.3 起服务
```bash
docker compose up -d --build
docker compose ps          # 三个容器应为 running / healthy
docker compose logs -f server   # 看后端启动 + prisma migrate deploy 是否成功
```
此时浏览器访问 `http://服务器IP` 应能打开登录页。注册一个账号，点「载入示例」验证全链路。

> 数据库表结构由 server 容器启动时执行版本化 `prisma migrate deploy`；数据存在 `pgdata` 数据卷，`docker compose down` 不会丢（除非加 `-v`）。不要在生产用 `db push` 绕过迁移历史。

> **CORE-108 Commitment cutover：** PostgreSQL migration `20260821030000_release_customer_level_commitments` 会在同一事务内先检查 CORE-106 完成标记、通用 Commitment 契约及 tenant/Customer/可选 Matter/Person/User/下一承诺父树，再放宽 `PlanAction.opportunityId`。任何检查失败都会阻止 DDL 和服务启动；应先修复报告的数据，不得用 `db push`、虚构 Matter 或手工登记 migration 绕过。SQLite 开发库只走 `npm run db:push` 的受控 wrapper（实际入口为 `scripts/upgrade-sqlite-schema.ts`），它会先备份、重建后再写 cutover 标记，中断后可原命令重跑。若生产已存在客户级空 Matter 行，回滚只能关闭通用 Commitment 入口并前向修复；禁止直接恢复 `NOT NULL` 或删除这些业务行。

> **CORE-109 data scope：** PostgreSQL migration `20260821040000_add_tenant_data_scope_policy` 只增加 `Tenant.dataScopePolicy` 非空文本列，存量与新租户都默认 `legacy_tenant_shared`，升级后无需手工改值，既有 owner/admin/member 与 viewer 可见性保持不变。CORE-109 不提供生产切换 `scoped` 的 UI/API/脚本；不要直接执行 SQL 启用。未来启用必须先完成稳定 Customer/Matter owner dry-run、指定租户备份、人工审批与 canary。未知 policy、非法当前角色或已删除 actor 会返回空资源而不是回退租户共享。回滚应用前必须确认没有租户处于 `scoped`；只要存在一个 scoped 租户，就不得回到不识别该策略的旧代码、不得把 policy 改回 legacy 扩权，应停止入口并前向修复。无论何种回滚都保留该列和 migration 历史，tenantId 过滤不得放宽。完整消费者与停机条件见 [CORE-109 effective-scope 消费者清单](CORE-109-effective-scope消费者清单.md)。

## 5. 域名解析（DNS）

到域名控制台加一条 A 记录：
- 主机记录：`@`（或 `app`/`www`）
- 记录类型：`A`
- 记录值：你的**服务器公网 IP**

几分钟生效后，`http://你的域名` 即可访问。
> 大陆服务器：**备案通过前**这一步即使解析了也打不开（80/443 被阻断），属正常；备案通过后自动恢复。

## 6. 开启 HTTPS（强烈建议，登录密码必须走加密）

三选一，按省事程度排序：

### 6.1 方案一：宿主机 Caddy 自动 HTTPS（最省事，推荐）
Caddy 自动申请并续期 Let's Encrypt 证书。先把 compose 的对外端口改到本机 8080：
```bash
# .env 里 WEB_PORT=8080，然后 docker compose up -d
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https
# 安装 Caddy（官方源略），然后写 /etc/caddy/Caddyfile：
```
`/etc/caddy/Caddyfile`：
```
你的域名 {
    reverse_proxy 127.0.0.1:8080
}
```
```bash
sudo systemctl restart caddy   # 自动签发证书，https 立即可用
```

### 6.2 方案二：云厂商免费 SSL 证书 + 容器内 Nginx
阿里云/腾讯云「SSL 证书」可免费申请 DV 证书（绑你的域名）。下载 Nginx 格式证书，挂载进 web 容器并启用 443（`app/nginx.conf` 里增加 443 server 块 + 把证书目录挂载到 compose 的 web 服务）。需改两处配置，稍繁。

### 6.3 方案三：云厂商 CDN/WAF 兜 HTTPS（适合做加速）
大陆备案后可叠加 CDN，回源到你的服务器，证书托管在 CDN 侧，顺带加速+防护。

### 6.4 备案号页脚
备案通过后，需在网站页脚展示备案号并链接到 `https://beian.miit.gov.cn`。可在 `app/` 前端底部加一行（上线前我可以帮你补）。

## 8. 安全与合规（务必过目）

- 🔐 **已内置**：JWT 强密钥校验（生产用默认密钥直接拒绝启动）、helmet 安全头、接口限流、Nginx 反代隔离（db/server 不暴露公网）、HTTPS（按 §6 开启）。
- 📜 **PIPL 个人信息合规（最高风险）**：本产品会存"真实个人的职务/关系/态度/弱点"等敏感信息。上线即面向真实数据，请：
  - 仅在**获授权**的销售作战范围内使用；最小化采集，不存与销售无关的隐私。
  - 团队成员签署内部数据使用约定；提供数据删除/导出能力（路线图）。
- 🏢 **企查查数据**：用自有商用授权 Key；无 Key 的 AI 联想结果标注"待核实"，不作为权威结论。
- 🤖 **AI 关系推断**：始终"建议 + 人审"，绝不自动写库（已实现）。
